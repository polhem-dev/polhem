## 1. 它做什麼

公司既有的表單通常是紙本，或是 PDF、Word 檔。DefineEditor 的 **檔案 → 從文件匯入表單...**
會把這類表單送給 AI 模型 Claude，由它據此草擬 Polhem 表單：

- 主表，以及明細表（重複出現的列），
- 欄位，含英文標題、zh-TW 標題、資料型別與長度，
- 文件提供固定選項時的下拉選項，
- 關聯：挑選員工、部門、客戶或其他單據的欄位，會對到定義資料夾中既有的對應表單，
- 表單放在選單的哪個位置。

文件沒寫的部分（ProgId、欄位名稱、長度、Claude 沒把握的關聯），Claude 會在對話中詢問，每次都附上建議答案。
選擇 **產生定義** 之前不會寫入任何檔案，而它執行的是與 [Excel 活頁簿](excel-form-modeling.md)相同的匯入，
檢查與確認步驟也相同。

Claude 只負責提議。DefineEditor 以框架自己的規則把草稿轉成定義，而且只有在匯入會成功時才能產生。

## 2. 開始之前：憑證

草擬會呼叫 Anthropic API，費用由 API 額度支付，不是 claude.ai 訂閱。DefineEditor 不保存任何憑證，
由 Anthropic SDK 找出你電腦上的憑證。

1. **準備 API 額度。** Max、Ultra 或 Team 方案可以把每月附送的 API 額度綁定到某個 Claude Console 組織：
   claude.ai → Settings → Billing → API credits。其他情況請在 Claude Console 為某個組織儲值。
2. **登入。** 安裝 `ant` 命令列工具，執行：

   ```bash
   ant auth login
   ```

   選擇步驟 1 的組織。登入資訊存在你的使用者設定檔中，會自動更新；過期時 DefineEditor 會告訴你，再執行同一個指令即可。
3. **或使用 API key。** 無法執行命令列工具的環境，在 Console 建立 key，並在啟動 DefineEditor 前設定
   `ANTHROPIC_API_KEY`。

環境變數優先於登入，所以殘留在 shell 設定檔裡的 key，在你登入之後仍會被使用。對話視窗上方會顯示目前使用的憑證，
送出前的對話框也會警告殘留或空字串的 key。像 Claude 自家應用程式那樣登入 claude.ai，並不會取得 API 存取權。

## 3. 草擬表單

1. 開啟定義資料夾，然後選 **檔案 → 從文件匯入表單...**。
2. 選擇同一張表單的文件。多個檔案會一起送出，例如分開拍攝的紙本表單正反面。可接受 PDF、Word 文件，
   以及 PNG 或 JPEG 影像；超過大小上限的檔案在送出任何東西之前就會被拒絕。
3. **同意送出。** 對話框列出這些檔案，說明其內容會送到 Anthropic API，並指出所用的憑證，也就是由哪個組織付費。
   公司文件可能含有個資：只在你可以與 Anthropic 分享時才送出。

接著開啟對話視窗，Claude 讀完文件後，第一版草稿會出現在其中。

| 區域 | 顯示內容 |
|------|----------|
| 左側 | 對話。輸入回答後按 Enter（Shift+Enter 換行）；**停止** 取消目前的回覆，草稿回到你送出訊息前的狀態 |
| **畫面**分頁 | 表單將呈現的樣子，每次變更後重畫。上方的按鈕可切換「檢視模式」與「手機寬度」。點選欄位會在 **欄位**分頁中開啟它 |
| **欄位**分頁 | 每張表的每個欄位：名稱、標題、型別、長度、必填、關聯，以及它在文件中的原文。編輯儲存格即可直接修改草稿；你下一則訊息會一併告訴 Claude 你改了什麼 |
| **問題**分頁 | 尚未解決的事項：缺少的值、待確認的關聯、驗證錯誤。有錯誤時無法產生表單 |

用自己的話回答 Claude 的問題：「use LeaveRequest」、「事由可以有 200 個字」、「放在人事資料夾下」。
一切確定後，Claude 會把草稿標記為就緒，**產生定義** 隨之啟用。

幾件值得知道的事：

- **關聯會對到你的表單。** Claude 會搜尋資料夾中的表單及其欄位。沒把握時（「收件人」欄位可能是員工，也可能是自由文字），
  它會先問再建立關聯。
- **慣例會自動補上**，與 Excel 匯入相同：系統欄位、`ft_` 資料表名稱、`company` 資料庫類別，以及顯示關聯資料的
  `ref_*_id` / `ref_*_name` 欄位。預覽中已經看得到它們。
- **計算欄位會被檢查。** 值由計算得出的欄位（由數量與單價算出金額、由日期算出請假天數），在草稿就緒前會先以框架的
  運算式引擎解析，所以每次存檔都會失敗的運算式會在這裡被攔下。運算式讀取的是同一列的欄位。

## 4. 產生定義

**產生定義** 把表單交給活頁簿匯入，所以[匯入會寫入的檔案](excel-form-modeling.md#5-匯入會寫入的檔案)與
[再次匯入](excel-form-modeling.md#6-再次匯入)的內容都適用：你選擇既有 TableSchema 與 FormLayout 的處理方式，
檢視檔案與動作清單，然後確認。檔案寫入後對話視窗會關閉，DefineEditor 接著提議為表單的資料表升級資料庫
（[資料庫相關工作](../../../tools/DefineEditor/README.zh-TW.md#資料庫相關工作)）。

ProgId 已存在時，**畫面**分頁顯示的是既有版面加上新欄位的樣子，也就是你選擇把缺少的欄位加進版面時，匯入會寫出的結果。

## 5. 匯入之後

- **調整版面。** 草稿決定欄位的順序，而不是排列方式。在 FormLayout 編輯器中搭配即時預覽，把欄位並排、分組成區段、
  調整寬度。
- **執行中的伺服器不必重新啟動。** 框架的定義快取在讀取時會比對每個檔案的寫入時間（最多每秒一次），
  所以執行中的伺服器在下一個請求就會讀到新的 FormSchema、FormLayout 與設定檔。2026-11-14 以框架的定義存取
  （`CacheDefineAccess`）對 Northwind 定義資料夾的副本實測：新表單、它的程式項目與選單項目，都在寫入後約一秒被讀到。
- **資料表必須存在。** 接受 DefineEditor 提議的升級，或自行執行 `db upgrade`
  （[初始化新部署](../database/database-settings-guide.md#7-初始化新部署)）。
- **重新登入才看得到選單項目。** 用戶端在登入時取得選單，所以已經開著的用戶端要重新登入後才會顯示新項目。

## 6. 費用與時間

每則訊息會產生一或多個付費的 API 請求，由憑證所屬的組織支付。文件在第一個請求後會被快取，
所以在快取有效期間（幾分鐘）送出的回覆，費用遠低於第一個請求。

參考數字：2026-11-14 以八份合成表單（印刷、手寫與拍照，部分含明細表與關聯）量測，每張表單約 US$0.25、80 秒，
使用者回覆一到兩次。實際文件會依長度與需要詢問的多寡而不同。各組織的花費可在 Console 查看。

## 7. 限制

- 一次對話草擬一張表單。
- 目前只支援 Claude。草擬功能本身不綁定廠商（[Polhem.Definition.Drafting](../../../src/Polhem.Definition.Drafting/README.zh-TW.md)）；
  其他模型需要一個像 [Polhem.AI.Claude](../../../src/Polhem.AI.Claude/README.zh-TW.md) 這樣的提供者套件。
- 主表上加總明細表的欄位無法表達，因為運算式只讀同一列；Claude 不會建立這類欄位。
- **畫面**分頁預覽的是桌面版表單。FormLayout 編輯器的 Web 預覽在對話視窗中無法使用。
- Excel 匯入不會解析運算式；只有草擬會。
- 定義無法表達的商業邏輯（自訂 business object 或 repository）要寫成程式碼，與任何表單相同。
