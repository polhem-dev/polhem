# Polhem 1.15.0 — 發佈說明

[English](../../en/changelogs/1.15.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.15.0]` 條目的詳細內容。

資料表升級現在會把每張表的升級記錄在 `st_table_upgrade`，並帶上為升級行為編版的格式版本。舊格式的工具不再復原新格式做過的改動；紀錄顯示已是最新的資料表不再與資料庫比對，沒有任何變更的啟動因此快很多。wire 格式與 1.14.0 相同。

## 新功能與變更

### 每次資料表升級都有紀錄，舊版工具不會改動新版升級過的資料庫

升級執行過的每個資料庫會有一張 `st_table_upgrade`，每張資料表一筆：最近一次升級的狀態（`Upgrading`、`Succeeded`、`Failed` 或 `Verified`）、失敗時的錯誤、最近套用的定義，以及工具的格式版本與框架版本。`SchemaFormat.Current` 是目前建置的格式版本，`TableUpgradeRecordStore` 用來讀取紀錄（`GetRecord`、`GetHighestFormatVersion`、`DescribeNewerFormat`）。

升級在改動任何東西之前，會先讀資料庫記錄的最高格式版本。資料庫被較新的格式升級過時，`db upgrade` 與 `IDatabaseInitializer.UpgradeTables` 回報一次並略過它的資料表；`IDatabaseRepository.UpgradeTableSchema`、`TableSchemaBuilder.Execute` 與 `TableUpgradeOrchestrator.Execute` 則丟出例外。該資料庫不會有任何改動，請用較新的工具升級。說明見[資料庫 Schema 升級指引 §11](../database/database-schema-upgrade.md#11-升級紀錄與格式版本)。

- **背景：** [ADR-065](../../../maintainers/adr/adr-065-table-upgrade-records-and-schema-format.md)

### `db upgrade` 回報紀錄的狀態

依紀錄判定的資料表顯示 `unchanged (upgrade record)`；上一次升級失敗或沒有完成的資料表，會在該行註明；最後的統計會列出依紀錄判定的表數。程式中由 `TableUpgradeEntry.UnchangedByRecord` 與 `TableUpgradeEntry.PreviousStatus` 提供相同資訊。見[資料庫設定](../database/database-settings-guide.md)。

## 破壞性變更

### 升級改為相信資料表的紀錄，不再逐一比對

- **影響：** 手動改過資料表、並靠下一次升級把它改回來的部署；以及用預設選項呼叫 `TableSchemaBuilder.Execute`、`IDatabaseRepository.UpgradeTableSchema` 或 `IDatabaseInitializer.UpgradeTables` 的程式。
- **之前：** 每次升級都從資料庫的系統目錄讀出每張表的結構，與定義比對。
- **現在：** `UpgradeOptions.CompareMode` 預設為 `UpgradeCompareMode.Fast`。資料表的紀錄顯示上次升級成功或比對一致，而且格式版本是目前的版本、定義與現在相同時，不讀系統目錄就視為沒有變更。在框架之外對這種資料表做的改動，要等定義改變才會被發現。
- **遷移：** 要讓每張表都與資料庫比對，執行 `db upgrade --full-compare`，或傳入 `new UpgradeOptions { CompareMode = UpgradeCompareMode.Full }`。更新後的第一次升級本來就會完整比對每張表，因為還沒有任何紀錄。
- **背景：** [ADR-065](../../../maintainers/adr/adr-065-table-upgrade-records-and-schema-format.md)
