# Polhem 1.10.0 — 發佈說明

[English](../../en/changelogs/1.10.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[Unreleased]` 條目的詳細內容，發佈時改為 `[1.10.0]`。

本版讓 Blazor Server 端擁有和 Avalonia 端相同的欄位編輯器：名稱相同、契約相同、行為相同，兩端建立與擴充表單的方式因此一致。
兩端共用的規則移到 `Polhem.UI.Core`。wire 格式與 1.9.0 相同，1.9.0 的用戶端與 1.10.0 的伺服器（或反過來）可以互通。

## 新功能與變更

### Blazor Server 的欄位編輯器

`Polhem.Web.Blazor.Server.Controls.Editors` 為每種 `ControlType` 提供一個元件：`TextEdit`、`MemoEdit`、`NumericEdit`、
`TimeEdit`、`DateTimeEdit`、`DateEdit`、`YearMonthEdit`、`CheckEdit`、`DropDownEdit`、`ButtonEdit`。名稱與 Avalonia 的欄位編輯器相同，
實作同樣的 `IFieldEditor` 契約（`Bind`、`Unbind`、`SetControlState`、`FieldName`、`FieldValue`），行為也一致：

- 使用者離開輸入框或按 Enter 時才提交值，不是每次按鍵都提交。
- 編輯器自行套用 schema 欄位的中繼資料：`MaxLength`、`ListItems`、數值格式。
- 可否輸入依表單模式、版面欄位的 `ReadOnly` 與 `AllowEditModes` 決定。
- 程式寫入的值，或資料物件重新載入，都會更新編輯器。
- `NumericEdit` 平時顯示格式化後的值，取得焦點時顯示完整精度；輸入無法解析時保留上一個有效值。`TimeEdit` 以 `HH:mm` 儲存。

編輯器的綁定以明確呼叫的 `Bind` 優先，其次是 `DataObject` 參數，最後才是外層的 `FormScope`：

```razor
<FormScope DataObject="dataObject" FormMode="SingleFormMode.Edit">
    <TextEdit FieldName="emp_name" />
    <NumericEdit LayoutField="amountField" />
</FormScope>
```

自訂編輯器繼承 `FieldEditorBase`，覆寫 `RefreshFromSource`；需要 schema 中繼資料時再覆寫 `ApplyMetadata`。
`FieldEditorFactory.GetEditorType` 由 `ControlType` 對應到編輯器型別。

編輯器輸出 `polhem-field-editor` class、各編輯器的修飾 class（例如 `polhem-field-editor--numeric`），不可輸入時再加上
`polhem-field-editor--readonly`；套件本身不附 CSS。日期、日期時間與下拉編輯器的唯讀狀態，以使用者 culture 的文字顯示值，
和 Avalonia 編輯器相同。

`FormDataObject` 補上編輯器需要的功能：指定資料列的 `GetField` 與 `SetField`、指定資料表與欄位的 `GetFormField`，以及
`FieldValueChanged`、`IsDirtyChanged`、`DataSetReplaced` 事件。寫入與欄位現值相同的值，不再把物件標記為已修改。

### Blazor Server 的查詢

綁定到有 `RelationProgId` 欄位的 `ButtonEdit`，執行和 Avalonia `ButtonEdit` 相同的查詢流程：輸入框顯示該欄位的顯示欄位
（例如 `D01 - Engineering`）且為唯讀，按鈕開啟 `LookupDialog`，選中資料列的 `sys_rowid` 與對應欄位透過
`FormDataObject.ApplyLookupSelection` 寫回，按 Delete 或 Backspace 則透過 `ClearLookupSelection` 清除。沒有
`RelationProgId` 時，按鈕觸發 `ButtonClick`。查詢無法載入或選取結果無法寫回時觸發 `LookupFailed`；沒有處理常式時，
訊息顯示為輸入框的提示文字。

`LookupDialog` 是包著 `LookupPanel` 的強制回應覆蓋層；`LookupPanel` 有搜尋框、依目標表單查詢版面呈現的清單與
OK / Cancel，雙擊資料列即可確認。對話框依序從 `Schema` 與 `Connector` 參數、容器中註冊的 `IFormDefinitionSource` 與
`IFormApiConnectorFactory`、circuit 的 `PolhemApiClient` 取得目標 schema 與連接器；最後一種會以 `FormPage` 載入自身
schema 的方式載入。有 Polhem 後端的應用程式不需註冊任何東西；沒有後端的應用程式則以 scoped 註冊自己的來源：

```csharp
builder.Services.AddScoped<IFormDefinitionSource, MyDefinitionSource>();
builder.Services.AddScoped<IFormApiConnectorFactory, MyConnectorFactory>();
```

`DynamicGrid` 新增 `OnRowActivated`（雙擊）與 `SelectedRowId`（要高亮的資料列），供查詢清單使用。

### Blazor Server 的即時計算

`FormPage` 會在使用者編輯時即時重算計算欄位（`ValueExpression`），新增記錄時也會評估預設值運算式，做法與 Avalonia 的
`FormView` 相同。規則是 `Polhem.UI.Core` 新的 `FormLiveComputationEngine`，現在兩端都用它，所以任一端預覽的值都與伺服器
存檔時寫入的值一致。運算引擎與使用者時區由呼叫端提供；Avalonia 的 `FormLiveComputation` 改為套在它之上，公開介面不變。

新的 `Polhem.Web.Blazor.Server.DataObjects.FormLiveComputation` 讓自訂頁面也能使用這個引擎，預設使用共用的
DynamicExpresso 運算引擎。時區要傳 circuit 自己的：

```csharp
var live = new FormLiveComputation(schema, timeZoneProvider: () => client.Session.Credentials.UserTimeZoneId);
dataObject.FieldValueChanged += (_, e) =>
{
    if (!live.IsRecomputing) live.Recompute(e.TableName, e.FieldName, e.Row);
};
```

`FormPage` 的預覽以框架預設的小數位數四捨五入，儲存時由伺服器做權威的四捨五入。`Polhem.Web.Blazor.Server` 為了預設
運算引擎，現在引用 `Polhem.Expressions`。

Blazor 的 `FormDataObject` 補上與 Avalonia 相同的資料列生命週期：新資料列依 schema 填入預設值（新的 `sys_rowid`、
與主檔的連結、依型別的非 null 值），`RowAdded` 與 `RowDeleted` 回報資料列變更，`BeginRowEdit` / `CommitRowEdit` /
`CancelRowEdit` 暫存單一資料列的編輯，提交前只觸發 `RowEditFieldChanged`，提交時才透過 `FieldValueChanged` 發布。

### FormPage 依表單模式運作

`FormPage` 按下 **New** 後以新增模式編輯記錄，載入或儲存資料列後以編輯模式編輯，沒有記錄時為檢視模式；因此只允許新增時
編輯的欄位（例如鍵值）在記錄儲存後會變成唯讀。

### 兩端共用的欄位規則

`Polhem.UI.Core.Fields` 收納兩端欄位編輯器共用的規則，讓它們不會各自分歧：

- `FieldEditRules.AllowsEdit`：表單模式、版面唯讀旗標與 `AllowEditModes`。
- `FieldValueFormatter.Format`：依使用者 culture 顯示值。
- `NumericFieldFormat`：數值格式解析（含幣別與單位的小數位數）、顯示、輸入剖析，以及寫回的值。
- `DateTimeFieldFormat`：日期時間欄位的顯示、輸入與綁定字串規則。
- `FormLiveComputationEngine`：計算欄位與新資料列預設值的即時計算。
- `LookupFieldRules` 與 `LookupDisplay`：欄位是否為查詢欄位、開啟哪個程式、顯示哪些欄位及如何串接，以及選取結果如何寫回或清除。

## 破壞性變更

### `DynamicForm` 改由 `FormLayoutPresenter` 取代

- **影響：** 自行呈現 `DynamicForm` 的 Blazor Server 應用程式。只使用 `FormPage` 的應用程式不需處理。
- **之前：** `Polhem.Web.Blazor.Server.Components.DynamicForm` 以一般輸入元素呈現主檔 section，CSS class 為
  `polhem-dynamic-form`、`polhem-dynamic-form__*` 與 `polhem-dynamic-form__input--*`，只依各欄位的 `ReadOnly`。
- **現在：** `Polhem.Web.Blazor.Server.Controls.FormLayoutPresenter` 透過欄位編輯器呈現相同的 section，參數同樣有
  `Layout`、`DataObject`、`IdPrefix`，另外新增 `FormMode` 與 `RoundingContext`。
- **遷移：**
  1. 把 `<DynamicForm ...>` 改為 `<FormLayoutPresenter ...>`，並加上 `@using Polhem.Web.Blazor.Server.Controls`。
  2. 頁面有檢視或新增狀態時傳入 `FormMode`；預設為 Edit，對非唯讀欄位而言與舊行為相同。
  3. 改名 CSS selector：`polhem-dynamic-form` → `polhem-form-layout`（以及 `__section`、`__section-caption`、
     `__grid`、`__field`、`__label` 各部分）；`polhem-dynamic-form__input` → `polhem-field-editor`；
     `polhem-dynamic-form__input--<kind>` → `polhem-field-editor--<kind>`。
