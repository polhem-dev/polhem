# Polhem 1.4.0 — 發佈說明

[English](../../en/changelogs/1.4.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.4.0]` 條目的詳細內容。

這一版新增物件樹與屬性方格，也就是 DefineEditor 現在用來建文件樹與屬性面板的元件，並移除三個在 1.2.0 改用 Polhem.JsonRpc
後已無用途的公開型別。以這一版建置需要 .NET SDK 10.0.400 以上。線路格式沒有改變：1.4.0 的用戶端與 1.3.x 的伺服端（反之亦然）
可以互通，因此伺服端與用戶端不需要同時升級。

## 新功能與變更

### 物件樹

`ObjectTreeBuilder`（`Polhem.Definition.ObjectTree`）依 `[TreeNode]` 與 `[TreeNodeIgnore]`，從物件圖建出與 UI 無關的
`ObjectTreeNode` 樹，適用於桌面工具。

- 建樹時只追蹤值帶有 `[TreeNode]` 的屬性。它會略過集合基底型別所宣告的屬性，因此集合項目的反向參照不會變成節點。
  `[Browsable(false)]` 不參與判斷，因為定義型別在集合屬性上標它，是為了不讓這些屬性出現在屬性方格中。
- 每個物件只成為一個節點，再加上 `ObjectTreeOptions.MaxDepth`，可以阻止循環。`ObjectTreeOptions.ExpandDepth` 設定建出的樹一開始展開幾層。
- 節點會發出變更通知，UI head 可以直接繫結。`ObjectTreeNode.IsExpanded` 保存展開狀態。
- 消費端可用 `PropertyFilter`、`NodeBuilt`、`LabelTranslator` 縮小、擴充與翻譯這棵樹。
- `ObjectTreeNode(object, Func<object, string>, bool)` 建立標籤由值計算、`Refresh` 時重算的節點，用於消費端自行加入、需要跟著切換顯示語言的節點。
- `TreeNodeAttribute.GetDisplayText(object, Func<string, string>?)` 會在填入屬性值之前先翻譯顯示格式。
- `ITreeNodeCommandProvider` 與 `TreeNodeCommand` 描述與 UI 無關的樹節點命令。
- `ITreeNodeDragDropHandler` 與 `TreeNodeDropPosition` 決定哪些樹節點可以拖曳、可以放在哪裡。

`ObjectTreeView`（`Polhem.UI.Avalonia`）是顯示 `ObjectTreeNode` 樹的 `TreeView`。設定 `RootNode` 即可，可選 `IconSelector`
在每個標籤前顯示圖示；每個項目的 `IsExpanded` 與節點雙向繫結。`ObjectTreeView.CommandProvider` 在每次開啟右鍵選單時，以選取節點的命令填入選單。
`ObjectTreeView.DragDropHandler` 讓使用者把節點拖到另一個節點之前或之後，並顯示落點；handler 搬動物件後，控制項再搬動樹上的節點。

### 定義型別的 `[TreeNode]` 標註

定義型別改依同一條資料夾規則：擁有者有兩個以上帶標註的集合時，集合以資料夾呈現，否則直接掛在擁有者下。`FormLayout` 的 Sections 與
Details、`FormSchema` 的 Tables 與 Rules 改為資料夾；`FormTable` 的 Fields 與 `LanguageEnum` 的 Entries 不再是資料夾。
每個帶標註的物件型別都明確寫出標籤取自哪些屬性，與其 `ToString()` 一致；`IndexField` 與其集合也補上標註，索引底下會列出索引欄位。

### 屬性方格

`PropertyGridControl`（`Polhem.UI.Avalonia`）依屬性上的 ComponentModel 標註，把 `SelectedObject` 的屬性顯示成標籤與編輯器：
`[Category]`、`[Description]`、`[DisplayName]`、`[Browsable]`、`[DefaultValue]`、`[TypeConverter]` 與 `[PasswordPropertyText]`。

- 值與預設值不同時以粗體顯示，標籤的右鍵選單可重設。每次寫回都會引發 `PropertyValueChanged`。
- `LabelTranslator` 翻譯標籤：每段文字以 `PropertyGridText` 傳入，附上 `PropertyGridTextKind`（分組、顯示名稱、說明、項目標籤）、
  所屬型別與屬性名稱，因此說明可以依屬性查詢。`Refresh` 重新讀取物件並重新翻譯。
- 標有 `[PasswordPropertyText(true)]` 的屬性會遮蔽顯示。
- `ValueSuggestionProvider` 讓字串屬性改為列出建議值、仍可自行輸入的下拉清單。
- `PropertyFilter` 可縮小顯示的列，例如只顯示一個分組。
- 集合屬性以 `CollectionEditDialog`（或 `CollectionEditorProvider` 提供的編輯器）開啟；巢狀物件只唯讀顯示。
- 控制項透過 `TypeDescriptor` 讀取型別，而 trim 不會保留這些資訊，所以定位為桌面工具使用，不適用於經過 trim 的行動端 head。

`CollectionEditDialog` 與 `CollectionEditContext`（`Polhem.UI.Avalonia`）組成編輯集合屬性的對話框，項目列在清單中（新增、刪除、上移、下移），
並以 `PropertyGridControl` 編輯選取的項目。對話框編輯項目的副本，按確定時以副本取代集合的項目，因此先前持有的項目參照要重新讀取；
按取消則集合完全不變。有鍵值的集合中，新項目會取得未使用的鍵值，按確定時拒絕重複的鍵值。

`PolhemUIText` 新增 `ResetValue`、`CollectionSummary`、`MoveUp`、`MoveDown`、`CollectionKeyMissing`、`CollectionKeyDuplicate` 與
`CollectionKeyTaken`：屬性方格與集合對話框使用的文字鍵。屬性方格寫入的鍵值已被集合中其他項目使用時，會以介面語言顯示
`CollectionKeyTaken`，而不是集合擲出的英文例外訊息。

### 定義型別為屬性方格加上標註

- 定義型別在屬性方格中顯示的每個屬性都宣告了 `[Category]` 與 `[Description]`，會依分組顯示並附上說明，不再落到 `Misc`。
- 編輯器以樹節點呈現的集合（表單結構描述的資料表與規則、各設定檔的項目、語系資源的項目與列舉）以及 `SessionUser.AccessToken`
  標為 `[Browsable(false)]`。
- `SecurityKeySettings` 的加密金鑰標上 `[PasswordPropertyText(true)]`，屬性方格會遮蔽顯示。
- `LanguageItem.Key` 重新標為可瀏覽：它覆寫的基底鍵值標了 `[Browsable(false)]`，覆寫時被一併繼承。
- `PermissionRule.Action` 宣告了型別轉換器，其互斥的標準值是單一動作，因此屬性方格會給單一動作的下拉清單，而不是可組合旗標的文字框。

這些 attribute 都不改變 XML 或線路格式。

### 相依套件

套件相依升為 MessagePack 3.1.11、DynamicExpresso.Core 2.19.6，以及框架所參考的 `Microsoft.Extensions` 套件的 10.0.12 版。
這些是 NuGet 為應用程式解析出的最低版本。分析器改用 Microsoft.CodeAnalysis 5.9，見
[需要 .NET SDK 10.0.400 以上](#需要-net-sdk-100400-以上)。

### 修正

- **在 Avalonia 12.1 下，登入者的 culture 重新生效。** Avalonia 12.1
  （[AvaloniaUI/Avalonia#21627](https://github.com/AvaloniaUI/Avalonia/pull/21627)）會在每次 dispatcher 作業後，把 UI 執行緒
  當下的 culture 寫回去。`ClientInfo` 是在非同步的登入處理常式中設定使用者的 culture，執行環境在下一個 `await` 就把這個變更還原，
  因此在中文作業系統上，en-US 帳號的標題與日期格式顯示的是作業系統的語言。`ClientInfo` 現在也會把 culture 投遞到呼叫端的同步內容，
  由一個單純的回呼來設定。`Polhem.UI.Avalonia` 接受 Avalonia 12.0.0 以上，所以自行升到 12.1 的應用程式在 1.3.x 也會受影響。
  （[#95](https://github.com/polhem-dev/polhem/pull/95)）

### 範例與工具

- DefineEditor 的每一種文件樹都改用 `ObjectTreeBuilder` 建樹、以 `ObjectTreeView` 顯示，右鍵選單由各文件型別的
  `ITreeNodeCommandProvider` 提供，取代原本手寫的樹節點。標籤依 `[TreeNode]` 標註，資料夾不再顯示數量。每個編輯器都可以把節點拖到同層的
  另一個節點之前或之後，調整它所在集合的順序。資料夾、根節點與群組的標籤會依編輯器的語言顯示，切換語言時立即更新。
- DefineEditor 改以 `PropertyGridControl` 顯示選取的物件，取代手寫的屬性面板，因此每個可瀏覽的屬性都能編輯，並依 `[Category]` 分組、
  以 `[Description]` 說明。分組與說明已翻成繁體中文，會跟著編輯器的語言切換；屬性名稱維持原文。欄位的 ListItems 改在方格的集合對話框中編輯，
  不再是樹節點；選取欄位的 Relation 或 Lookup 群組時顯示其 Relation 屬性，表單代碼、對應欄位與方案內的語系列舉會列出建議值。貼上連線字串改為
  資料庫 Server 或 Item 右鍵選單開啟的對話框，預覽不再顯示密碼。修改物件名稱後，樹上的標籤會立即更新。
- Avalonia.DemoCenter 新增 Property Grid 案例：以 `PropertyGridControl` 顯示 `FormField`、`DbField`、`DatabaseServer`、
  `PermissionRule`、`BackendConfiguration` 與一個「群組含項目」的示範物件，可切換顯示選項與表單代碼建議值，並記錄 `PropertyValueChanged`。
  FormField 的 `ListItems` 在 `CollectionEditDialog` 中開啟，群組的項目會在第一層對話框之上再開第二層。
- Avalonia 的各個 head（DefineEditor、Avalonia.DemoCenter、Northwind 各 head）改用 Avalonia 12.1 與 Semi.Avalonia 12.1；
  `Polhem.UI.Avalonia` 仍以 Avalonia 12.0.0 為最低版本。Northwind 的 iOS head 改為需要 iOS 15.0，這是 .NET SDK 10.0.400 的
  iOS workload 所接受的最低版本。Northwind 的 Android head 維持 Xamarin.AndroidX.Core.SplashScreen 1.0.1.15：1.2.0.3 會帶進
  AndroidX Lifecycle 2.11，超出 Avalonia.Android 依賴的範圍，Android 建置會失敗。
  （[#95](https://github.com/polhem-dev/polhem/pull/95)、[#96](https://github.com/polhem-dev/polhem/pull/96)）

## 破壞性變更

### 需要 .NET SDK 10.0.400 以上

- **影響對象：** 每個直接或經由其他 Polhem 套件參考 `Polhem.Definition` 套件的專案。
- **原本：** 較舊的 .NET 10 SDK 也能建置參考 Polhem 套件的專案。
- **現在：** `Polhem.Definition` 套件所附的 Roslyn 分析器改以 Microsoft.CodeAnalysis 5.9 建置。分析器建置時所參考的版本，就是能載入它的
  最低編譯器版本，因此較舊的編譯器會回報 `CS9057` 而不執行分析器，在 `TreatWarningsAsErrors` 下建置會失敗。
- **遷移：**
  1. 以 .NET SDK 10.0.400 以上建置；用 `dotnet --version` 確認。
  2. 若 `global.json` 鎖定了較舊的 SDK band，也要一起調整。CI 上以 `actions/setup-dotnet` 搭配 `dotnet-version: 10.0.x`，
     取得的已是 10.0.4xx 的 SDK。
- **背景：** [#96](https://github.com/polhem-dev/polhem/pull/96)

### 移除改用 Polhem.JsonRpc 後遺留的型別

- **影響對象：** 用到 `Polhem.Api.Core.Messages.PayloadFormat`（例如 connector 的 `ExecuteAsync` 呼叫或 `ApiCallContext`）、
  呼叫 `Polhem.Core.Serialization.Gzip`、或拋出或攔截 `Polhem.Api.Core.JsonRpc.JsonRpcException` 的程式碼；以及以較早 1.x
  建置、又用到這些型別的組件。
- **原本：** 這三個型別仍是公開的，但 1.2.0 改用 Polhem.JsonRpc 後它們已無用途：`Polhem.JsonRpc.Payload` 有成員與值都相同的格式列舉，
  `Gzip` 只是 `GZipStream` 的薄包裝、框架自 1.2.0 起就沒有呼叫端，而框架自 1.2.0 起也不再拋出 `JsonRpcException`。
- **現在：** 三個型別都移除。各 connector 的 `ExecuteAsync` 與 `ApiCallContext` 改用成員與值都相同的
  `Polhem.JsonRpc.Payload.PayloadFormat`。線路格式不變。
- **遷移：**

  | 移除 | 替代 |
  |------|------|
  | `Polhem.Api.Core.Messages.PayloadFormat` | `Polhem.JsonRpc.Payload.PayloadFormat`：用到 `PayloadFormat` 的地方把 `using Polhem.Api.Core.Messages;` 換成 `using Polhem.JsonRpc.Payload;` |
  | `Polhem.Core.Serialization.Gzip` | 直接使用 `System.IO.Compression.GZipStream` |
  | `Polhem.Api.Core.JsonRpc.JsonRpcException` | 原本拋出它來顯示訊息的商業物件改拋 `UserMessageException`；它以相同的代碼（`-32099`）傳遞，用戶端看不出差異 |

  接著重新編譯所有參考 Polhem 套件的專案：以較早 1.x 建置、又用到已移除型別的組件，執行時會失敗。
- **背景：** 移除 `PayloadFormat` 與 `Gzip` 會破壞原始碼與二進位相容性。這是 1.x 內第四個語意化版本的例外，前三個是 1.1.0、1.2.0 與
  1.3.0，並且與它們一樣有自己的 ADR：[ADR-051](../../../maintainers/adr/adr-051-remove-jsonrpc-leftovers-in-1-x.md)。兩者都沒有
  應用程式會失去的行為。`JsonRpcException` 依本版新增的規則移除：[ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md)
  的決策 4 允許框架的例外型別在次版號中變更，前提是發佈說明要列出這項變更。JSON-RPC 錯誤碼，以及每種失敗以哪個代碼傳遞，仍受語意化版本
  約束，因為用戶端是拿數字來比對的。

### `[TreeNode]` 與 `[TreeNodeIgnore]` 移到 Polhem.Definition

- **影響對象：** 套用了 `[TreeNode]` 或 `[TreeNodeIgnore]` 的自訂型別。
- **原本：** `TreeNodeAttribute` 與 `TreeNodeIgnoreAttribute` 位於 `Polhem.Core.Attributes`（`Polhem.Core`）。框架沒有任何地方讀取它們，
  套用與否對行為沒有影響。
- **現在：** 它們位於 `Polhem.Definition.Attributes`（`Polhem.Definition`），與它們所標註的定義型別放在一起，並由 `ObjectTreeBuilder` 讀取。
- **遷移：** 在這些型別中把 `using Polhem.Core.Attributes;` 換成 `using Polhem.Definition.Attributes;`。

### `DatabaseItem` 改以 `Id` 為標籤

- **影響對象：** 顯示或比對 `DatabaseItem.ToString()` 結果的程式碼。
- **原本：** `DatabaseItem.ToString()` 與其 `[TreeNode]` 標籤使用 `DbName`，因此不指定資料庫名稱的項目（例如 SQLite）顯示空白名稱。
- **現在：** 兩者都改用 `Id`。
- **遷移：** 需要資料庫名稱的地方明確讀取 `DbName`。
