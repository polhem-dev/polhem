# Polhem 1.4.0 — 詳細發佈說明

[English](../../en/changelogs/1.4.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.4.0]` 條目的詳細說明。變更紀錄以一行列一項變更；本檔保留
理由與背景。

> **需要 .NET SDK 10.0.400 以上。** `Polhem.Definition` 套件內附的分析器改以 Microsoft.CodeAnalysis 5.9 建置。較舊的編譯器
> 不會執行它們，並回報 `CS9057`；專案若設定 `TreatWarningsAsErrors`，建置就會失敗。見「如何升級」。

## 為什麼是次版號

這一版新增了公開 API（物件樹、屬性方格），並移除三個在 1.2.0 改用 Polhem.JsonRpc 後已無用途的公開型別：
`Polhem.Api.Core.Messages.PayloadFormat`、`Polhem.Core.Serialization.Gzip` 與 `Polhem.Api.Core.JsonRpc.JsonRpcException`。

前兩項移除會破壞原始碼與二進位相容性。這是 1.x 內第四個語意化版本的例外，前三個是 1.1.0、1.2.0 與 1.3.0，並且與它們一樣有自己的 ADR：
[ADR-051](../../../maintainers/adr/adr-051-remove-jsonrpc-leftovers-in-1-x.md)。兩者都沒有應用程式會失去的行為：格式列舉在另一個
命名空間下有相同的成員與值，而 `Gzip` 只是 `GZipStream` 的薄包裝，框架內也已沒有任何呼叫端。

`JsonRpcException` 依本版新增的規則移除：[ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md) 的
決策 4 允許框架的例外型別在次版號中變更，前提是發佈說明要列出這項變更。JSON-RPC 錯誤碼，以及每種失敗以哪個代碼傳遞，仍受語意化版本
約束，因為用戶端是拿數字來比對的。

`TreeNodeAttribute` 與 `TreeNodeIgnoreAttribute` 從 `Polhem.Core` 移到 `Polhem.Definition`。這是把兩個已出貨的型別搬到另一個組件，
但在本版之前框架沒有任何地方讀取它們，套用與否對行為沒有影響，所以列在「變更」而不是破壞性變更。

線路格式沒有改變：1.4.0 的用戶端與 1.3.x 的伺服端（反之亦然）可以互通。

## 如何升級

1. **以 .NET SDK 10.0.400 以上建置。** 用 `dotnet --version` 確認。若 `global.json` 鎖定了較舊的 SDK band，也要一起調整。
   CI 上以 `actions/setup-dotnet` 搭配 `dotnet-version: 10.0.x`，取得的已是 10.0.4xx 的 SDK。
2. 把 Polhem 套件升到 1.4.0。
3. 程式碼若用到 `PayloadFormat`，把 `using Polhem.Api.Core.Messages;` 換成 `using Polhem.JsonRpc.Payload;`。成員與值都相同。
4. 程式碼若呼叫 `Gzip`，改為直接使用 `System.IO.Compression.GZipStream`。
5. 商業物件若拋出 `JsonRpcException` 來顯示訊息，改拋 `UserMessageException`。它以相同的代碼（`-32099`）傳遞，用戶端看不出差異。
6. 自訂型別若套用了 `[TreeNode]` 或 `[TreeNodeIgnore]`，把 `using Polhem.Core.Attributes;` 換成 `using Polhem.Definition.Attributes;`。
7. 重新編譯所有參考 Polhem 套件的專案：以較早 1.x 建置、又用到已移除型別的組件，執行時會失敗。

伺服端與用戶端不需要同時升級。

## 物件樹與屬性方格

這些是 DefineEditor 現在用來建文件樹與屬性面板的元件，適用於桌面工具。

- **`ObjectTreeBuilder`**（`Polhem.Definition.ObjectTree`）從物件圖建立與 UI 無關的 `ObjectTreeNode` 樹，只追蹤值帶有
  `[TreeNode]` 的屬性。它會略過集合基底型別所宣告的屬性，因此集合項目的反向參照不會變成節點；`[Browsable(false)]` 不參與判斷，
  因為定義型別在集合屬性上標它，是為了不讓這些屬性出現在屬性方格中。每個物件只成為一個節點，再加上
  `ObjectTreeOptions.MaxDepth`，可以阻止循環。`PropertyFilter`、`NodeBuilt` 與 `LabelTranslator` 讓使用端縮小、擴充與翻譯這棵樹。
  命令（`ITreeNodeCommandProvider`）與拖放排序（`ITreeNodeDragDropHandler`）同樣以與 UI 無關的方式描述，`Polhem.UI.Avalonia`
  的 `ObjectTreeView` 會連同兩者一起顯示這棵樹。
- **定義型別的 `[TreeNode]` 標註改依同一條資料夾規則**：擁有者有兩個以上帶標註的集合時，集合以資料夾呈現，否則直接掛在擁有者下。
  `TreeNodeAnnotationGateTests` 鎖定這條規則，以及每個帶標註的型別都以與其 `ToString()` 相同的方式組成標籤。
- **`PropertyGridControl`**（`Polhem.UI.Avalonia`）依屬性上的 ComponentModel 標註編輯物件：`[Category]`、`[Description]`、
  `[DisplayName]`、`[Browsable]`、`[DefaultValue]`、`[TypeConverter]` 與 `[PasswordPropertyText]`。集合屬性會在
  `CollectionEditDialog` 中開啟，它編輯的是項目的副本，只有按下確定才取代集合的項目。這個控制項透過 `TypeDescriptor` 讀取型別，
  而 trim 不會保留這些資訊，所以不適用於經過 trim 的行動端 head。
- **定義型別每個可瀏覽的屬性現在都宣告了 `[Category]` 與 `[Description]`**，屬性方格因此能分組並顯示說明；
  `EditorAnnotationGateTests` 鎖定這一點。編輯器以樹節點呈現的集合標為 `[Browsable(false)]`。這些 attribute 都不改變 XML 或線路格式。

## 修正

- **在 Avalonia 12.1 下，登入者的 culture 重新生效。** Avalonia 12.1
  （[AvaloniaUI/Avalonia#21627](https://github.com/AvaloniaUI/Avalonia/pull/21627)）會在每次 dispatcher 作業後，把 UI 執行緒
  當下的 culture 寫回去。`ClientInfo` 是在非同步的登入處理常式中設定使用者的 culture，執行環境在下一個 `await` 就把這個變更還原，
  因此在中文作業系統上，en-US 帳號看到的是中文標題與日期格式。`ClientInfo` 現在也會把 culture 投遞到呼叫端的同步內容，
  由一個單純的回呼來設定。`Polhem.UI.Avalonia` 接受 Avalonia 12.0.0 以上，所以自行升到 12.1 的應用程式在 1.3.x 也會受影響。
  （[#95](https://github.com/polhem-dev/polhem/pull/95)）

## 相依套件

- MessagePack 3.1.11、DynamicExpresso.Core 2.19.6，以及框架所參考的 `Microsoft.Extensions` 套件的 10.0.12 版。
  這些是 NuGet 為應用程式解析出的最低版本。
- 分析器改用 Microsoft.CodeAnalysis 5.9，這就是 SDK 門檻提高的原因。分析器建置時所參考的版本，就是能載入它的最低編譯器版本，
  因此每個參考 `Polhem.Definition` 的專案所需的 SDK 都跟著提高。（[#96](https://github.com/polhem-dev/polhem/pull/96)）

  分組與說明已翻成繁體中文。
- Avalonia.DemoCenter 新增 Property Grid 案例。
- Avalonia 的各個 head 改用 Avalonia 12.1 與 Semi.Avalonia 12.1。Northwind 的 iOS head 改為需要 iOS 15.0，這是 .NET SDK 10.0.400
  的 iOS workload 所接受的最低版本。Northwind 的 Android head 維持 Xamarin.AndroidX.Core.SplashScreen 1.0.1.15：1.2.0.3 會帶進
  AndroidX Lifecycle 2.11，超出 Avalonia.Android 依賴的範圍，Android 建置會失敗。
