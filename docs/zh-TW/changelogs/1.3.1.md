# Polhem 1.3.1 — 發佈說明

[English](../../en/changelogs/1.3.1.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.3.1]` 條目的詳細內容。

這一版改變用戶端內部封裝呼叫的方式，並把可接受的 Polhem.JsonRpc 最低版本提高到 1.2.0。`PublicAPI.Shipped.txt` 基準沒有任何
新增、移除或變更，線路格式也與 1.3.0 相同，所以 1.3.1 的用戶端與 1.3.0 的伺服端（反之亦然）可以互通：伺服端與用戶端不必
一起升級。

## 新功能與變更

### 用戶端透過 `PayloadConnector` 封裝呼叫

`ApiConnector` 原本自己用 `PayloadProcessor.WrapRequest` 包裝參數、讀回實際送出的格式、呼叫 JSON-RPC connector，再自己開啟
結果。[Polhem.JsonRpc 1.2.0](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/CHANGELOG.md) 新增了做這件事的套件
`Polhem.JsonRpc.Payload.Client`，`ApiConnector` 現在改呼叫它的 `PayloadConnector`。線路格式，以及呼叫採用的格式、金鑰與
序號都不變：金鑰仍取自 session、序號取自 session 的計數器、codec 取自 `PayloadCodec`。Polhem 自己的規則維持原處：本機
provider 在非 debug 模式送 Plain、沒有 session 金鑰的 Encrypted 呼叫改以 Encoded 送出，時區轉換與其防護仍包在呼叫前後。

`Polhem.Api.Client` 改參考 `Polhem.JsonRpc.Payload.Client`，取代 `Polhem.JsonRpc.Client`（仍經由它間接參考）。這需要
Polhem.JsonRpc 1.2.0 以上：把 Polhem 套件更新到 1.3.1 時，NuGet 會一併帶入；自行鎖定 Polhem.JsonRpc 版本的應用程式，請把
鎖定版本提高到 1.2.0 以上。([#63](https://github.com/polhem-dev/polhem/pull/63))

### 文件

- 開發限制文件與 `StaticApiEncryptionKeyProvider` 的說明，寫明共用 API 金鑰留下的缺口：所有用戶端共用一把金鑰時，序號仍以
  session 為單位計算。因此在時間戳記的容許範圍內，於某個 session 攔截到的呼叫，只要由能出示另一個 session 的人送到
  該序號仍未用過的 session，就會被接受，而且不需要持有金鑰。預設的 `DerivedApiEncryptionKeyProvider` 讓每個 session 各有
  自己的金鑰。([#62](https://github.com/polhem-dev/polhem/pull/62))

## 破壞性變更

### 回應沒有結果時改擲出 `InvalidPayloadException`

- **影響對象：** 呼叫非 Polhem 伺服端、且對方可能回應時完全沒有 `result` 的 .NET 用戶端，以及 catch 原本擲出的
  `InvalidOperationException` 的程式碼。Polhem 伺服端一定會以 payload 外殼回應，所以 Polhem 伺服端的用戶端不會遇到這個變更。
- **原本：** `ApiConnector` 擲出 `InvalidOperationException`（"The API answered without a result."）。
- **現在：** Encoded 或 Encrypted 呼叫會因為缺少的結果不是該呼叫的格式，而擲出 Polhem.JsonRpc 的
  `InvalidPayloadException`；Plain 呼叫則讀成 null 值。
- **遷移：** 在原本 catch `InvalidOperationException` 的地方，Encoded 或 Encrypted 呼叫改為 catch
  `InvalidPayloadException`，Plain 呼叫則處理 null 值。([#63](https://github.com/polhem-dev/polhem/pull/63))
