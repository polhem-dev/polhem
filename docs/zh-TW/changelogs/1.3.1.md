# Polhem 1.3.1 — 詳細發佈說明

[English](../../en/changelogs/1.3.1.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.3.1]` 條目的詳細說明。變更紀錄以一行列一項變更；本檔保留
理由與背景。

## 為什麼是修訂號

`PublicAPI.Shipped.txt` 基準沒有任何新增、移除或變更，線路格式也與 1.3.0 相同，所以 1.3.1 的用戶端與 1.3.0 的伺服端
（反之亦然）可以互通。這一版改變的是用戶端內部封裝呼叫的方式，並提高可接受的 Polhem.JsonRpc 最低版本。

## 如何升級

把 Polhem 套件更新到 1.3.1。NuGet 會一併帶入 Polhem.JsonRpc 1.2.0；自行鎖定 Polhem.JsonRpc 版本的應用程式，請把鎖定版本
提高到 1.2.0 以上。伺服端與用戶端不必一起升級。

## 行為變更

- **用戶端透過 `PayloadConnector` 封裝呼叫。** `ApiConnector` 原本自己用 `PayloadProcessor.WrapRequest` 包裝參數、
  讀回實際送出的格式、呼叫 JSON-RPC connector，再自己開啟結果。
  [Polhem.JsonRpc 1.2.0](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/CHANGELOG.md) 新增了做這件事的套件
  `Polhem.JsonRpc.Payload.Client`，`ApiConnector` 現在改呼叫它的 `PayloadConnector`。金鑰仍取自 session、序號取自 session
  的計數器、codec 取自 `PayloadCodec`。Polhem 自己的規則維持原處：本機 provider 在非 debug 模式送 Plain、沒有 session
  金鑰的 Encrypted 呼叫改以 Encoded 送出，時區轉換與其防護仍包在呼叫前後。
  `Polhem.Api.Client` 改參考 `Polhem.JsonRpc.Payload.Client`，取代 `Polhem.JsonRpc.Client`（仍經由它間接參考）。
  ([#63](https://github.com/polhem-dev/polhem/pull/63))
- **回應沒有結果時的失敗方式不同。** 伺服端回應呼叫時完全沒有 `result`，原本會讓 `ApiConnector` 擲出
  `InvalidOperationException`（"The API answered without a result."）。現在 Encoded 或 Encrypted 呼叫會因為缺少的結果
  不是該呼叫的格式，而擲出 Polhem.JsonRpc 的 `InvalidPayloadException`；Plain 呼叫則讀成 null 值。Polhem 伺服端一定會以
  payload 外殼回應，所以只有在對象不是 Polhem 伺服端時才會遇到。([#63](https://github.com/polhem-dev/polhem/pull/63))

## 文件

- 開發限制文件與 `StaticApiEncryptionKeyProvider` 的說明，寫明共用金鑰留下的缺口：所有用戶端共用一把金鑰時，序號仍以
  session 為單位計算。因此在時間戳記的容許範圍內，於某個 session 攔截到的呼叫，只要由能出示另一個 session 的人送到
  該序號仍未用過的 session，就會被接受，而且不需要持有金鑰。預設的 `DerivedApiEncryptionKeyProvider` 讓每個 session 各有自己的
  金鑰。([#62](https://github.com/polhem-dev/polhem/pull/62))
