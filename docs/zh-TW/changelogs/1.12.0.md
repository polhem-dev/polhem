# Polhem 1.12.0 — 發佈說明

[English](../../en/changelogs/1.12.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.12.0]` 條目的詳細內容。

本版尚在開發中。wire 格式與 1.11.0 相同。

## 新功能與變更

### 清單的分頁按鈕

`ListView` 以往只讀取一頁伺服器資料且沒有任何提示，超過 `PagingOptions.MaxPageSize` 的資料都不會顯示。現在每次顯示 50 筆，提供上一頁、下一頁、目前位置，
以及每頁 50、100 或 200 筆的選項。`ReloadAsync` 會停留在目前頁面；該頁變成空白時（例如刪除該頁最後一筆後），則回到最後一個還有資料的頁面。

Blazor Server 的 `FormPage` 行為相同，分頁列的樣式來自 `polhem.css`；使用自有樣式表的 host 可以設定 `polhem-form-page__pager`。

分頁位置由 `Polhem.UI.Core` 的 `ListPagingState` 保存，兩個前端共用。文字來自新增的 `PolhemUIText` 鍵值 `PreviousPage`、`NextPage`、`PageNumber`、
`PageNumberOfTotal` 與 `RowsPerPage`。替換 `UIText.Localizer` 的 host 在宣告這些鍵值之前，會看到英文文字。

### 分頁與開窗的穩定排序

`GetLookup` 改依第一個可排序的開窗欄位排列候選資料，開窗不再依建立順序列出。`Text` 與 `Binary` 欄位會略過；沒有可排序的欄位時，仍依
`sys_no` 排序。呼叫端不能選擇排序方式。

分頁的 `GetList` 帶明確排序時，若排序未指定 `sys_no`，現在會補上 `sys_no`；資料表沒有 `sys_no` 時則補 `sys_rowid`。排序值相同的資料列順序因此固定，
跨頁不再重複或漏筆。空的排序視同未指定排序。

位移大到無法計算的頁碼，在 `GetList`、`GetLookup` 與稽核記錄查詢中會回傳欄位但不含資料列，`HasMore` 為 false。先前會失敗，或在某些頁碼回傳前面頁面的資料。

### 從唯讀表單開啟關聯欄位的資料

在 Blazor Server 的 `FormPage` 或 Avalonia 的 `FormView` 以唯讀顯示的記錄上，雙擊宣告了 `RelationProgId` 的欄位，會在對話框中以唯讀方式開啟該欄位指向的資料。
例如在假單上雙擊假別，就會開啟那筆假別。按「關閉」回到原本的假單，狀態不變。對話框裡的關聯欄位也能再開啟下一筆，疊在上層。

只有使用者對關聯表單的權限模型有 `Read` 權限時才會開啟：頁面在向後端要任何資料之前，先以所進入公司的權限快照判斷，
沒有權限就在提示中指出該表單名稱。關聯表單沒有權限模型時，任何人都能開啟。最終仍由後端把關：對話框經由關聯表單的
`GetData` 載入資料，它會檢查權限與記錄範圍。

能挑選與能檢視是兩種權限。查詢窗不要求關聯表單的 `Read` 權限，所以使用者可能持有某個值，卻無權開啟它。

記錄為唯讀時，有值的關聯欄位會顯示手形游標與提示「按兩下開啟這筆資料」。編輯中則一切照舊，欄位保留查詢按鈕。

明細格的關聯欄也一樣：記錄為唯讀時雙擊該儲存格即可開啟，例如訂單明細的產品。編輯中雙擊資料列，仍然是開啟該列的編輯表單。

在 Avalonia 上，對話框和查詢窗一樣：桌面 classic-window lifetime 下是原生視窗，browser、iOS、Android 上則是疊層。
對話框內是關聯表單的 `FormView`，它從開啟它的畫面所用的同一個來源取得定義，按鈕顯示「關閉」而非「返回」。
`FormView` 的子類別可以替換這兩個步驟：`CreateRelatedView` 建立關聯畫面，`ShowRelatedViewAsync` 負責呈現。

在 Blazor Server 上自行組頁面時，可使用這些公開元件：

- `RelatedRecordDialog`（`Polhem.Web.Blazor.Server.Components`）顯示一筆關聯資料。
- `FormLayoutPresenter.OpenRelation` 與 `FormScope.OpenRelation` 接收欄位要求開啟的資料；沒有處理常式時，欄位不提供這項操作。
- `RelationOpenRules` 與 `RelationTarget`（`Polhem.UI.Core.Fields`）是各前端共用的規則：欄位何時提供這項操作、開啟哪一筆、
  使用者能否讀取。

`PolhemUIText` 新增 `Close`、`OpenRelatedRecord`、`RelatedRecordDenied` 三個鍵，並附繁體中文翻譯。套件樣式表 `polhem.css`
加入對話框與游標的樣式。

### Avalonia 以警告樣式顯示訊息，以錯誤樣式顯示失敗

`FormView` 的訊息列原本一律使用錯誤樣式。現在使用者可以處理的訊息改用警告樣式，包括必填欄位未填、後端回傳的驗證訊息、停止即時計算的計算欄位，以及使用者無權開啟的關聯資料。真正的失敗（例如呼叫擲出例外）仍使用錯誤樣式。Blazor Server 的 `FormPage` 則以警告樣式顯示它的提示。

### 刪除記錄前會先詢問

Avalonia 的 `ListView` 與 Blazor Server 的 `FormPage` 按下 Delete 後，原本會立刻刪除選取的記錄。現在兩者都會先詢問，且焦點預設停在安全的選項上。在 Avalonia，這個問題在桌面上是視窗，在瀏覽器與行動裝置上是覆蓋層。

想維持舊行為的應用程式，將 `ConfirmDelete` 設為 `false`：在 `FormPage` 是參數，在 `ListView` 是 styled property，因此樣式 setter 也能套用到外殼建立的清單。`ListView` 的子類別可覆寫 `ConfirmDeleteAsync`，用自己的方式詢問。

`PolhemUIText` 新增鍵 `DeleteRecordPrompt`，並附繁體中文翻譯。`polhem.css` 提供對話框的樣式。
