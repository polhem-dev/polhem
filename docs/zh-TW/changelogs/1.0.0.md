## 新功能與變更

### 新的名稱與新的 repo

Polhem 就是原本以 Bee.NET 發佈的框架，移到 `polhem-dev` 組織，以便由多人共同維護。它從新的 repo
`polhem-dev/polhem` 開始，不帶 git 歷史；搬移之前的歷史留在已凍結的 `jeff377/bee-library`。`Bee.*` 套件不再開發，
新的套件 ID 從 1.0.0 開始自己的版號。

作者與著作權人為 Polhem contributors，專案與 repository 網址指向 `polhem-dev/polhem`，套件換上新的 Polhem 圖示。
授權仍是 MIT。`Polhem.Cli` 共用相同的中繼資料，並隨附 README 與符號套件。([#3](https://github.com/polhem-dev/polhem/pull/3))

1.0.0 之前，框架做過一次全面審查：安全、wire 合約、並行、公開 API、測試、國際化、效能與修剪。修正都在首次發佈前
完成，所以修正公開 API 不必等到 2.0.0。公開 API 現在遵循的規則記錄在
[ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md)。

### 安全性強化

讓伺服端拒絕原本會接受之請求的變更，見[伺服端更嚴格地檢查請求](#伺服端更嚴格地檢查請求)；讓 session 與舊密碼雜湊失效
的變更，見[session 結束，舊格式的密碼雜湊不再通過驗證](#session-結束舊格式的密碼雜湊不再通過驗證)。其餘如下：

- **密碼。** 新的雜湊使用 PBKDF2-SHA256、600,000 次迭代（當時的 OWASP 建議），格式本身記錄迭代次數；迭代次數較少的
  雜湊在下次登入成功時換新（`PasswordHasher.NeedsRehash`）。不存在的帳號也會執行一次誘餌雜湊，所以登入失敗花的時間不會
  透露帳號是否存在；登入嘗試追蹤器有容量上限。([#5](https://github.com/polhem-dev/polhem/pull/5))
- **稽核規則與 ProgId 大小寫。** 呼叫端無法靠改變 ProgId 的大小寫避開稽核規則。不論呼叫端用什麼大小寫，progId 都會
  解析到它的表單，所以稽核規則也必須如此。保留與已註冊 progId 的業務物件，以 `ProgramSettings` 宣告的大小寫建立
  （[#4](https://github.com/polhem-dev/polhem/pull/4)）。剩下的是註冊表沒有列出的表單：它們保留呼叫端的大小寫，而完全
  比對的規則查找，讓呼叫端能以另一種大小寫進入這種表單、退回部署預設。`CompanyAuditRules` 現在以不分大小寫的方式查找
  規則（只差在大小寫的兩條規則，保留第一條），稽核紀錄寫入 FormSchema 的 ProgId 寫法（見
  [稽核與記錄表的紀錄改變](#稽核與記錄表的紀錄改變)）。([#26](https://github.com/polhem-dev/polhem/pull/26))
- **錯誤訊息中的伺服端路徑。** 找不到定義檔時，過去的訊息帶有完整路徑。除錯模式的 host 會把未對應的例外訊息傳給
  遠端呼叫端，而 FormSchema 是依請求指定的 progId 取得，因此任何呼叫端都能得知伺服端的目錄結構。
  `FileUtilities.EnsureFileExists` 只寫出檔名；完整路徑留在 `FileNotFoundException.FileName`，供伺服端記錄使用。
  ([#26](https://github.com/polhem-dev/polhem/pull/26))
- **磁碟上的金鑰。** 主金鑰檔與用戶端的 `apikey.txt` 以僅擁有者可存取的權限寫入；`DatabaseSettings` 含密碼卻沒有
  `ConfigEncryptionKey` 保護時會記錄警告。([#5](https://github.com/polhem-dev/polhem/pull/5))
- **DDL 與連線字串。** SQL Server 的字串預設值會被跳脫；連線字串的佔位字透過 `DbConnectionStringBuilder` 填入
  （`ConnectionStringTemplate`）。([#4](https://github.com/polhem-dev/polhem/pull/4))

### 在地化

內建文字以英文為基底語言，並隨附 `zh-TW` 翻譯；這對既有應用程式造成的改變，見[英文為基底語言](#英文為基底語言)。新增的
成員有 `LanguageFallback`、`MenuLocalizer`、`FrameworkLanguageService`、`PolhemMessages`、`PolhemUIText`、
`ILocalizableMessage`，以及 Avalonia 與 Blazor UI 文字的英文預設值與 `zh-TW` 翻譯。給終端使用者的框架訊息以帶有鍵值與
參數的 `UserMessageException` 擲出。`FormView`、`ListView`、`LookupDialog` 預設透過 `ClientInfo.DefinitionLoader`
在地化定義。([#15](https://github.com/polhem-dev/polhem/pull/15), [#22](https://github.com/polhem-dev/polhem/pull/22))

### 日期時間編輯器，以及清單中的清單項目文字

`ControlType.DateTimeEdit` 編輯 `DateTime` 欄位：Avalonia 的 `DateTimeEdit` 編輯器是以使用者文化顯示與剖析日期時間的
文字框，Blazor 使用 `datetime-local` 輸入框。`Date` 欄位仍用 `DateEdit`。清單透過 `FormValueBinding.TryGetListItemText`
顯示下拉欄位的清單項目文字；`GridControl.Bind` 新增接收 `FormTable` 的多載，`DynamicGrid.FormTable` 亦同。哪些版面會用到
新的編輯器，見[產生的版面改用其他編輯器](#產生的版面改用其他編輯器)。([#33](https://github.com/polhem-dev/polhem/pull/33))

### 設定與啟動

- **元件。** `BackendComponents` 各項預設為空白，空白代表框架預設，因此設定檔不必寫出框架內部型別的名稱。只是重複
  Bee.NET 預設值的項目，請直接清空，不必改名。([#8](https://github.com/polhem-dev/polhem/pull/8),
  [#11](https://github.com/polhem-dev/polhem/pull/11))
- **自訂定義元件。** `BackendComponents` 指定的 `DefineAccess` 或 `DefineStorage` 型別，過去必須宣告固定幾種建構子之一。
  現在改由 `ActivatorUtilities` 建立，建構子可以接收任何已註冊的服務；`byte[]` 參數仍會收到設定加密金鑰，儲存區的
  `(IServiceProvider)` 建構子仍然優先，因為以資料庫為後端的儲存區會延後解析其相依。
  ([#26](https://github.com/polhem-dev/polhem/pull/26))
- **啟動警告。** 方法要求 `ApiReplayProtection.UniqueSequence` 而 `RequireWireFrame` 關閉時，啟動時記錄警告，並列出未
  宣告權限模型的表單。這份清單過去只看 `ProgramSettings`，但註冊表沒有列出的 progId 仍由 `FormBusinessObject` 提供服務，
  所以現在也列出定義儲存區中的表單（`IDefineStorage.GetFormSchemaIds`）。這個成員有回傳空清單的預設實作，所以自訂的
  儲存區照樣能編譯；實作它，該儲存區的表單才會納入檢查。([#4](https://github.com/polhem-dev/polhem/pull/4),
  [#6](https://github.com/polhem-dev/polhem/pull/6), [#26](https://github.com/polhem-dev/polhem/pull/26))

### 快取中的定義不因序列化而改變

序列化快取中的定義不再改動它，因此快取中的定義正在序列化時，並行的儲存與刪除不再失敗。每個物件的序列化狀態已移除；
空集合改由唯讀的 `XSpecified` 屬性省略，iOS 上僅用反射的 `XmlSerializer` 接受這種寫法。內建定義檔重新序列化後逐位元組
相同。([#8](https://github.com/polhem-dev/polhem/pull/8))

### 效能

變更當時的量測：

- 帶檔案 token 的定義快取命中，由 1,216 ns 降到 62 ns，因為每個項目每秒最多檢查一次來源檔。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- Gzip 預設以最快等級壓縮：570 KB 的 payload 由 1.67 ms 降到 0.48 ms，輸出由 80 KB 變成 110 KB。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- `AesCbcHmacCryptor` 改用 span API，加密 173 KB 的 payload，配置由 694 KB 降到 174 KB，輸出格式不變。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- 快取每個請求的反射結果後，存取控制查找由 506 ns 降到 20 ns；Avalonia 各 head 共用一個運算式求值器。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- 20 欄、10,000 列的 `DataTable` 經 MessagePack：原始位元組少 57%、壓縮後少 10%、序列化時間少 86%、配置少 83%（新的
  寫法見 [wire 合約改變](#wire-合約改變)）。([#12](https://github.com/polhem-dev/polhem/pull/12))
- 稽核批次寫入器以單一交易寫入一批。([#14](https://github.com/polhem-dev/polhem/pull/14))

### 平台支援

- **修剪。** Polhem 支援不修剪與部分修剪的建置。使用端專案以 NativeAOT 發佈、以 `TrimMode=full` 修剪，或停用
  System.Text.Json 反射時，`POLHEM9004` 會發出警告；把 `PolhemSuppressTrimSupportWarning` 設為 `true` 可關閉。
  `Polhem.Expressions` 隨附 ILLink descriptor，行動端預設的修剪會保留運算式以反射取用的成員。
  ([#7](https://github.com/polhem-dev/polhem/pull/7), [#17](https://github.com/polhem-dev/polhem/pull/17))
- **行動端與瀏覽器。** `LookupDialog` 與 `RowEditDialog` 只在桌面開原生視窗，其他平台一律使用覆蓋層（overlay host），
  因此 lookup 在 iOS、Android 與瀏覽器都能使用。MessagePack 值格式器不需動態程式碼即可處理 Polhem 列舉與巢狀的
  `ParameterCollection`；HTTP 用戶端在瀏覽器、Android 與 Apple 行動端 head 使用平台預設的處理器。
  ([#7](https://github.com/polhem-dev/polhem/pull/7), [#17](https://github.com/polhem-dev/polhem/pull/17))
- **iOS 上的運算式。** 在無法於執行時產生程式碼的平台，`LambdaExpression.Compile()` 會退回直譯器，但直譯器仍會建立
  與 lambda 簽章完全相同的委派，超過兩個參數就需要產生程式碼。在 iOS 上，`quantity * unit_price * (1 - discount)` 這類
  計算欄位會讓 App 以 `ExecutionEngineException` 終止；Mac Catalyst 也一樣。`DynamicExpressoEvaluator` 現在把每個運算式
  編譯成單一個以物件陣列接收變數的委派，不需要動態程式碼；快取、null 處理與例外行為不變。
  ([#30](https://github.com/polhem-dev/polhem/pull/30))
- **macOS 與 Linux 上的 Local 模式。** `FileUtilities.IsLocalPath` 過去只接受 Windows 磁碟機與 UNC 路徑，所以 macOS
  或 Linux 上的桌面 head 無法以 Local 模式連線（「Unrecognized connection type」）。現在接受目前作業系統上的完整路徑，
  Windows 的兩種形式則在各平台都能辨識。([#29](https://github.com/polhem-dev/polhem/pull/29))
- **手機上的覆蓋層。** 面板的最小寬度壓過覆蓋層卡片的最大寬度，使 lookup 對話框在手機上左右兩側被切掉；在 iOS 上，
  螢幕鍵盤還會蓋住明細列編輯的按鈕。現在由覆蓋層承載的面板不再自行設定最小寬度，覆蓋層讓卡片留在安全區域內、位於鍵盤
  之上，lookup 與明細列編輯面板的按鈕也留在捲動內容之外。([#33](https://github.com/polhem-dev/polhem/pull/33))

### 修正

- **Plain 讀取。** 帶值過濾條件的 Plain `GetList` 在 SQL 參數處失敗；用戶端把 Plain 的 `DataTable` 結果讀成空表。
  ([#9](https://github.com/polhem-dev/polhem/pull/9))
- **快取競爭。** 與失效通知競爭的快取填入可能保留過期值。([#8](https://github.com/polhem-dev/polhem/pull/8))
- **語系資源。** 從用戶端儲存語系資源一律失敗。([#17](https://github.com/polhem-dev/polhem/pull/17))
- **AuditRule 表單。** 隨附的 AuditRule 表單在沒有定義載入器時，模式下拉選單是空的。
  ([#7](https://github.com/polhem-dev/polhem/pull/7))
- **Blazor circuit。** 登入時沒有設定 circuit 的時區，`FormDataObject` 沒有回到 circuit 的內容繼續執行。
  ([#8](https://github.com/polhem-dev/polhem/pull/8))
- **資料庫設定。** `SaveDatabaseSettings` 加密的是傳入執行個體本身的密碼，而不是副本。
  ([#8](https://github.com/polhem-dev/polhem/pull/8))
- **重建時縮小欄位。** `UpgradeOptions.AllowColumnNarrowing` 過去只在 `ALTER` 路徑檢查，因此重建資料表（SQLite 上的
  任何欄位變更）可能在未開啟選項時縮小欄位並截斷資料。重建路徑現在套用同樣的檢查。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **關聯 JOIN。** 表單資料表沒有 `DbTableName` 時，產生的 JOIN 使用空白的資料表名稱；現在與 SQL 建構器其他部分一樣
  改用 `TableName`。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **中文的書寫系統標籤。** 語系資源以地區命名（`zh-TW`、`zh-CN`），macOS 與 iOS 回報的卻是書寫系統（`zh-Hant-TW`），
  所以在那裡永遠用不到 `zh-TW` 資源。`LanguageFallback` 在 `zh-Hant-TW` 與 `zh-Hant` 之後接 `zh-TW`，在 `zh-Hans-CN` 與
  `zh-Hans` 之後接 `zh-CN`；以書寫系統本身命名的資源仍會先嘗試。([#26](https://github.com/polhem-dev/polhem/pull/26))
- **範圍外的明細列。** 明細列屬於此次儲存未包含的記錄時，儲存會拒絕它，過去的訊息只有英文；現在有訊息鍵
  （`PolhemMessages.PermissionDetailOutOfScope`）與 `zh-TW` 翻譯。([#26](https://github.com/polhem-dev/polhem/pull/26))
- **主機指定的版面。** `FormView` 套用權限能力時，直接縮減主機指定的 `Layout`，使主機手上的執行個體被改掉；現在改在
  副本上進行。([#27](https://github.com/polhem-dev/polhem/pull/27))
- **清單。** Avalonia 與 Blazor 的表格、卡片清單、lookup 與明細表格，過去顯示下拉欄位儲存的代碼；現在顯示使用者語言的
  清單項目文字。布林值在卡片清單顯示停用的核取方塊，其他地方顯示在地化的是／否。手機寬度的 Avalonia 卡片清單過去在
  日期上顯示時間部分、也不理會數值格式；現在與表格以相同方式格式化。
  ([#29](https://github.com/polhem-dev/polhem/pull/29), [#33](https://github.com/polhem-dev/polhem/pull/33))
- **明細列編輯覆蓋層。** Avalonia 的明細列編輯覆蓋層過去要到確認該列才重算計算欄位；現在編輯時即重算
  （`FormDataObject.RowEditFieldChanged`），按取消則還原。([#30](https://github.com/polhem-dev/polhem/pull/30))
- **Blazor 的日期。** Blazor 的 `DateEdit` 遇到帶時間的值會顯示空白，因為日期輸入框只接受日期；現在顯示日期部分。
  ([#33](https://github.com/polhem-dev/polhem/pull/33))
- **Blazor 的 Remote 模式。** 照 Blazor Server 的 README 以 Remote 模式執行會得到 `401 Unauthorized`，因為伺服端要求

  必須設定 `ApiClientInfo.ApiKey`。([#29](https://github.com/polhem-dev/polhem/pull/29))

## 破壞性變更

### 套件、命名空間與 Bee 名稱改名

- **影響對象：** 所有以 Bee.NET 建置的應用程式。
- **原本：** 套件與命名空間是 `Bee.*`，有些型別與成員的名稱帶有 `Bee`，命令列工具是 `Bee.Cli`，以 `dotnet bee` 呼叫。
- **現在：** 套件 ID 與命名空間改為 `Polhem.*`，版號從 1.0.0 重新起算。套件的切分不變。型別或成員名稱中的 `Bee` 改為
  `Polhem`。仍使用舊名稱的地方，編譯器都會報出來。
- **遷移：**
  1. 把每個 `Bee.<名稱>` 套件參考換成 `Polhem.<名稱>`，每個 `Bee.<名稱>` 命名空間換成 `Polhem.<名稱>`。
  2. 依下表改名。`IBeeContext`、`BeeContext` 與 `BeeStringLocalizer<T>` 在審查中又改了一次名，見
     [公開型別改名、搬移或改為 sealed](#公開型別改名搬移或改為-sealed)。

     | Bee.NET | Polhem |
     |---------|--------|
     | `AddBeeFramework`、`UseBeeFramework` | `AddPolhemFramework`、`UsePolhemFramework` |
     | `AddBeeBlazor`、`BeeBlazorOptions`、`BeeBlazorProviderMode` | `AddPolhemBlazor`、`PolhemBlazorOptions`、`PolhemBlazorProviderMode` |
     | `BeeApiConnectorFactory`、`BeeAccessTokenProvider` | `PolhemApiConnectorFactory`、`PolhemAccessTokenProvider` |
     | `BeeLoginPanel` | `PolhemLoginPanel` |
     | `BeeFrameworkServiceCollectionExtensions`、`BeeFrameworkApplicationBuilderExtensions`、`BeeBlazorServiceCollectionExtensions` | `PolhemFrameworkServiceCollectionExtensions`、`PolhemFrameworkApplicationBuilderExtensions`、`PolhemBlazorServiceCollectionExtensions` |
     | `Bee.Cli`（`dotnet bee`） | `Polhem.Cli`（`dotnet polhem`） |

  3. 改掉編譯器看不到的字串，見[編譯器不檢查的名稱也改名](#編譯器不檢查的名稱也改名)。
- **背景：** 改名以機械方式進行，驗證方法是把所有名稱改回 `Bee`，再與起點的 Bee.NET 原始碼比對（`jeff377/bee-library`
  的 commit `7d6cc9d9`，其 `src/` 與 `tools/Bee.Cli` 與 `v4.33.0` tag 完全相同）。比對後剩下的只有授權條款、套件中繼
  資料與圖示。完整的測試（含資料庫測試）跑出的測試數與 Bee.NET 相同，且全數通過。有幾類名稱是編譯器不會檢查的字串，
  例如定義檔中的型別名稱、analyzer 以 metadata name 查找的型別、trimming descriptor 中的組件名稱；原本沒有測試的類別都
  補上了測試。這項驗證涵蓋的是改名這一步；之後的首發前審查修改了程式碼，那些變更就是本說明的其他各項。

### 編譯器不檢查的名稱也改名

- **影響對象：** 寫有框架型別名稱的定義檔與設定、依賴主金鑰預設變數名稱的部署、analyzer 的抑制設定、MSBuild 屬性、
  Blazor 元件的樣式表、讀取下列資料 key 的程式碼，以及 Bee.NET 用戶端搭配 Polhem 伺服端（或反過來）的所有組合。
- **原本：** 這些字串帶有 `Bee`。
- **現在：** 改為 `Polhem`，舊名稱不再被辨識。使用舊名稱照樣建置成功，問題只在執行時才出現，或根本不出現：使用舊名稱的
  設定會被忽略，而且沒有警告；Bee.NET 殘留的型別或組件名稱，失敗訊息與其他無法解析的名稱相同；找不到
  `POLHEM_MASTER_KEY` 時，不論 `BEE_MASTER_KEY` 有沒有設定，錯誤訊息都一樣。伺服端只接受允許的命名空間中的 payload
  型別，所以 Bee.NET 用戶端與 Polhem 伺服端無法互通。
- **遷移：**

  | 項目 | Bee.NET | Polhem |
  |------|---------|--------|
  | payload、預設設定，以及定義檔中 `BusinessObject` / `Repository` 繫結的型別名稱 | `Bee.*` | `Polhem.*` |
  | 主金鑰的預設環境變數 | `BEE_MASTER_KEY` | `POLHEM_MASTER_KEY`；在 `MasterKeySource` 寫明變數名稱的 `SystemSettings.xml`，照樣使用該名稱 |
  | analyzer 診斷代號 | `BEEnnnn`，例如 `BEE1008` | `POLHEMnnnn`，數字不變，例如 `POLHEM1008` |
  | 定義檔檢查用的 MSBuild 屬性 | `BeeDefinitionFilesGlob`、`BeeRequireDefinitionFiles`、`BeeAnalyzeDefinitionFiles` | `PolhemDefinitionFilesGlob`、`PolhemRequireDefinitionFiles`、`PolhemAnalyzeDefinitionFiles` |
  | Blazor 元件的 CSS class | `bee-…` | `polhem-…` |
  | 記錄欄位宣告型別的 `DataColumn` 擴充屬性 | `Bee.FieldDbType` | `Polhem.FieldDbType` |
  | `Exception.Data` 的 key `SerializationErrorData.FilePath` | `Bee.FilePath` | `Polhem.FilePath` |
  | 衍生 session 加密金鑰的標籤（`DerivedApiEncryptionKeyProvider`） | `bee-api-*` | `polhem-api-session-key`、`polhem-api-encryption-root-key` |

  以 Bee.NET 建置的應用程式大多放在開發者自己掌控的 repo 裡，一次性的搜尋取代就足夠；
  [從 Bee.NET 遷移](../guides/migrating-from-bee-net.md)附有找出這些名稱的指令。用戶端與伺服端要一起升級。
- **背景：** `POLHEM4001`–`POLHEM4004` 保留不用、永不重複使用：Bee.NET 曾發佈後又停用 `BEE4001`–`BEE4004`，依數字
  對應過來的抑制設定不應讓未來的規則靜默。衍生出的 session 金鑰從不儲存，所以沒有任何儲存的資料依賴這些標籤；無論如何，
  Bee.NET 建立的 session 都會結束（見[session 結束，舊格式的密碼雜湊不再通過驗證](#session-結束舊格式的密碼雜湊不再通過驗證)）。
  Bee.NET 寫入的稽核紀錄仍保留 `Bee.FieldDbType`（見[稽核與記錄表的紀錄改變](#稽核與記錄表的紀錄改變)）。
  ([#10](https://github.com/polhem-dev/polhem/pull/10))

### 用戶端 API 接收服務提供者與取消權杖

- **影響對象：** 建立 `LocalApiProvider` 或本機 connector、使用 `ApiClientInfo.LocalServiceProvider`、
  `ApiClientInfo.ApiEncryptionKey` 或 `ApiClientInfo.UserTimeZoneId`、實作 `IUIViewService`、覆寫 `FormView` 或
  `ListView` 受保護的 `Resolve*Async` 掛勾、在 `SystemApiConnector` 或 `AuditLogApiConnector` 上呼叫 `ExecuteAsync<T>`，
  或呼叫 `JsonRpcExecutor.ExecuteAsync` 的程式碼。
- **原本：** 本機 provider 與 connector 從靜態屬性讀取 `IServiceProvider`，每個 session 的狀態放在 `ApiClientInfo`，
  非同步成員不接收 `CancellationToken`，被取消的呼叫會顯示在畫面上。
- **現在：**
  - `LocalApiProvider` 與本機 connector 的建構子接收 `IServiceProvider`；每個 session 的狀態放在 `ApiSessionContext`。
  - 用戶端介面與 UI 套件（`Polhem.UI.Core`、`Polhem.UI.Avalonia`、`Polhem.Web.Blazor.Server`）所有公開的非同步成員，以及
    `JsonRpcExecutor.ExecuteAsync`，都多一個結尾的 `CancellationToken`，一路傳到 `HttpClient`。請求被取消時伺服端回應
    499，被取消的呼叫會擲回給呼叫端，不再顯示在畫面上。
  - connector 的 action 方法皆為 virtual。
  - `SystemApiConnector` 與 `AuditLogApiConnector` 的 `ExecuteAsync<T>` 為 protected，因為其上每個框架 action 都有
    具型別的方法，主機程式新增的 action 由子類別公開；`FormApiConnector` 的維持公開，因為表單的業務物件可以宣告自己的
    action。
- **遷移：**
  1. 把 `IServiceProvider` 傳給 `LocalApiProvider` 與本機 connector；加密金鑰與使用者時區改從 `ApiSessionContext` 讀取。
  2. 在 `IUIViewService` 的實作與 `Resolve*Async` 掛勾的覆寫加上 `CancellationToken` 參數；原本把被取消的呼叫顯示在
     畫面上的地方，改為捕捉 `OperationCanceledException`。
  3. `SystemApiConnector` 或 `AuditLogApiConnector` 額外的 action，改由子類別公開。
- **背景：** [#10](https://github.com/polhem-dev/polhem/pull/10), [#11](https://github.com/polhem-dev/polhem/pull/11),
  [#12](https://github.com/polhem-dev/polhem/pull/12), [#26](https://github.com/polhem-dev/polhem/pull/26),
  [#27](https://github.com/polhem-dev/polhem/pull/27)

### 擴充介面與快取型別改變

- **影響對象：** 實作 `IReplayWindowStore`、`ICacheDataSourceProvider` 或 `IFormRuleProcessor`、加入 payload codec，
  或設定快取中依資料庫而來之型別、session 公司範圍屬性的主機程式。
- **原本：** 下列成員與 setter 維持 Bee.NET 的形式。
- **現在：**

  | 型別 | 變更 |
  |------|------|
  | `IReplayWindowStore` | 改為單一原子操作 `TryAcceptAsync`，多個伺服端節點共用的儲存才能正確實作 |
  | payload codec | 以 `ApiServiceOptions.RegisterPayloadCodec` 加入。請求未宣告 codec 時使用的仍是 MessagePack，不能替換，因為所有既有用戶端都依賴它 |
  | `ICacheDataSourceProvider.GetCompanyAuditRules` | 不再有預設實作 |
  | `IFormRuleProcessor` | 新增 `ApplyNewRowDefaults`，[建立新列時以預設值運算式為準](#建立新列時以預設值運算式為準)需要它 |
  | 快取中依資料庫而來的型別（`CompanyInfo`、`DepartmentTree`、`ApiKeyInfo` 等） | 改為 init-only 屬性 |
  | session 的公司範圍 | 改為單一不可變的 `SessionCompanyScope`，一次寫入整個替換，讀取端不會看到只改了一半的狀態 |

- **遷移：** 在自己的實作中實作 `TryAcceptAsync`、`GetCompanyAuditRules` 與 `ApplyNewRowDefaults`；以
  `RegisterPayloadCodec` 註冊 codec；快取型別的屬性在物件初始設定式中設定，`SessionCompanyScope` 整個替換而不是修改。
- **背景：** ADR-046 允許可由主機替換的介面增加成員
  （[ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md)）。

  [#12](https://github.com/polhem-dev/polhem/pull/12), [#14](https://github.com/polhem-dev/polhem/pull/14),
  [#22](https://github.com/polhem-dev/polhem/pull/22)

### 可調整的常數改為 static readonly

- **影響對象：** 在常數運算式（例如 attribute 引數或 `case` 標籤）中使用下列成員的程式碼。
- **原本：** 它們在 Bee.NET 中是 `const`。
- **現在：** 改為 `static readonly`：`ApiKeyFormat.MinSysIdLength`、`ApiKeyFormat.MaxSysIdLength`、
  `LoginAttemptTracker.DefaultLockoutMinutes`、`DefaultMaxFailedAttempts`、`DefaultMaxTrackedAccounts`、
  `CurrencySettings.FallbackRounding`、`UnitSettings.FallbackDecimals`、`ApiKeyCache.AbsoluteMinutes`、`NegativeMinutes`、
  `RowEditPanel.CompactWidthThreshold`、`FormView.DefaultCompactWidthThreshold`。協定名稱、識別碼與格式維持 `const`。
- **遷移：** 把使用處移出常數運算式，例如從 `case` 標籤改為 `if`。
- **背景：** `const` 會編譯進每個呼叫端，日後改值也到不了以舊值建置的程式碼。([#26](https://github.com/polhem-dev/polhem/pull/26))

### session 結束，舊格式的密碼雜湊不再通過驗證

- **影響對象：** 所有從 Bee.NET 搬過來的部署：已登入的使用者，以及密碼雜湊仍是舊格式的帳號。
- **原本：** `st_session` 儲存存取權杖，session 種子也包含它；沒有前綴的 PBKDF2-SHA1 格式雜湊能通過驗證。
- **現在：** 不儲存存取權杖。`st_session` 的 `access_token` 欄位存的是權杖經 `AccessTokenHasher.ComputeStorageKey` 算出
  的 SHA-256 衍生鍵值，session 種子也不再包含權杖，因此能讀取該表也拿不到可用的 bearer 權杖。切換前寫入的資料列對不上
  任何權杖，因此既有的 session 全部結束。沿用自 Bee.NET、沒有前綴的 PBKDF2-SHA1 格式不再能通過驗證。
- **遷移：**
  1. 使用者重新登入。刪除 Bee.NET 留在 `st_session` 的資料列：它們存的是 Bee.NET 的權杖，已對不上任何東西。
  2. `st_user.password` 不是以 `v2.` 開頭的帳號，重設密碼。以 `v2.` 開頭的雜湊照常可用，並在下次登入成功時以更多次
     迭代重新雜湊。
- **背景：** [#5](https://github.com/polhem-dev/polhem/pull/5)

### 稽核與記錄表的紀錄改變

- **影響對象：** 對記錄表的查詢與報表、讀取 `AuditEntry.AccessToken` 的程式碼，以及讀取 Bee.NET 寫入之稽核紀錄欄位
  宣告型別的程式碼。
- **原本：** `st_log_access`、`st_log_anomaly_api`、`st_log_change`、`st_log_login` 在 `access_token` 儲存存取權杖。
  `ProgramSettings` 沒有列出的表單，其稽核紀錄寫入呼叫端的 ProgId 寫法。
- **現在：**
  - 這四個記錄表在 `token_fingerprint` 保存簡短的權杖指紋，仍可串起同一個 session 的記錄；`AuditEntry.AccessToken`
    改為 `AuditEntry.TokenFingerprint`。
  - 稽核紀錄寫入 FormSchema 的 ProgId 寫法，因此同一張表單的紀錄在 `st_log_change` 與 `st_log_access` 中共用同一個
    `prog_id`。之前寫入的紀錄維持當時的寫法。
  - Bee.NET 寫入的稽核紀錄，其儲存的 XML 中仍是 `Bee.FieldDbType`（`st_log_change` 的 `changes_xml` 欄位中的
    `msprop:Bee.FieldDbType`）；讀出的值不變，只是不再知道其欄位宣告的型別：`GetDeclaredFieldDbType()` 對它們回傳
    `null`。
- **遷移：**
  1. 結構升級會新增 `token_fingerprint`，但從不刪除欄位，所以舊的 `access_token` 欄位連同 Bee.NET 寫入的權杖都還在。
     請自行清空或刪除該欄位。
  2. 查詢較舊的紀錄時，以不分大小寫的方式比對 `prog_id`。
  3. 改讀 `AuditEntry.TokenFingerprint`，不再讀 `AuditEntry.AccessToken`。
- **背景：** [#5](https://github.com/polhem-dev/polhem/pull/5), [#26](https://github.com/polhem-dev/polhem/pull/26)

### 匿名呼叫與協定錯誤的回應方式改變

- **影響對象：** 檢查 HTTP 401、顯示伺服端例外訊息，或依賴未知 action 與無法讀取之本文錯誤碼的用戶端；覆寫
  `IsAuthorizationRequired` 的伺服端。
- **原本：** 伺服端手動維護一份可以不帶 Bearer 標頭呼叫的方法清單，其他沒帶標頭的請求一律回 HTTP 401。解析不到任何方法
  的 action 名稱與無法讀取的 `Plain` 本文，都以其他錯誤碼出現，`-32601` 與 `-32602` 沒有產生者。BCL 例外的訊息會傳給
  遠端呼叫端。
- **現在：**
  - 沒帶 `Authorization` 標頭的請求就是匿名呼叫，只由 `[ApiAccessControl]` 決定。需要 session 的方法回應 JSON-RPC
    `-32001`（Unauthorized，`AuthenticationRequiredException`），.NET 用戶端把它轉成 `UnauthorizedAccessException`。
    `RemoteApiProvider` 取得存取權杖後才送出該標頭，所以登入前不送；覆寫 `IsAuthorizationRequired` 以拒絕匿名請求的部署，
    也不會被空的佔位權杖繞過。
  - 未知的 action 回應 `-32601`（`MethodNotFound`），無法讀成方法型別的 `Plain` 本文回應 `-32602`（`InvalidParams`），
    各有固定訊息。
  - BCL 例外的訊息只留在伺服端的記錄（`JsonRpcExecutor.Logger`）；呼叫端得到每個錯誤碼固定的訊息。給使用者看的框架訊息
    以 `UserMessageException` 擲出。
- **遷移：** 改為檢查錯誤碼 `-32001`（.NET 中為 `UnauthorizedAccessException`），不再檢查 HTTP 401；要讓使用者看到的
  訊息，在業務物件中以 `UserMessageException` 擲出。
- **背景：** [#6](https://github.com/polhem-dev/polhem/pull/6), [#18](https://github.com/polhem-dev/polhem/pull/18),
  [#22](https://github.com/polhem-dev/polhem/pull/22)

### 伺服端更嚴格地檢查請求

- **影響對象：** 請求會被下列檢查拒絕的呼叫端與業務物件，以及依賴伺服端除錯設定的用戶端。
- **原本：** Bee.NET 接受這些請求。
- **現在：**
  - **寫入的記錄範圍。** 儲存時，主檔範圍以 UPDATE 或 DELETE 實際繫結的資料列檢查；拒絕變更自身 row id 的資料列；
    對照資料庫確認修改與刪除的明細列屬於同一個 payload 中、範圍內的主檔；新增或修改的主檔列儲存後留下的值，也要落在
    呼叫端的新增或修改範圍內。規則說明見[權限與授權](../security/permission-authorization.md)。
    ([#4](https://github.com/polhem-dev/polhem/pull/4))
  - **讀取的記錄範圍。** `GetList` 與 `GetCount` 只接受表單宣告過的過濾與排序欄位，且不接受受保護欄位；`GetLookup`
    套用讀取的記錄範圍。([#4](https://github.com/polhem-dev/polhem/pull/4))
  - **經 API 取用定義。** 遠端 `GetDefine` 只提供明列的定義類型（用戶端呈現畫面所需的那些，列於
    `SystemBusinessObject.GetDefine`）；`SystemSettings`、`DatabaseSettings` 等部署設定只在行程內讀取。
    ([#4](https://github.com/polhem-dev/polhem/pull/4))
  - **Encoded 與 Encrypted 本文**依請求解析出的 action 的參數型別解碼；用戶端宣告的型別名稱只用於一致性檢查。兩種 codec
    解碼時套用同一個深度上限，巢狀的過濾條件也不例外。只有公開、非泛型、單一參數且不是屬性存取子的執行個體方法能被當成
    action 呼叫（`JsonRpcExecutor.IsResolvableAction`），與 `POLHEM3001` 在建置時套用的規則相同。
    ([#6](https://github.com/polhem-dev/polhem/pull/6))
  - **Plain 本文。** 過去 `Plain` 本文直接反序列化成業務物件方法的引數型別，呼叫端因此能設定該型別的任何公開成員，
    包括契約沒有宣告的成員。現在先讀成 action 的請求型別，再複製到引數，與 Encoded 路徑原本的做法相同。
    ([#22](https://github.com/polhem-dev/polhem/pull/22))
  - **Session 與金鑰。** `CreateSession` 只接受本機呼叫。API 金鑰的 `CreateApiKey`、`SetApiKeyEnabled`、
    `SetApiKeyExpiry` 與其他會改變狀態的系統方法一樣受重放防護。資料庫異常記錄只有部署管理員能讀取。
    ([#5](https://github.com/polhem-dev/polhem/pull/5))
  - **DDL。** 非字串欄位的預設值必須是該欄位型別的字面值。([#4](https://github.com/polhem-dev/polhem/pull/4))
  - **集合。** `KeyCollectionBase` payload 中的 nil 元素會被拒絕，不再略過。
    ([#9](https://github.com/polhem-dev/polhem/pull/9), [#14](https://github.com/polhem-dev/polhem/pull/14))
  - **用戶端。** 用戶端拒絕伺服端宣告的 "none" 加密器，除非用戶端自己處於除錯模式；也不再沿用伺服端的除錯旗標與允許的
    型別命名空間。([#6](https://github.com/polhem-dev/polhem/pull/6))
- **遷移：**
  1. 呼叫端用來過濾或排序的欄位，都要在表單中宣告。lookup 不該套用記錄範圍的業務物件，把
     `FormBusinessObject.LookupAppliesRecordScope` 設為 `false`。
  2. 在行程內呼叫 `CreateSession`；重放防護開啟時，呼叫 `CreateApiKey`、`SetApiKeyEnabled`、`SetApiKeyExpiry` 要帶
     frame sequence。
  3. `SystemSettings` 與 `DatabaseSettings` 改在行程內讀取，不經 `GetDefine`。
  4. 非字串欄位的預設值改寫成該欄位型別的字面值。
  5. 必須與使用 "none" 加密器的伺服端溝通的用戶端，以除錯模式執行。
- **背景：** [#4](https://github.com/polhem-dev/polhem/pull/4), [#5](https://github.com/polhem-dev/polhem/pull/5),
  [#6](https://github.com/polhem-dev/polhem/pull/6), [#9](https://github.com/polhem-dev/polhem/pull/9),
  [#14](https://github.com/polhem-dev/polhem/pull/14), [#22](https://github.com/polhem-dev/polhem/pull/22)

### wire 合約改變

- **影響對象：** 不以 Polhem .NET 套件建置的用戶端（例如 TypeScript 用戶端），以及其他自行讀寫 payload 的程式。
- **原本：** wire 是 Bee.NET 的形式。
- **現在：**
  - `CreateSessionRequest.userID` 改為 `userId`，並移除 `oneTime`；`LoginResponse` 新增 `culture`；稽核記錄的回應型別
    改名（`AuditLog…`）。
  - 經 MessagePack 傳輸的 `DataTable` 改寫成一份欄位表加上依位置排列的資料列，不再每列一份名稱／值對照。JSON 與 Plain
    不變。
  - 初始值不是 CLR 預設值的 wire 成員一律寫出，因此不論哪種 codec，缺少的成員都代表 CLR 預設值。Plain 請求依 JSON
    種類繫結 `object` 型別的過濾與參數值，所以 Plain、JSON 與 MessagePack 傳遞相同的值。
- **遷移：** 把自己的用戶端更新為這些形式。TypeScript 用戶端 `polhem-connector-js` 跟著合約變更更新。
- **背景：** [#9](https://github.com/polhem-dev/polhem/pull/9), [#10](https://github.com/polhem-dev/polhem/pull/10),
  [#11](https://github.com/polhem-dev/polhem/pull/11), [#12](https://github.com/polhem-dev/polhem/pull/12),
  [#15](https://github.com/polhem-dev/polhem/pull/15)

### 未分頁的 `GetList` 只回傳一頁

- **影響對象：** 不傳分頁選項、預期取得全部資料列的 `GetList` 呼叫端。
- **原本：** 沒有分頁選項的 `GetList` 回傳全部資料列。
- **現在：** 回傳第一頁，上限為 `PagingOptions.MaxPageSize`。
- **遷移：** 傳入分頁選項，讀取需要的頁面。
- **背景：** [#4](https://github.com/polhem-dev/polhem/pull/4)

### 英文為基底語言

- **影響對象：** 顯示內建文字的應用程式、使用 `CommonConfiguration.DefaultLang` 或 `BackendConfiguration.DefaultLanguage`
  的設定、在登入前讀取 `UserInfo.Culture` 的程式碼、把中文字詞傳給 `ValueUtilities.CBool` 的程式碼，以及傳標籤給
  `PolhemLoginPanel` 或設定 `DynamicGrid.EmptyText` 的程式碼。
- **原本：** 內建文字是中文，預設語言由兩個設定決定，`UserInfo.Culture` 在登入前是 `zh-TW`，`CBool` 能辨識中文的「是」
  「真」。
- **現在：**
  - 內建定義檔、Avalonia 與 Blazor 的 UI 文字、框架訊息都以英文為基底文字，中文移到隨附的 `zh-TW` 資源。標題、列舉、
    選單、規則訊息與框架文字共用同一條回退鏈（`LanguageFallback`）：要求的文化、其上層文化、部署預設，最後是基底文字。
  - 部署預設是 `CommonConfiguration.DefaultLanguage`（預設 `zh-TW`），取代 `CommonConfiguration.DefaultLang` 與
    `BackendConfiguration.DefaultLanguage`，後兩者不再讀取。它是沒有自己 `st_user.culture` 之使用者的文化，也是最後的
    語言回退。
  - 登入回應帶有使用者的文化（`st_user.culture` 或部署預設），用戶端會採用，因此 `UserInfo.Culture` 在登入前是空字串，
    不再是 `zh-TW`。
  - 給終端使用者的框架訊息帶有鍵值與參數（`UserMessageException`），依 session 的文化解析；表單規則訊息解析
    `{ProgId}.Rule.{RuleId}.Message`。數字與日期依使用者的文化顯示與剖析，wire 則維持與文化無關。
  - `ValueUtilities.CBool` 只接受與語言無關的代碼：`1`、`T`、`TRUE`、`Y`、`YES`，不分大小寫。
  - `PolhemLoginPanel` 的標籤參數與 `DynamicGrid.EmptyText` 改為 `string?`；`null` 顯示在地化文字。
- **遷移：**
  1. 把預設語言移到 `CommonConfiguration/DefaultLanguage`。
  2. 不該套用部署預設的使用者，設定其 `st_user.culture`。
  3. 在 `{ProgId}.Rule.{RuleId}.Message` 之下加入表單規則訊息的翻譯。
  4. 使用者以自己語言輸入的值，先在 UI 轉換，再交給 `CBool`。
- **背景：** 中文的「是」「真」讓一種語言在與文化無關的轉換裡享有特例；使用者以自己語言輸入的值，應由 UI 轉換。
  ([#15](https://github.com/polhem-dev/polhem/pull/15))

### 儲存時強制檢查必填欄位

- **影響對象：** FormSchema 把欄位標為 `Required`，而儲存或送出的資料中該欄位是空的應用程式。
- **原本：** `FormField.Required` 只是標題上的提示：伺服端照樣儲存空的必填欄位。
- **現在：** 儲存時，新增或修改的資料列（主檔或明細）有必填欄位是空的，就會被拒絕，訊息以呼叫端語言的標題指出該欄位
  （`PolhemMessages.SaveFieldRequired`、`SaveDetailFieldRequired`）。Avalonia 的 `FormView` 與 Blazor 的 `FormPage` 在
  送出儲存前執行同一條規則 `RequiredFieldCheck`（搭配 `MissingRequiredField`），列出所有空的必填欄位
  （`PolhemUIText.RequiredFieldsEmpty`），並且不送出。空的意思是 `null`、空字串或只有空白的文字、`Guid.Empty`，以及長度
  為零的二進位值；數字、布林值與日期永遠不算空，因為這些欄位一定有值。只檢查會寫入資料庫的欄位，所以關聯或虛擬欄位上的
  `Required` 旗標對儲存沒有作用。
- **遷移：** 升級前請檢視各 FormSchema 的 `Required` 旗標。既有記錄若以空的必填欄位儲存，在補上該欄位之前無法再次儲存，
  因此請補上資料，或取消該旗標。請改標在實際儲存的鍵值欄位，而不是關聯或虛擬欄位。
- **背景：** [#26](https://github.com/polhem-dev/polhem/pull/26), [#27](https://github.com/polhem-dev/polhem/pull/27)

### 建立新列時以預設值運算式為準

- **影響對象：** 欄位有 `DefaultValueExpression` 的表單（尤其同時有字面值 `DefaultValue` 者），以及讀取 `Short`、`Long`、
  `Decimal`、`Binary` 欄位預設值的程式碼。
- **原本：** 依型別的初值（0、空字串、今天、`Guid.Empty`）讓大多數欄位不是空的，所以日期欄位上的 `Today()` 之類的運算式
  從來不會執行。
- **現在：** 建立新列時（伺服端的 `GetNewData` 或 UI 用戶端），欄位的 `DefaultValueExpression` 會寫過字面值
  `DefaultValue` 與依型別的初值。存檔時運算式仍只填空的欄位，使用者輸入的值會保留。`Short`、`Long`、`Decimal`、`Binary`
  欄位的預設值具型別且不為 null。
- **遷移：** 檢查同時有運算式與字面值預設值的欄位；新列現在顯示的是運算式的值。自訂的 `IFormRuleProcessor` 要實作
  `ApplyNewRowDefaults`（見[擴充介面與快取型別改變](#擴充介面與快取型別改變)）。
- **背景：** [#14](https://github.com/polhem-dev/polhem/pull/14), [#22](https://github.com/polhem-dev/polhem/pull/22)

### 畫面預設在地化定義

- **影響對象：** 呈現定義的 Avalonia head 與 Blazor Server 主機。
- **原本：** 除非設定了定義載入器，畫面照原樣呈現定義。
- **現在：** `ClientInfo.UseDefinitionLoader` 預設開啟，Avalonia 畫面不需任何設定，就會顯示使用者語言的標題、租戶客製的
  版面與公司的數值格式。Blazor 的 `FormPage` 也預設透過定義載入器在地化其定義（`PolhemBlazorOptions.UseDefinitionLoader`）：
  circuit 文化的標題、租戶的版面與框架的數值格式；頁面自己的參數仍可逐頁覆寫。
- **遷移：** 把 `ClientInfo.UseDefinitionLoader` 或 `PolhemBlazorOptions.UseDefinitionLoader` 設為 `false`，即可照原樣
  呈現定義，省下載入器額外的往返。
- **背景：** [#22](https://github.com/polhem-dev/polhem/pull/22), [#27](https://github.com/polhem-dev/polhem/pull/27)

### 用戶端把端點存在新的位置

- **影響對象：** 以 Bee.NET 儲存端點與 API 金鑰的桌面與行動端用戶端。
- **原本：** 存在組件旁的 `{ExeName}.Settings.xml`。
- **現在：** 端點與 API 金鑰存成每位使用者本機應用程式資料資料夾下的 `endpoint.txt` 與 `apikey.txt`
  （`FileEndpointStorage`，現在位於 `Polhem.UI.Core` 並作為預設），因為組件旁的資料夾在 iOS 上唯讀、在 WebAssembly
  上會遺失。原本的 `{ExeName}.Settings.xml` 不再讀取。
- **遷移：** 使用者重新輸入端點與 API 金鑰。
- **背景：** [#12](https://github.com/polhem-dev/polhem/pull/12)

### 設定與啟動檢查

- **影響對象：** 元件型別名稱寫錯、缺少 `common` 資料庫項目，或 `ProgramSettings.xml` 仍是巢狀 `<Categories>` 版面的部署。
- **原本：** `CacheProvider` 或元件型別名稱寫錯時，之後才出現 null 參考；缺少 `common` 資料庫項目時，要等到第一個碰到
  框架資料表的請求才失敗；巢狀版面的 `ProgramSettings.xml` 會被拒絕。
- **現在：**
  - `CacheProvider` 或元件型別名稱寫錯時，會在啟動時失敗並指出設定名稱。
    ([#8](https://github.com/polhem-dev/polhem/pull/8), [#11](https://github.com/polhem-dev/polhem/pull/11))
  - 以 `AddPolhemFramework` 建立的 host 會在其他 hosted service 啟動前呼叫 `IDatabaseSettingsProvider.ValidateRequired`，
    因此缺少 `common` 資料庫項目的部署不會啟動。([#22](https://github.com/polhem-dev/polhem/pull/22))
  - 不檢查 `ProgramSettings` 的格式：`ProgramSettings.xml` 與其他定義檔以相同方式讀取。仍是較早 Bee.NET 版本那種帶著
    選單的巢狀 `<Categories>` 版面的檔案，會載入成空的註冊表，於是每個 progId 都退回框架預設的業務物件。
    ([#28](https://github.com/polhem-dev/polhem/pull/28))
- **遷移：**
  1. 修正啟動錯誤指出的元件型別名稱。
  2. 加入 `Id` 為 `common` 的 `DatabaseItem`。

### 產生的版面改用其他編輯器

- **影響對象：** materialize 或產生版面的部署，以及含 `DateTime` 欄位的版面。
- **原本：** 預設的 `AuditRule`、`Department`、`Employee` 版面把每個欄位都顯示成文字框，包括模式代碼、旗標與 row id。
  `DateTime` 欄位使用 `DateEdit`，這個日期選擇器只寫入日期，所以編輯該欄位會丟掉時間。
- **現在：** 隨附的 `AuditRule`、`Department`、`Employee` 版面以 `FormLayoutGenerator` 依其 schema 重新產生：稽核模式用
  下拉選單、敏感旗標用核取方塊、部門與主管用 lookup，也不再顯示系統欄位。`FormLayoutGenerator` 與 `Auto` 控制項類型給
  `DateTime` 欄位新的 `DateTimeEdit`。materialize 預設檔（`Defaults.MaterializeTo`、`dotnet polhem defines materialize`）
  會略過已存在的檔案，因此已有這些版面的部署會保留舊版；已儲存的版面中，`DateTime` 欄位也維持 `DateEdit`。
- **遷移：**
  1. 在帶過自己的修改之後，覆寫這三個版面（見 `dotnet polhem help defines`），或自行修改。
  2. 時間有意義的 `DateTime` 欄位，改為 `DateTimeEdit`。
- **背景：** [#29](https://github.com/polhem-dev/polhem/pull/29), [#33](https://github.com/polhem-dev/polhem/pull/33)
