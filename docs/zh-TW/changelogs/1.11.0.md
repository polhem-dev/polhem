# Polhem 1.11.0 — 發佈說明

[English](../../en/changelogs/1.11.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.11.0]` 條目的詳細內容。

本版尚在開發中。wire 格式與 1.10.0 相同。

## 新功能與變更

### `polhem-blazor-server` 範本

`Polhem.Templates` 新增第二個範本，在 C# Dev Kit 中名為 **Polhem App (Blazor Server)**：

```bash
dotnet new polhem-blazor-server -n Acme.Erp --database SqlServer
```

它建立一個 ASP.NET Core 網站 `src/<Name>.Web`，以 `AddPolhemBackend` 在自身行程內執行後端，並提供 Blazor Server 外殼：
登入、伺服器的選單，以及顯示所有表單的單一頁面。定義檔資料夾、活頁簿資料夾、工具與資料庫工作都與 `polhem-avalonia` 共用，
選項同樣是 `--database`、`--company`、`--db-password` 與 `--default-language`。頁面對後端的呼叫是受信任的本機呼叫；
產生出來的 `Program.cs` 與 `README.md` 說明了你自己的頁面不得傳入哪些內容。

### `AddPolhemBackend`：一次呼叫啟動後端

`Polhem.Hosting` 新增 `AddPolhemBackend`，是 `IHostApplicationBuilder`（Web 應用程式、Worker Service、generic host）的擴充方法。
它依序完成以往每個後端宿主在 `AddPolhemFramework` 之前要做的呼叫：從建置輸出往上找到 `Define` 資料夾、補上資料夾還沒有的框架預設定義、
讀取 `SystemSettings.xml`、初始化 `SysInfo`，再呼叫 `AddPolhemPayload` 與 `AddPolhemFramework`。它回傳所註冊的 `PathOptions`。

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddPolhemBackend(options => options.AutoCreateMasterKey = true);
builder.Services.AddJsonRpcServer();
```

`PolhemBackendOptions` 可以指定定義檔資料夾（`DefinePath`）與客製層根目錄（`CustomizePath`）、關閉或篩選預設定義的補齊
（`MaterializeDefaults`、`MaterializeOptions`），並讓開發用宿主自動建立 master key（`AutoCreateMasterKey`）。資料庫 provider
仍由宿主自行註冊。自行完成這些呼叫的既有宿主不受影響；`polhem-avalonia` 範本的伺服器改用 `AddPolhemBackend`。

### 範本字串的繁體中文翻譯

各範本的名稱、說明與選項翻譯成繁體中文（`zh-Hant`）。`dotnet new` 的語言是繁體中文時
（`DOTNET_CLI_UI_LANGUAGE=zh-TW` 或 `zh-Hant`）會顯示中文；VS Code 中 C# Dev Kit 的 New Project 清單在作業系統語言是繁體中文時顯示中文，
zh-TW 與 zh-HK 都會退回使用 zh-Hant。其他語言顯示英文。安裝或更新範本套件後，請重新載入 VS Code 視窗。

### Blazor Server 的現成外殼

`Polhem.Web.Blazor.Server` 新增 `Polhem.Web.Blazor.Server.Shell`，幾行就能組成網站的前端，就像 `Polhem.UI.Avalonia.Shell`
之於 Avalonia 各前端。路由器的預設版面 `PolhemShellLayout` 在 circuit 的使用者進入公司之前顯示登入畫面（公司、帳號、密碼），
之後顯示頂端列（標題、使用者與公司、登出）、伺服器的選單與路由到的頁面。螢幕寬度小於 600 CSS 像素時，選單改為從側邊滑出蓋在頁面上。
登入畫面經由新的 `GET /culture` 端點在英文與繁體中文之間切換，這個端點只轉址到本站的路徑。

網站以 `AddPolhemShell` 註冊（標題、登入提示、預設的公司、帳號與密碼、提供的語言與預設 culture、表單路由），在 pipeline 加上
`UsePolhemShellLocalization` 與 `MapPolhemShellCulture`，把 `PolhemShellLayout` 設為預設版面，並保留一個放 `PolhemShellHome`
的根頁面與一個放 `FormPage` 的表單頁。完整設定見套件的 README。Northwind 的 Blazor 前端已改用它。

`PolhemShellHome` 會開啟選單的第一個表單。選單裡還沒有表單時（例如新應用程式加入第一個表單之前），根頁面與選單都會說明選單中還沒有表單；
選單無法載入時，由選單顯示錯誤，根頁面保持空白。

`PolhemLoginPanel` 新增 `InitialUserId` 與 `InitialPassword`，用來填入輸入框一次。

### Blazor 元件的預設樣式表

套件附帶 `_content/Polhem.Web.Blazor.Server/polhem.css`，是元件與外殼的預設外觀。它是選用的：到目前為止每個網站都自行為
`polhem-*` class 設定樣式，繼續這麼做的網站不受影響。它的顏色都是自訂屬性（`--polhem-accent`、`--polhem-surface` 等），
因此連結在它之後的網站樣式表只要重新定義這些屬性就能改變外觀。

### 預設的 Department 與 Employee 表單會顯示清單

框架預設的 `Department` 與 `Employee` 表單 schema（由 `Defaults.MaterializeTo` 與 `AddPolhemBackend` 寫進新應用程式的 `Define`
資料夾）原本的 `ListFields` 是空的，清單因此沒有任何欄位：存下的資料可以用 View 或 Edit 開啟，卻在清單上看不到。現在兩者會列出
`sys_id`、`sys_name` 與關聯的名稱（Department 為 `ref_manager_name`，Employee 為 `ref_dept_name`）。

`Department` 也宣告了 `LookupFields="sys_id,sys_name,ref_manager_id,ref_manager_name"`。Employee 的部門查詢會把部門主管帶進直屬主管欄位，
少了這個宣告時查詢只回傳 `sys_id` 與 `sys_name`，選取部門就會失敗並顯示「Lookup source field 'ref_manager_id' is not in the lookup
result」。`Employee` 宣告 `LookupFields="sys_id,sys_name"`，與它原本退回使用的欄位相同。

補上預設定義時會略過已存在的檔案，因此 `Define` 資料夾由較早版本建立的應用程式仍保留舊的 schema。請手動在它的
`FormSchema/Department.FormSchema.xml` 與 `FormSchema/Employee.FormSchema.xml` 設定這兩個屬性，或刪除這兩個檔案後重新啟動宿主，
讓它重新寫入（僅限你沒有修改過這兩個檔案時）。

### 表單版面的合併欄位會生效

`LayoutField.Clone` 沒有複製 `RowSpan` 與 `ColumnSpan`。每個前端渲染的都是版面的複本（表單載入器在套用在地化標題之前會先複製版面，
Avalonia 的 `FormView` 也會複製宿主設定的版面），所以設定為跨多列或多欄的欄位，在 Blazor Server 與 Avalonia 的表單裡都只佔一格。
複本現在會保留這兩個屬性；新的測試 `CloneCompletenessGateTests` 會在定義型別的 `Clone` 漏掉定義檔可設定的成員時失敗。

Avalonia 的 `FormLayoutPresenter`（DefineEditor 的預覽也用它）原本在跨多列欄位之後只往下一列擺放下一個欄位，因此會與跨列欄位佔用的列重疊。
現在依 CSS grid 自動排列的方式擺放欄位，與 Blazor Server 的 presenter 一致：每個欄位放在第一個格子都沒被佔用的位置。
超過版面欄數的 `ColumnSpan` 會限制在欄數以內，與 Blazor Server 相同。

### DefineEditor 在瀏覽器預覽版面

DefineEditor 的 FormLayout 編輯器新增**在瀏覽器預覽**（編輯器上方的地球按鈕），在預設網頁瀏覽器開啟這份版面，由 `Polhem.Web.Blazor.Server`
的 Blazor Server 元件繪製，與 `polhem-blazor-server` 範本建立的應用程式呈現方式相同。頁面會跟著編輯器：尚未存檔的修改、檢視模式、
手機寬度與欄位名稱都會隨變更同步，網址也可以貼到其他瀏覽器比對。與編輯器自己的預覽一樣，它不帶資料渲染版面：查詢與下拉清單都是空的。

頁面由編輯器自己的行程在 127.0.0.1 提供，網址帶隨機 token，不需要後端。因此編輯器需要 ASP.NET Core runtime：
`polhem-define` dotnet tool 透過 .NET SDK 已經具備；以 `publish.sh` 建置的 framework-dependent 版本，目標機除了 .NET 10 runtime，
現在也需要 ASP.NET Core 10 runtime。
