# Polhem 1.12.1 — 發佈說明

[English](../../en/changelogs/1.12.1.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.12.1]` 條目的詳細內容。

本版修正以 1.12.0 的 Blazor 套件建置與錄影時發現的問題：三層深的關聯鏈、關聯欄位在清單與版面中的細節、未指定格式的數字與可編輯
日期的顯示方式，以及 MudBlazor 與 Fluent UI 套件的表格與編輯器行為。DefineEditor 新增編輯器內的 Web 預覽。
本版沒有破壞性變更，wire 格式與 1.12.0 相同。

## 新功能與變更

### DefineEditor：編輯器內的 Web 預覽

FormLayout 編輯器的預覽多了 **Web** 選項。它顯示與**在瀏覽器預覽**相同的 Blazor 頁面（由 MudBlazor 元件繪製），
但顯示在預覽區內而不是瀏覽器視窗，並跟著尚未存檔的修改與檢視模式、手機寬度、欄位名稱三個選項同步。每份開啟的版面各自記住
選擇；新開的版面從 Avalonia 預覽開始。

版面配置按鈕旁的**專注 Web 預覽**按鈕一次就把視窗整理成這種工作方式：只留樹狀結構與 Web 預覽，隱藏側欄，屬性改在
**屬性設定…**對話框中編輯。再按一次即恢復原本的版面配置、預覽與側欄。

頁面由作業系統的網頁引擎繪製：Windows 為 WebView2、macOS 為 WKWebView、Linux 為 WPE WebKit 或 WebKitGTK。
日期與時間輸入框的外觀依該引擎而定，因此要最終確認瀏覽器中的呈現，仍請使用**在瀏覽器預覽**，該功能不變。

引擎必須已安裝：Windows 需要 WebView2 Runtime（Windows 11 內建，部分 Windows 10 需另行安裝），Linux 需要
WebKitGTK 4.1（Debian、Ubuntu 的 `libwebkit2gtk-4.1-0`）。缺少時預覽區會說明原因並提供改用瀏覽器的按鈕，編輯器其他功能
不受影響。網頁檢視不會在使用者設定檔留下資料。

### DefineEditor：版面與預覽選項改為圖示切換鈕

FormLayout 編輯器中決定右側顯示內容的按鈕，以及預覽的檢視模式、手機寬度、欄位名稱選項，改為 VS Code 風格的圖示切換鈕，
名稱顯示在工具提示中。

### Blazor 套件：表格編輯

- **Enter 提交儲存格。** MudBlazor 與 Fluent UI 表格的儲存格編輯器按 Enter 原本沒有反應，而 Avalonia 表格會提交。現在 Enter
  會離開輸入框（寫入值）、關閉編輯器並把焦點留在儲存格，與不寫入的 Escape 相同。多行輸入框的 Enter 仍是換行，下拉選單的
  Enter 仍用於清單。
- **儲存格開啟時的點擊不再遺失。** 儲存格開啟時，焦點會先落回頁面，直到聚焦編輯器的腳本抵達；這段時間點到別處的點擊會被吞掉，
  編輯器留著輸入的文字，值卻沒有寫入。現在點擊會等編輯器就緒後再重放。

### Blazor 套件：欄位的外觀

- **可編輯的日期依使用者文化顯示。** 日期在可編輯時顯示為 `yyyy-MM-dd`，唯讀時才依使用者文化顯示。日期與年月選擇器、日期時間
  編輯器的日期部分現在也依文化的格式顯示；寫回的值仍是不變文化的格式。
- **唯讀編輯器只保留底線**，與 Avalonia 控制項一致，唯讀檢視的記錄不再看起來可以編輯。MudBlazor 中底線與同一列可編輯編輯器的
  底邊對齊。
- **同時引用 Fluent UI 的宿主中，MudBlazor 頁面可以捲動。** Fluent UI 的預設樣式表會讓這類宿主中每個 Blazor 應用程式的 body
  不能捲動；讓外殼頁面捲動的規則現在放在兩個 UI 套件都會匯入的共用樣式表。
- **Fluent UI：** 挑選與表格命令改以圖示按鈕繪製，與 MudBlazor 套件一致；數字編輯器靠右對齊；資料列放得下時表格不再出現垂直
  捲軸；版面未指定寬度的欄位會分配表格剩餘的寬度，而不是固定 120px。

### Avalonia

- 表格的文字儲存格垂直置中，與旁邊的下拉、日期、核取方塊儲存格一致；數字欄的文字與儲存格編輯器靠右對齊，與 Blazor 表格一致。
- `ButtonEdit` 的挑選按鈕以 Search 文字命名；`DateEdit`（以及 `YearMonthEdit`）在應用程式未指定時，以繫結欄位的標題作為
  無障礙名稱，輔助技術不再讀出型別名稱。

### 範本：Avalonia 瀏覽器前端的輸入法

`polhem-avalonia` 範本的瀏覽器前端可以使用嘸蝦米等輸入法。Avalonia.Browser 會把組字過程中的每個按鍵當成文字輸入，並忽略
選定的字；由 `main.js` 載入的 `wwwroot/ime-input-bridge.js` 會攔下這些按鍵並轉送選定的字。既有專案請從新產生的專案複製這兩個檔案。

### 三層深的關聯鏈

關聯欄位可以來自相關表單自己的關聯欄位，而那個欄位又可能來自另一個關聯。三層深的關聯鏈（例如訂單的員工、該員工的部門、部門的
主管）在查詢讀取時會失敗：存檔成功，但重新讀取或列出表單時以「Field mapping for '…' is null.」中止。現在不論多深，這類欄位
都以最外層表單的欄位名稱讀出，與[以 FormSchema 驅動的資料存取](../definitions/formschema-data-access.md)的說明一致。

### 同步表單時以名稱列出外鍵

**Sync TableSchema and FormLayout** 把新欄位加入表單的 `ListFields` 時，外鍵改以其最後一個顯示欄位列出（有對應 `sys_name`
時就是關聯名稱），因為清單無法顯示外鍵存的資料列識別碼。沒有顯示欄位的外鍵不列入。其他欄位照舊。

### 產生的版面中關聯欄位為唯讀

`FormLayoutGenerator` 會把每個關聯欄位（`Type="RelationField"`）設為唯讀，主檔區段與明細表格皆同。它的值由挑選或查詢的
JOIN 填入，沒有任何資料表儲存，所以修改會在下次讀取時遺失。先前產生的版面維持原樣；請手動為這類欄位設定 `ReadOnly`，或重新產生。

### 未指定格式的數字去掉小數尾端的 0

資料庫讀回的 decimal 帶著欄位的小數位數，所以沒有指定數字格式的欄位，讀回的值顯示 `0.0000`，輸入或預設的相同值卻顯示 `0`，
編輯畫面與表格皆是如此。現在這類值以使用者文化的最短精確形式顯示（`0`、`18.5`）。有數字格式、數字種類或顯示格式的欄位不變。

### 來源為關聯欄位的 LookupOnly 列維持關聯欄位

DefineEditor 關聯對話框中的列切換為 **Lookup only** 時，新的目的欄位以往不論來源為何都會變成儲存欄位。現在改為依來源而定：
相關表單的資料表欄位照舊複製到儲存欄位；相關表單的關聯欄位則維持關聯欄位，由表單透過自己的關聯填入（見
[以 FormSchema 驅動的資料存取](../definitions/formschema-data-access.md) §3.4 的員工與部門範例）。

## 破壞性變更

無。
