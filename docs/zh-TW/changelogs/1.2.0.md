# Polhem 1.2.0 — 發佈說明

[English](../../en/changelogs/1.2.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.2.0]` 條目的詳細內容。JSON-RPC 改建在
[`Polhem.JsonRpc`](https://github.com/polhem-dev/polhem-jsonrpc) 套件上，payload 外殼、加密與重放 frame 改建在它的選用
payload 套件上。移除 `Polhem.Api.AspNetCore` 與 `ApiServiceOptions`，這會讓 host 編譯失敗，卻在次版號發佈：繼 1.1.0
之後，1.x 內第二次違反語意化版本的例外。線路上，參數與結果外殼的位元組與 1.1.0 相同，wire fixtures 沒有變動；但內部錯誤碼
與回應的 `method` 成員改為符合 JSON-RPC 2.0，因此非 .NET 的用戶端要與伺服器一起升級：
[polhem-connector-js](https://github.com/polhem-dev/polhem-connector-js) 用戶端需要以 1.2.0 為目標的版本。決策、考慮過的
替代方案與完整的遷移步驟記錄在 [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)（英文）。

各類應用程式要處理的項目：

- **以 HTTP 提供 API 的 host：** [移除 `Polhem.Api.AspNetCore` 套件](#移除-polhemapiaspnetcore-套件)與
  [被拒的憑證改以 JSON-RPC 錯誤回應](#被拒的憑證改以-json-rpc-錯誤回應)。
- **所有 host：** [移除 `ApiServiceOptions` 與 payload 型別](#移除-apiserviceoptions-與-payload-型別)、
  [log category 改為寫出 log 的型別](#log-category-改為寫出-log-的型別)；同一行程也呼叫 API 的 host 另見
  [in-process 呼叫會序列化參數](#in-process-呼叫會序列化參數)。
- **.NET 用戶端：** [移除 `IJsonRpcProvider` 與 JSON-RPC 訊息型別](#移除-ijsonrpcprovider-與-json-rpc-訊息型別)、
  [移除 `ApiServiceOptions` 與 payload 型別](#移除-apiserviceoptions-與-payload-型別)中用戶端的部分，以及
  [被拒的憑證改以 JSON-RPC 錯誤回應](#被拒的憑證改以-json-rpc-錯誤回應)。
- **非 .NET 用戶端：** [錯誤回應改為符合 JSON-RPC 2.0](#錯誤回應改為符合-json-rpc-20)。

## 新功能與變更

### JSON-RPC 改建在 `Polhem.JsonRpc` 套件上

到 1.1.0 為止，Polhem 自帶一份 JSON-RPC 2.0 實作：`Polhem.Api.Core` 的 executor 與它的訊息型別、`Polhem.Api.AspNetCore`
的 controller，以及 `Polhem.Api.Client` 的兩個用戶端 provider。這些都不是 Polhem 特有的。Polhem 特有的部分疊在它上面：
API key 與 access token 檢查、方法層級的存取控制、錯誤合約、異常紀錄，以及 payload 外殼背後的 session 金鑰與線路型別。

協定這一半現在是獨立維護的套件，它們對 Polhem 一無所知，不用 Polhem 也能使用。Polhem 透過它們的擴充點掛上自己的行為，
集中在 `Polhem.Api.Core.Dispatch`。payload 外殼、加密與重放 frame 也基於同樣的理由跟著移出：它們本身就是一套協定，
polhem-connector-js 也在使用，因此現在放在 `Polhem.JsonRpc.Payload` 與 `Polhem.JsonRpc.Payload.Server`。

ADR-049 也列出了**框架管線型別**：只為了讓 `Polhem.*` 套件彼此協作而公開的型別，例如 `Polhem.Api.Core.Dispatch` 裡的
所有型別。它們的變更不算破壞性變更，因此應用程式不應建立在它們之上。

### `AddPolhemApiKeyGateCheck()`

`Polhem.Hosting` 的 `AddPolhemApiKeyGateCheck()`：尚未發行 API key 時於啟動時記錄 log，供以 HTTP 提供 API 的 host 使用。
它接手 `UsePolhemFramework()` 原本執行的啟動檢查；需要自行加入，因為 in-process 的 host 沒有需要 API key 保護的 HTTP 端點。
([#46](https://github.com/polhem-dev/polhem/pull/46))

### 以框架的方式組出 payload 選項

`Polhem.Hosting` 的 `AddPolhemPayload()` 在伺服器上註冊 payload 選項，`Polhem.Api.Client` 的
`ApiClientInfo.PayloadOptions` 在 .NET 用戶端上保存它，`Polhem.Api.Core` 的 `PolhemPayload` 以框架的方式組出這些選項。
([#47](https://github.com/polhem-dev/polhem/pull/47))

### 範例

`QuickStart.Server`、Northwind 伺服器與負載測試 host 以 `MapJsonRpc("/api")` 提供 API，並以 `AddPolhemPayload()` 註冊
payload 選項，可以當作下方升級方式的實際範例。
([#46](https://github.com/polhem-dev/polhem/pull/46)、[#47](https://github.com/polhem-dev/polhem/pull/47))

## 破壞性變更

### 移除 `Polhem.Api.AspNetCore` 套件

- **影響對象：** 以 HTTP 提供 API 的 host。
- **原本：** host 參考 `Polhem.Api.AspNetCore`，從 `ApiServiceController` 衍生 controller，並呼叫 `UsePolhemFramework()`。
- **現在：** 移除該套件，連同 `ApiServiceController` 與 `UsePolhemFramework()`。host 改用 `Polhem.JsonRpc.AspNetCore`
  提供 API：`AddJsonRpcServer()` 與 `MapJsonRpc("/api")`。`UsePolhemFramework()` 原本執行的啟動檢查移到
  `AddPolhemApiKeyGateCheck()`。([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：**
  1. 替換套件參考：

     ```diff
     - <PackageReference Include="Polhem.Api.AspNetCore" Version="1.1.0" />
     + <PackageReference Include="Polhem.JsonRpc.AspNetCore" Version="1.0.0" />
     ```

  2. 替換 controller 的設定：

     ```diff
       builder.Services.AddPolhemFramework(configuration, paths);
     - builder.Services.AddControllers();
     + builder.Services.AddJsonRpcServer();
     + builder.Services.AddPolhemApiKeyGateCheck();
       var app = builder.Build();
     - app.UsePolhemFramework();
     - app.MapControllers();
     + app.MapJsonRpc("/api");
     ```

  3. 刪除衍生自 `ApiServiceController` 的 controller。覆寫過其成員的檢查改寫成 filter，以
     `AddJsonRpcServer(options => options.Filters.Add(...))` 加入。
- **背景：** 協定移出後，`ApiServiceController` 除了呼叫端點之外已無事可做。保留它就會有兩種提供 API 的方式，之後每次修改
  都得讓兩邊同步。見 [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)（英文）。

### 移除 `ApiServiceOptions` 與 payload 型別

- **影響對象：** 所有 host；有設定 payload 選項或捕捉 `ReplayRejectedException` 的 .NET 用戶端；有自訂
  `IApiAuthorizationValidator` 的伺服器；使用 payload codec、壓縮器、加密器或重放紀錄型別的程式碼。
- **原本：** 由 `ApiServiceOptions` 設定 payload，`Polhem.Api.Core` 持有 payload 型別：transformer、serializer、壓縮器與
  加密器的介面及實作、`ApiPayloadOptionsFactory`、外殼型別（`ApiPayload`、`JsonRpcParams`、`JsonRpcResult`、
  `ApiPayloadConverter`）、`ApiPayloadFrame`、`IReplayWindowStore`、`MemoryReplayWindowStore` 與 `ReplayRejectedException`。
- **現在：** 這些都已移除。替代品在 `Polhem.JsonRpc.Payload`：codec、重放紀錄與 frame 設定移到套件的 `PayloadOptions`。
  伺服器以 `AddPolhemPayload()` 註冊 payload 選項，.NET 用戶端把它放在 `ApiClientInfo.PayloadOptions`。
  ([#47](https://github.com/polhem-dev/polhem/pull/47))
- **遷移：**
  1. 每個 host 都要替換 `ApiServiceOptions` 的呼叫：

     ```diff
     - ApiServiceOptions.Initialize(settings.CommonConfiguration.ApiPayloadOptions, settings.CommonConfiguration.IsDebugMode);
     - ApiServiceOptions.RequireWireFrame = true;
     + builder.Services.AddPolhemPayload(settings.CommonConfiguration.ApiPayloadOptions, settings.CommonConfiguration.IsDebugMode,
     +     options => options.RequireFrame = true);
     ```

  2. .NET 用戶端把 `ApiClientInfo.PayloadOptions.RequireFrame` 設成與伺服器一致。
  3. 更新移動過的成員：

     | 原本 | 現在 |
     |------|------|
     | `ApiServiceOptions.AuthorizationValidator` | 從 service collection 取得的 `IApiAuthorizationValidator`；要替換預設值就註冊自己的實作 |
     | `MessagePackPayloadSerializer` | `MessagePackPayloadCodec`，實作套件的 `IPayloadCodec` |
     | `ReplayRejectedException`（`Polhem.Api.Core`） | `Polhem.JsonRpc.Payload.ReplayRejectedException`，用戶端捕捉重放呼叫的例外 |
     | 其餘 payload、外殼、frame 與重放型別 | `Polhem.JsonRpc.Payload` 及其 `PayloadOptions` |

  4. 其餘遷移步驟，包括多數 host 用不到的（自訂 codec、共用的重放紀錄、同一行程也呼叫 API 的 host），見
     [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)（英文）的決策 3 與決策 5。
- **背景：** `ApiServiceOptions` 成了第二套設定介面，必須和 payload 套件的選項保持一致。保留它就會有兩種設定 payload 的
  方式，之後每次修改都得讓兩邊同步。[ADR-048](../../../maintainers/adr/adr-048-rename-base-to-core-in-1-1.md)（英文）說
  1.1.0 的改名是 1.x 內唯一一次違反語意化版本的例外；[ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)
  （英文）是第二次，並規定 1.x 內往後的破壞性變更都需要自己的 ADR。

### 移除 `IJsonRpcProvider` 與 JSON-RPC 訊息型別

- **影響對象：** 使用 `ApiConnector.Provider` 或實作 `IJsonRpcProvider` 的 .NET 用戶端程式碼，以及使用 `JsonRpcExecutor`
  或 `Polhem.Api.Core.JsonRpc` 訊息型別的程式碼。
- **原本：** `RemoteApiProvider` 與 `LocalApiProvider` 實作 `IJsonRpcProvider`；`Polhem.Api.Core.JsonRpc` 持有
  `JsonRpcExecutor`，以及訊息型別 `JsonRpcRequest`、`JsonRpcResponse`、`JsonRpcError`。
- **現在：** 移除 `IJsonRpcProvider`、`JsonRpcExecutor` 與這些訊息型別。`RemoteApiProvider` 與 `LocalApiProvider` 改實作
  套件的 `IJsonRpcTransport`，`ApiConnector.Provider` 也改為該型別。([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：** 以 `IJsonRpcTransport` 取代 `IJsonRpcProvider`，以 `Polhem.JsonRpc` 套件的型別取代被移除的 executor 與訊息型別。
- **背景：** [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)（英文）

### 錯誤回應改為符合 JSON-RPC 2.0

- **影響對象：** 比對 -32000、讀取回應的 `method` 成員，或處理格式錯誤／不存在之方法名稱的用戶端；讀取
  `JsonRpcErrorCode.InternalError` 的程式碼。
- **原本：** 內部錯誤回 -32000，回應以 `method` 成員回傳方法名稱。格式錯誤的方法名稱回 `UserMessage`。
- **現在：** 參數與結果外殼的位元組與 1.1.0 相同。原本屬於 Polhem 自己的兩處改為符合 JSON-RPC 2.0：內部錯誤改回規格為它
  定義的錯誤碼 -32603，`JsonRpcErrorCode.InternalError` 也改為此值；回應不再帶 `method` 成員。格式錯誤的方法名稱依規格回
  `MethodNotFound`（-32601）。不存在的 action 由 dispatcher 直接以固定訊息回應，debug 模式也一樣，且不寫異常紀錄。
  ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：** 比對 -32000 或讀取 `method` 的用戶端要和伺服器一起升級；polhem-connector-js 對應的是以 1.2.0 為目標的版本。
- **背景：** [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md)（英文）

### 被拒的憑證改以 JSON-RPC 錯誤回應

- **影響對象：** 處理 HTTP 401 的用戶端，以及在 API key 或 access token 被拒時捕捉 `HttpRequestException` 的 .NET 程式碼。
- **原本：** API key 或 `Authorization` header 被拒時回 HTTP 401。
- **現在：** 回 HTTP 200 與 JSON-RPC 錯誤。檢查在建立 business object 之前、於 JSON-RPC 管線內執行，所以它的失敗和其他
  失敗一樣回報，.NET 用戶端丟出的是錯誤合約重建的例外，而不是 `HttpRequestException`。
  ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：** 把被拒當成 JSON-RPC 錯誤處理：在 .NET 中改為捕捉錯誤合約的例外。

### in-process 呼叫會序列化參數

- **影響對象：** 在同一行程呼叫 API，且依賴伺服器收到呼叫端物件的 host。
- **原本：** in-process 呼叫把參數物件原樣交給伺服器。
- **現在：** in-process 呼叫與遠端呼叫一樣會序列化參數，所以伺服器永遠不會持有呼叫端的物件。`Plain` 本文裡的篩選值會以
  文字送達，和過去經由 HTTP 時一樣。([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：** 伺服器端對 in-process 與遠端呼叫的參數一視同仁。

### 拒絕未知格式的 payload 外殼

- **影響對象：** 送出 `format` 不是 0、1 或 2 之 payload 外殼的用戶端。
- **原本：** 這樣的外殼會先被接受，到後面才失敗。
- **現在：** 以無效參數拒絕。([#47](https://github.com/polhem-dev/polhem/pull/47))
- **遷移：** `format` 送 0、1 或 2。

### log category 改為寫出 log 的型別

- **影響對象：** 依舊 category 設定的 log 組態。
- **原本：** 被遮蔽的失敗與 API key 啟動檢查記在其他 category。
- **現在：** 被遮蔽的失敗記在 `Polhem.Api.Core.Dispatch.PolhemExceptionMapper`，API key 啟動檢查記在
  `Polhem.Hosting.ApiKeys.ApiKeyGateWarningService`。([#46](https://github.com/polhem-dev/polhem/pull/46))
- **遷移：** 依舊 category 過濾的 log 設定改用新名稱。
