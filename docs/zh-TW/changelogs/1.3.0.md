# Polhem 1.3.0 — 詳細發佈說明

[English](../../en/changelogs/1.3.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.3.0]` 條目的詳細版。變更記錄每項變更只列一行；原因與背景
留在這裡，變更記錄省略的 repository 維護方式變更也列在這裡。

> Polhem 改建在 [Polhem.JsonRpc](https://github.com/polhem-dev/polhem-jsonrpc) 1.1（1.1.1 以上）上，它的 payload 線路格式與
> Polhem 1.2.0 的不相容。**伺服端與所有遠端用戶端必須一起升級。** 這個變更修補了 1.2.0 的一個弱點，見「為什麼線路格式改變」。 決策與考慮過的替代方案記錄在
> [ADR-050](../../../maintainers/adr/adr-050-jsonrpc-1-1-wire-break-in-1-3.md)（英文）。

## 為什麼線路格式改變

**這是安全性修正。** 到 1.2.0 為止，Encrypted payload 的 HMAC 只涵蓋它的位元組本身。因此攔截到加密請求的人可以把它送給
同一個 session 的另一個方法（例如把讀取變成刪除），也可以把結果當成請求送回去：接收端無從分辨，因為位元組是真的。
Polhem.JsonRpc 1.1.0 把這兩條路都封住。HMAC 現在也涵蓋 payload 的方向與呼叫的 JSON-RPC method，所以 payload 只能以它被寫出
時的方法與方向開啟。同一方法的結果之間仍可互換，錯誤回應不受驗證，原封不動地重放呼叫則要靠 frame 處理。綁定的計算方式與
它不涵蓋的部分記錄在
[Polhem.JsonRpc 的 ADR-003](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/maintainers/adr/adr-003-bind-method-into-payload-hmac.md)（英文）。

同一版也讓結果以請求的格式回應（`null` 結果也一樣），並讓讀取端拒絕其他格式的結果。否則結果可能在途中被換成 plain 的，
而 plain 完全沒有 HMAC。

兩者都沒有相容模式。同時接受有綁定與沒有綁定兩種形式的伺服端，也會接受攻擊者送來的沒有綁定的那一種，而那正是綁定要
封住的。

## 為什麼是次版號

語意化版本要求 2.0.0。Polhem 自己的公開 .NET API 在本版只新增了 `DefinitionNotFoundException`，`PublicAPI.Shipped.txt`
基準中沒有任何移除或修改，所以只參考 Polhem 套件的應用程式以 1.3.0 編譯的情形與 1.2.0 相同。破壞在線路上，而版號改變不了
誰能和誰通訊：1.2.0 的用戶端無法呼叫 1.3.0 的伺服端，不論伺服端的版號叫什麼；polhem-connector-js 無論如何都要重新建置。
次版號確實有一個代價：浮動參考（例如 `1.*`），或會自動合併次版更新的工具，可能在沒有人決定的情況下把伺服端升到 1.3.0，
它的遠端用戶端隨即失敗。因此本說明與變更記錄條目都以這個警示開頭。這是 1.x 內語意化版本的第三次例外，繼 1.1.0 與 1.2.0
之後，與它們一樣有自己的 ADR。

1.3.0 發佈後，維護者會在 nuget.org 把 Polhem 1.2.0 套件標為 deprecated。Polhem 1.2.0 接受任何更新的 Polhem.JsonRpc，而
Polhem.JsonRpc 1.1 遇到以 1.0 編譯的程式碼會拒絕啟動，所以在 1.2.0 上更新間接相依套件的應用程式，會得到一個無法啟動的伺服端。

## 如何升級

**伺服端與所有遠端用戶端在同一個時段一起升級。** 版本不相符的一組（不論哪一端較舊），每個 Encrypted 呼叫都會失敗，
伺服端一律回 `-32603 Internal error`。Plain 與 Encoded 呼叫沒有 HMAC，所以版本不相符的一組在第一個 Encrypted 呼叫之前
可能看起來正常。

- **伺服端**：把 Polhem 套件升到 1.3.0，應用程式直接參考的每個 `Polhem.JsonRpc.*` 套件升到 1.1.1 以上。以 HTTP 提供 API
  的 host 自己參考 `Polhem.JsonRpc.AspNetCore`；它的 1.0 版是以 `Polhem.JsonRpc.Server` 1.0 編譯的，1.1 的 dispatcher
  在這類組件旁邊會拒絕啟動，並指出是哪個組件。停在 1.0.0 的直接參考（例如為了自訂 replay store 而參考的
  `Polhem.JsonRpc.Payload.Server`）也會讓 restore 以 NU1605 失敗，因為 Polhem 套件需要 1.1.1。
- **`JsonRpcServerOptions.AllowCodeCompiledAgainst10` 無法跳過這個啟動錯誤。** 從 1.1.1 起它沒有作用：以 1.0 編譯、
  讀取或設定傳輸種類的程式碼，可能把 HTTP 呼叫當成行程內呼叫，而 Polhem 對行程內呼叫不做存取檢查，所以所有以 1.0
  編譯的東西都要升級或重新編譯。
- **以 `Polhem.Api.Client` 建構的 .NET 用戶端**：把套件升到 1.3.0。`ApiConnector` 會綁定它的呼叫，並以它送出的格式讀取
  結果；呼叫端的程式碼不需修改。
- **瀏覽器與其他 JavaScript 用戶端**：從 polhem-connector-js `main` 上合併
  [polhem-dev/polhem-connector-js#11](https://github.com/polhem-dev/polhem-connector-js/pull/11) 的 commit 或之後重新建置並
  重新安裝。它沒有發佈到 npm，套件版號也不會改變，所以要以 commit 分辨新舊建置。
- **以其他語言實作 payload 的用戶端**：實作 Polhem.JsonRpc 的 ADR-003。該 repo 的跨語言測試向量是依據。
- **如果你開啟 `RequireFrame`**：框架自己的 `Save`、`Delete`、`ExecFunc`、`EnterCompany` 與 `LeaveCompany` 宣告了
  `ReplayProtection = UniqueSequence`，現在只接受 Encrypted 的遠端呼叫。.NET 瀏覽器 head（WebAssembly）登入時沒有
  session 金鑰，它對這些方法的呼叫會降為 Encoded，並以 `-32602` 被拒絕。polhem-connector-js 還不會寫 frame，所以在
  `RequireFrame` 下它的 Encoded 與 Encrypted 呼叫本來就會被拒，現在它對這些方法的 Plain 呼叫也會被拒。有這類用戶端的
  部署，在它們能持有金鑰並寫出 frame 之前，請保持 `RequireFrame` 關閉。

安裝在使用者裝置上的用戶端（例如桌面或行動 head）不一定能在同一個時段升級。一個過渡做法是在另一個端點保留一台
Polhem 1.2.0 伺服端，它參考的每個 `Polhem.JsonRpc.*` 套件都鎖定在 1.0.0，供尚未更新的用戶端使用，等它們都更新後再關掉。

以下只適用於自己擴充 JSON-RPC 層的應用程式：

- 自己以 `Polhem.JsonRpc.Server` 1.0 編譯的程式碼（例如透過 `AddJsonRpcServer` 加入的 filter）必須以 1.1.1 以上重新編譯。
- 自己實作的 `IPayloadEncryptor` 必須實作接受 associated data 的 `Encrypt` 與 `Decrypt` 多載，讓驗證涵蓋那份資料。在實作
  之前，經由它的每個 Encrypted 呼叫都會失敗。忽略 associated data 的實作會接受 1.2.0 的形式，讓上述兩種攻擊重新打開。

Polhem.JsonRpc 自己的其餘變更見[它的變更記錄](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/CHANGELOG.md)。

## 行為變更

- **Encrypted 呼叫綁定到它的方法。** `ApiConnector` 以方法封裝每個請求，並以同一個方法開啟結果；伺服端透過 payload filter
  做同樣的事。見「為什麼線路格式改變」。([#60](https://github.com/polhem-dev/polhem/pull/60))
- **結果以請求的格式回應。** 請求為 Encoded 或 Encrypted 時，`null` 結果不再是 plain 的 `null`，而是請求格式、本文為空的
  信封。`ApiConnector` 讀取它實際送出的格式（沒有金鑰的 session 會把 Encrypted 降為 Encoded，以降級後的為準），收到其他
  格式的結果時以 `InvalidPayloadException` 拒絕。([#60](https://github.com/polhem-dev/polhem/pull/60))
- **要求 frame 時，受保護的方法只接受 Encrypted 的遠端呼叫。** 開啟 `RequireFrame` 時，宣告
  `ReplayProtection = UniqueSequence` 的方法會以 `-32602 Invalid params` 拒絕已登入 session 的遠端 Plain 或 Encoded 呼叫。
  Plain 呼叫過去不檢查序號而直接接受；Encoded 呼叫雖會檢查，但它的序號任何人都能偽造，因為只有 Encrypted 的 frame
  受 HMAC 保護。因此呼叫這類方法的用戶端需要 session 金鑰；涉及哪些框架方法與用戶端，見上方「如果你開啟 `RequireFrame`」。
  ([#60](https://github.com/polhem-dev/polhem/pull/60))
- **行程內呼叫不檢查序號是否重複。** 它們從不經過網路，沒有可重放的東西；而本機 provider 在非 debug 模式下送 Plain，
  否則會被上一條規則拒絕。呼叫是否為本機仍只由傳輸層決定。([#60](https://github.com/polhem-dev/polhem/pull/60))
- **沒有值可繫結的呼叫回 `-32602`。** 沒有 `params`，或 payload 信封沒有 `value`、`value` 為 `null` 的請求，會在方法執行前
  以 `-32602 Invalid params` 回應。過去方法會以 `null` 引數執行：多數框架方法回 `-32099` 與「The request is not valid.」，
  其餘則失敗並回 `-32603 Internal error`。這與 Polhem.JsonRpc 預設的 binder 回應相同。`"params": null` 的請求仍以
  `-32600` 拒絕，這是 JSON-RPC 2.0 的要求。([#60](https://github.com/polhem-dev/polhem/pull/60))
- **相依範圍。** 套件相依的 Polhem.JsonRpc 改為 `[1.1.1, 2.0.0)`，不再是 `1.0.0` 以上，所以 Polhem 自己的相依不會解析到
  1.0 套件，之後的主版本也要等 Polhem 以它建置後才會進來。應用程式直接參考的套件要自己升級（見「如何升級」）。下限是
  1.1.1，因為它是第一個只要旁邊有以 `Polhem.JsonRpc.Server` 1.0 編譯的組件，dispatcher 就一律拒絕啟動的版本：
  `AllowCodeCompiledAgainst10` 在其中沒有作用。([#60](https://github.com/polhem-dev/polhem/pull/60))
- **找不到定義改為使用者訊息。** 內建的檔案或資料庫儲存中應存在卻找不到的表單結構描述、資料表結構描述、程式登錄或資料庫
  分類，改為丟出 `DefinitionNotFoundException`：衍生自 `FileNotFoundException`，帶有定義類型與鍵。自訂的儲存沒有傳回表單
  結構描述時，`GetFormSchema` API 也丟出它；除此之外自訂的儲存不受影響。遠端呼叫端會以 UserMessage 錯誤碼（-32099）收到
  它的訊息，例如 `FormSchema 'Employee' not found.`。過去檔案儲存回通用的 `-32603`、資料庫儲存回固定訊息，兩者不一致，
  也都沒有告訴呼叫端少了什麼。訊息只含定義類型與它的鍵，不含任何路徑。既有的 `catch (FileNotFoundException)` 仍會捕捉到
  它；比對確切型別的程式碼會看到這個衍生型別。資料庫儲存過去丟出 `InvalidOperationException`，所以以 catch 該型別處理
  找不到定義的程式碼，必須改為 catch `DefinitionNotFoundException`（或 `FileNotFoundException`）。([#51](https://github.com/polhem-dev/polhem/pull/51))
- **連線只以 ping 檢查端點。** `ApiConnectValidator`（以及 UI head 透過它呼叫的 `ClientInfo`）不再在 ping 之前送 HTTP
  `HEAD` 請求。端點只接受 POST，所以每次連線都回 405，瀏覽器 head 會把它記成錯誤。連不上的主機仍回報為
  `Endpoint not reachable`。([#50](https://github.com/polhem-dev/polhem/pull/50))

## Repository 維護

以下變更的是 repository 的維護方式，不是套件：

- 只改 Markdown 檔的 pull request，會略過必要檢查 `build` 的建置步驟。([#53](https://github.com/polhem-dev/polhem/pull/53))
- 協作者從 fork 工作，由維護者審查並合併他們的 pull request。`CONTRIBUTING.md`、branch protection 說明與 agent 指引改為
  指向 polhem-dev 組織[共用的貢獻指南](https://github.com/polhem-dev/.github/blob/main/CONTRIBUTING.md)，不再各自保留一份。
  ([#55](https://github.com/polhem-dev/polhem/pull/55)、[#56](https://github.com/polhem-dev/polhem/pull/56)、
  [#57](https://github.com/polhem-dev/polhem/pull/57)、[#58](https://github.com/polhem-dev/polhem/pull/58))
