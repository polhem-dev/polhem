# Polhem 1.6.0 — 詳細發佈說明

[English](../../en/changelogs/1.6.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.6.0]` 條目的詳細說明。變更紀錄以一行列一項變更；本檔保留
理由與背景。

## 為什麼是含破壞性變更的次版號

本版破壞了 `Polhem.Api.Client`、`Polhem.UI.Core` 與 `Polhem.Web.Blazor.Server` 的公開 API。從這一版起，1.x 的次版號可以
這麼做，但每一項破壞都會連同遷移步驟列在變更紀錄裡；修訂版號不會。嚴格的語意化版本從 2.0 開始。這項政策與理由見
[ADR-052](../../../maintainers/adr/adr-052-breaking-changes-in-1-x-minors.md)。引用套件時請使用不跨次版號的範圍，例如
`[1.6,1.7)`。

wire 格式與 1.5.0 相同。1.5.0 的客戶端與 1.6.0 的伺服端（或反過來）可以互通；只有對客戶端套件編譯的程式碼需要修改。

## 如何升級

- **自行建立連接器的主控台程式、服務或工具：** 建立一個 `PolhemApiClient`，再從它取得連接器，如下方範例。
- **以 `ClientInfo` 為基礎的桌面 head：** 程式碼不變，只要把 `ApiClientInfo.SupportedConnectTypes` 與
  `ApiClientInfo.ConnectType` 改為 `ClientInfo` 上的同名成員。
- **Blazor Server 主機：** 把 API 金鑰傳給 `UseRemoteProvider(endpoint, apiKey)`，原本注入
  `PolhemApiConnectorFactory` 的地方改注入 `PolhemApiClient`，並移除傳給 `FormPage` 的 `AccessToken`。

每個被移除的成員與其替代品都列在變更紀錄中。

## 一個 client 擁有連線與身分

到 1.5.0 為止，.NET 客戶端呼叫時用到的狀態分屬三處：靜態的 `ApiClientInfo`（端點、API 金鑰、payload 選項、預設語言）、
`ApiSessionContext`（傳輸金鑰、時區），以及每個連接器（存取權杖與傳輸，建構時就固定）。呼叫端得自己在行程內與 HTTP 的
建構子之間選擇，並一路傳遞權杖。重新登入後，仍被某處握著的連接器會以舊權杖配新金鑰送出，被伺服器拒絕。多使用者主機
若忘了給連接器自己的 session，會退回共用的那一份，出現偶發的 `ReplayRejected`。

`PolhemApiClient` 取代了這三處。它只建立一次（行程內或經 HTTP），並發出連接器：

```csharp
var client = PolhemApiClient.CreateRemote("https://host/api", apiKey);
await client.System.LoginAsync(userId, password);
await client.System.EnterCompanyAsync(companyId);
var data = await client.Form("Employee").GetDataAsync(rowId);
```

登入會把存取權杖、傳輸金鑰與使用者時區以一個 `ApiSessionCredentials` 存進 client 的 session，整份替換。每次呼叫在開始時
讀取一次，所以一次呼叫不會送出某次登入的權杖配上另一次登入的金鑰。同一個行程可以呼叫多台伺服器，各用自己的 client。
設計與替代方案見 [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)。

### 需要知道的行為

- **連接器跟隨它的 client。** 在重新登入前取得的連接器，之後會以新的身分呼叫。服務多位使用者的主機為每位使用者各建
  一個 client；Blazor Server 套件為每個 circuit 註冊一個。
- **`Form(progId)` 每次都回傳新的連接器。** 建立的成本很低，它本身不持有身分。
- **API 金鑰在每個請求時讀取。** 設定 `PolhemApiClient.ApiKey` 後，從下一次呼叫起生效。
- **連線檢查不再送出 API 金鑰。** `ApiConnectValidator` 以不帶金鑰的方式 ping，因為伺服器回應 `System.Ping` 不需要金鑰。
  金鑰錯誤改在連線時取得設定的那一次呼叫才會出現。
- **`ClientInfo.ApplyLoginResult` 一律丟棄快取的定義與權限能力。** 以前只有權杖改變時才會。

## 效能

現在每次呼叫都會建立一個傳輸。2026-10-10 的負載測試（SQL Server、20 個虛擬使用者、Closed 模型）與 1.5.0 相比沒有可
量測的差異：兩個版本之間的差距，比同一版本兩次執行之間的差距還小。數據與量測條件見 pull request
（[#104](https://github.com/polhem-dev/polhem/pull/104)）。
