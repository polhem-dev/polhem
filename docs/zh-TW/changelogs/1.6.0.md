# Polhem 1.6.0 — 發佈說明

[English](../../en/changelogs/1.6.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.6.0]` 條目的詳細內容。

本版讓 `Polhem.Api.Client` 只有一個進入點：`PolhemApiClient`，由它擁有連線與已登入的身分，並發出連接器。本版破壞了
`Polhem.Api.Client`、`Polhem.UI.Core` 與 `Polhem.Web.Blazor.Server` 的公開 API。從這一版起，1.x 的次版號可以這麼做，但每一項
破壞都會連同遷移步驟一併列出；修訂版號不會。嚴格的語意化版本從 2.0 開始。這項政策與理由見
[ADR-052](../../../maintainers/adr/adr-052-breaking-changes-in-1-x-minors.md)。引用套件時請使用不跨次版號的範圍，例如
`[1.6,1.7)`。wire 格式與 1.5.0 相同：1.5.0 的客戶端與 1.6.0 的伺服端（或反過來）可以互通；只有對客戶端套件編譯的程式碼需要修改。

- **自行建立連接器的主控台程式、服務或工具：** [連接器從 `PolhemApiClient` 取得](#連接器從-polhemapiclient-取得)、
  [`ApiClientInfo` 已移除](#apiclientinfo-已移除)與[連接器以所屬 client 目前的登入身分呼叫](#連接器以所屬-client-目前的登入身分呼叫)。
- **以 `ClientInfo` 為基礎的桌面 head：** 程式碼不變，只要把 `ApiClientInfo.SupportedConnectTypes` 與
  `ApiClientInfo.ConnectType` 改為 `ClientInfo` 上的同名成員（[`ApiClientInfo` 已移除](#apiclientinfo-已移除)）；另見
  [`ClientInfo.ApplyLoginResult` 一律丟棄快取的定義](#clientinfoapplyloginresult-一律丟棄快取的定義)。
- **Blazor Server 主機：** [Blazor Server 為每個 circuit 注入一個 `PolhemApiClient`](#blazor-server-為每個-circuit-注入一個-polhemapiclient)。

## 新功能與變更

### 一個 client 擁有連線與身分

`PolhemApiClient` 只建立一次：行程內用 `PolhemApiClient.CreateLocal(services)`，經 HTTP 用
`PolhemApiClient.CreateRemote(endpoint, apiKey)`，並由它發出連接器（`client.System`、`client.AuditLog`、
`client.Form(progId)`）：

```csharp
var client = PolhemApiClient.CreateRemote("https://host/api", apiKey);
await client.System.LoginAsync(userId, password);
await client.System.EnterCompanyAsync(companyId);
var data = await client.Form("Employee").GetDataAsync(rowId);
```

登入會把存取權杖、傳輸金鑰與使用者時區以一個 `ApiSessionCredentials` 存進 client 的 session，整份替換。之後每個連接器都以
該次登入的權杖、傳輸金鑰與時區呼叫，不必再到處傳遞權杖。每次呼叫在開始時讀取一次這份憑證，所以一次呼叫不會送出某次登入的
權杖配上另一次登入的金鑰。

- **同一個行程呼叫多台伺服器。** 每個 client 各自擁有端點、API 金鑰與身分，所以同一個行程可以呼叫多台伺服器，各用自己的 client。
- **`Form(progId)` 每次都回傳新的連接器。** 建立的成本很低，它本身不持有身分。
- **API 金鑰在每個請求時讀取。** 設定 `PolhemApiClient.ApiKey` 後，從下一次呼叫起生效。
- **桌面與 Blazor。** `ClientInfo.ApiClient` 是桌面 head 的 client。`PolhemBlazorOptions.ApiKey` 與
  `PolhemBlazorOptions.DefaultLanguage` 設定 Blazor Server 套件所註冊的 client。
- **`LoginAsync` 之後，可用同一個 `ClientInfo.SystemApiConnector` 呼叫 `EnterCompanyAsync`，** 不必重新讀取。

**原因。** 到 1.5.0 為止，.NET 客戶端呼叫時用到的狀態分屬三處：靜態的 `ApiClientInfo`（端點、API 金鑰、payload 選項、預設語言）、
`ApiSessionContext`（傳輸金鑰、時區），以及每個連接器（存取權杖與傳輸，建構時就固定）。呼叫端得自己在行程內與 HTTP 的
建構子之間選擇，並一路傳遞權杖。重新登入後，仍被某處握著的連接器會以舊權杖配新金鑰送出，被伺服器拒絕。多使用者主機
若忘了給連接器自己的 session，會退回共用的那一份，出現偶發的 `ReplayRejected`。設計與替代方案見
[ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)。

**效能。** 現在每次呼叫都會建立一個傳輸。2026-10-10 的負載測試（SQL Server、20 個虛擬使用者、Closed 模型）與 1.5.0 相比沒有可
量測的差異：兩個版本之間的差距，比同一版本兩次執行之間的差距還小。數據與量測條件見 pull request
（[#104](https://github.com/polhem-dev/polhem/pull/104)）。

## 破壞性變更

### 連接器從 `PolhemApiClient` 取得

- **影響對象：** 自行建構連接器、讀取 `ApiConnector.AccessToken` 或 `ApiConnector.Provider`，或使用 `LocalApiProvider`、
  `RemoteApiProvider` 的程式碼。
- **原本：** 每個連接器都有接收端點或服務提供者加存取權杖的建構子，由呼叫端在行程內與 HTTP 的建構子之間選擇，並一路傳遞權杖。
- **現在：** 每個連接器只剩一個接收 client 的建構子。接收端點或服務提供者加存取權杖的建構子已移除，`ApiConnector.AccessToken` 與
  `ApiConnector.Provider` 已移除，`LocalApiProvider` 與 `RemoteApiProvider` 改為 internal。
- **遷移：** 以 `PolhemApiClient.CreateRemote(endpoint, apiKey)` 或 `PolhemApiClient.CreateLocal(services)` 建立一個
  `PolhemApiClient`，透過 `client.System.LoginAsync` 登入，再從它取得連接器（`client.System`、`client.AuditLog`、
  `client.Form(progId)`），如[一個 client 擁有連線與身分](#一個-client-擁有連線與身分)所示。
- **背景：** [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)

### `ApiClientInfo` 已移除

- **影響對象：** 讀取或設定 `ApiClientInfo` 的程式碼，包括使用 `ApiClientInfo.SupportedConnectTypes` 或
  `ApiClientInfo.ConnectType` 的桌面 head，以及呼叫 `ApiConnectValidator.ValidateAsync` 的程式碼。
- **原本：** 靜態的 `ApiClientInfo` 為整個行程保存端點、連線方式、API 金鑰、payload 選項、支援的連線方式與預設語言。
- **現在：** 每項設定改放在 client 上，或桌面的 `ClientInfo` 上。`ApiConnectValidator.ValidateAsync` 的第二個參數改為允許的連線方式。
- **遷移：**

  | 原本 | 現在 |
  |------|------|
  | `ApiClientInfo.Endpoint` | `PolhemApiClient.Endpoint` |
  | `ApiClientInfo.ConnectType` | `PolhemApiClient.IsLocal`（桌面：`ClientInfo.ConnectType`） |
  | `ApiClientInfo.ApiKey` | `CreateRemote` 的參數，或 `PolhemApiClient.ApiKey` |
  | `ApiClientInfo.PayloadOptions` | `PolhemApiClient.PayloadOptions` |
  | `ApiClientInfo.SupportedConnectTypes` | `ClientInfo.SupportedConnectTypes` |
  | `ApiClientInfo.DefaultLanguage` | `PolhemApiClient.DefaultLanguage`（Blazor：`PolhemBlazorOptions.DefaultLanguage`） |

  把允許的連線方式作為第二個參數傳給 `ApiConnectValidator.ValidateAsync`。桌面 head 的 `ClientInfo` 簽章不變。
- **背景：** [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)

### `ApiSessionContext` 持有一個 `ApiSessionCredentials`

- **影響對象：** 使用 `ApiSessionContext.Ambient`，或設定 `ApiSessionContext.ApiEncryptionKey`、`ApiSessionContext.UserTimeZoneId`
  的程式碼。
- **原本：** 有一個 ambient session，傳輸金鑰與時區逐項設定。
- **現在：** `ApiSessionContext.Ambient` 以及 `ApiEncryptionKey`、`UserTimeZoneId` 的 setter 已移除。session 改持有一個
  `ApiSessionCredentials`，由 `SignIn` 與 `SignOut` 整份替換。
- **遷移：** 透過 client 的 `System.LoginAsync` 登入，由它替換憑證；自行管理 session 的程式碼以 `ApiSessionCredentials` 呼叫
  `SignIn`，並呼叫 `SignOut`。
- **背景：** [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)

### Blazor Server 為每個 circuit 注入一個 `PolhemApiClient`

- **影響對象：** 以 `Polhem.Web.Blazor.Server` 建立的 Blazor Server 主機。
- **原本：** 元件注入 `PolhemApiConnectorFactory`，API 金鑰透過 `ApiClientInfo.ApiKey` 設定，`FormPage` 有 `AccessToken` 參數。
- **現在：** `PolhemApiConnectorFactory` 已移除。`AddPolhemBlazor` 為每個 circuit 註冊一個 scoped 的 `PolhemApiClient`。
  `UseRemoteProvider` 的第二個參數改為 API 金鑰。`FormPage` 不再有 `AccessToken` 參數：它以 circuit 的 client 上已登入的身分呼叫。
- **遷移：**
  1. 把 API 金鑰傳給 `UseRemoteProvider(endpoint, apiKey)`，取代設定 `ApiClientInfo.ApiKey`。
  2. 原本注入 `PolhemApiConnectorFactory` 的地方改注入 `PolhemApiClient`。
  3. 移除傳給 `FormPage` 的 `AccessToken`。
- **背景：** [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)

### 連接器以所屬 client 目前的登入身分呼叫

- **影響對象：** 在重新登入後仍保留連接器的程式碼，以及服務多位使用者的主機。
- **原本：** 連接器保留建構時拿到的存取權杖。
- **現在：** 連接器跟隨它的 client：在重新登入前取得的連接器，之後會以新的身分呼叫。
- **遷移：** 服務多位使用者的主機為每位使用者各建一個 client；Blazor Server 套件為每個 circuit 註冊一個。
- **背景：** [ADR-053](../../../maintainers/adr/adr-053-api-client-composition-root.md)

### 連線檢查不再送出 API 金鑰

- **影響對象：** 依賴 `ApiConnectValidator` 回報 API 金鑰錯誤的應用程式。
- **原本：** 連線檢查會送出 API 金鑰。
- **現在：** `ApiConnectValidator` 以不帶金鑰的方式 ping，因為伺服器回應 `System.Ping` 不需要金鑰。金鑰錯誤改在連線時取得設定的
  那一次呼叫才會出現。
- **遷移：** 在連線時取得設定的那一次呼叫處理金鑰錯誤，而不是在連線檢查。

### `ClientInfo.ApplyLoginResult` 一律丟棄快取的定義

- **影響對象：** 呼叫 `ClientInfo.ApplyLoginResult` 的桌面 head。
- **原本：** 只有權杖改變時，才丟棄快取的定義與權限能力。
- **現在：** 一律丟棄。
- **遷移：** 不需修改；預期每次登入後都會重新載入定義與權限能力。
