# Polhem 1.7.0 — 發佈說明

[English](../../en/changelogs/1.7.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.7.0]` 條目的詳細內容。

本版把前端與 API client 從伺服端分開：前端透過契約連到後端，不再帶著傳輸層；API client 也不再帶著伺服端的 dispatcher。
wire 格式與 1.6.0 相同，所以 1.6.0 的客戶端與 1.7.0 的伺服端（或反過來）可以互通。

## 新功能與變更

### 不需要 Polhem 後端也能執行的表單

`FormView` 與 `ListView` 依 host 設定的 schema、layout 與連接器運作，應用程式可以用自己的資料顯示表單。組成如下：

- `IFormApiConnector` 與 `IFormApiConnectorFactory`（`Polhem.Api.Contracts`）：前端呼叫的表單操作。
  `FormApiConnector` 以 Polhem 後端實作它們；應用程式也可以依自己的資料實作。
- `Polhem.UI.Core` 中的 `UIServices`（存放前端要解析的服務）、`IUserContext`、`IFormDefinitionSource` 與從
  `IDefineStorage` 讀定義的 `StorageDefinitionSource`，以及回應型別 `FormListResult`、`FormDataResult`、
  `FormDeleteResult`。

### 新套件 `Polhem.UI.ApiBridge`

把前端接到 Polhem 後端：`AddPolhemUIApiBridge` 註冊 `FormApiConnectorFactory`、`ApiFormDefinitionSource` 與
`ClientUserContext`。連後端的 head 要參考它；如何切換見
[前端不再參考 API client](#前端不再參考-api-client)。

### 新套件 `Polhem.Api.Server`

只有伺服端執行的 dispatcher 設定、授權與存取控制。`Polhem.Hosting` 參考它，所以以 `AddPolhemFramework` 建立的 host
不必修改；見 [API 的伺服端移到 Polhem.Api.Server](#api-的伺服端移到-polhemapiserver)。

### `Polhem.Web.Blazor.Server` 參考 `Polhem.UI.Core`

Blazor Server 套件與桌面前端共用表單繫結與權限能力型別。

## 破壞性變更

### 前端不再參考 API client

- **影響對象：** 所有以 `Polhem.UI.Core` 或 `Polhem.UI.Avalonia` 建立的桌面、行動或瀏覽器 head，以及使用
  `FormValueBinding`、`FormDataGuard` 或權限能力解析器的程式碼。
- **原本：** `Polhem.UI.Core` 參考 `Polhem.Api.Client`，持有 `ClientInfo` 與端點儲存，表單檢視透過 `ClientInfo`
  取得連接器與定義。
- **現在：** `Polhem.UI.Core` 與 `Polhem.UI.Avalonia` 只相依 `Polhem.Api.Contracts` 的契約。它們需要的服務來自
  `UIServices.Provider`，連線相關元件放在 `Polhem.UI.ApiBridge`。
- **遷移：**
  1. 連 Polhem 後端的 head 參考 `Polhem.UI.ApiBridge`，並在啟動時設定
     `UIServices.Provider = new ServiceCollection().AddPolhemUIApiBridge().BuildServiceProvider();`。
     沒有這一步，`FormView`、`ListView` 與查詢視窗取不到連接器、定義與使用者情境。
  2. 更新搬家型別的命名空間：

     | 型別 | 原本 | 現在 |
     |------|------|------|
     | `ClientInfo`、`IEndpointStorage`、`IApiKeyStorage`、`FileEndpointStorage` | `Polhem.UI.Core` | `Polhem.UI.ApiBridge` |
     | `FormValueBinding`、`FormDataGuard` | `Polhem.Api.Client` | `Polhem.UI.Core` |
     | `ElementCapabilityResolver`、`IElementCapabilityResolver`、`FieldCapability` | `Polhem.Api.Client.Permissions` | `Polhem.UI.Core.Permissions` |

  3. `FormView.FormConnector`、`ListView.FormConnector`、`FormDataObject`、`LookupPanel.Bind` 與
     `LookupDialog.ShowAsync` 改收 `IFormApiConnector`。原本傳入 `FormApiConnector` 的程式碼照常編譯。
     覆寫 `ResolveFormConnector` 的程式碼改回傳 `IFormApiConnector?`。`FormDataGuard.RequireConnector` 改為泛型。
  4. `FormView.DefinitionLoader`、`ListView.DefinitionLoader` 改用 `DefinitionSource`（`IFormDefinitionSource`）。
     移除 `ResolveLang` 的覆寫：語系由定義來源決定。
  5. 移除對 `FormView.AccessToken`、`ListView.AccessToken` 與 `ResolveAccessToken` 的使用；token 已由 client 的
     session 持有，沒有地方讀它們。檢視子類別中讀 `ClientInfo` 的程式碼改用 `ResolveUserContext`。
  6. `IUIViewService` 與 `ClientInfo.UIViewService` 已移除。以 `ClientInfo.InitializeAsync(SupportedConnectTypes)`
     取代 `ClientInfo.InitializeAsync(IUIViewService, SupportedConnectTypes)`；回傳 `false` 時由 head 自行顯示連線設定，
     再呼叫 `ClientInfo.InitializeAsync(endpoint)`。
- **背景：** [ADR-054](../../../maintainers/adr/adr-054-front-end-decoupled-from-api-client.md)

### API 的伺服端移到 Polhem.Api.Server

- **影響對象：** 有自訂 `IApiAuthorizationValidator` 的伺服端、不經 `AddPolhemFramework` 自行組裝 dispatcher 的
  host、在自建 service provider 上呼叫 `PolhemApiClient.CreateLocal` 的程式碼、以 `Polhem.Api.Core` 為鍵的 log 設定，
  以及經由 `Polhem.Api.Client` 使用伺服端套件的應用程式。
- **原本：** `Polhem.Api.Core` 包含 dispatch、授權與存取控制，因此每個 API client，以及經由 `Polhem.UI.ApiBridge`
  的每個前端，都帶著伺服端套件。
- **現在：** 這些移到 `Polhem.Api.Server`，它對 `Polhem.Api.Core` 的相依是完全相同的版本。wire 不變。
- **遷移：**
  1. 修改命名空間：`Polhem.Api.Core.Dispatch`、`Polhem.Api.Core.Authorization`、`Polhem.Api.Core.Validator`
     改為 `Polhem.Api.Server.Dispatch`、`Polhem.Api.Server.Authorization`、`Polhem.Api.Server.Validator`。
     自訂的 `IApiAuthorizationValidator` 要改 `using`。
  2. 不經 `AddPolhemFramework` 自行組裝 dispatcher 的 host 參考 `Polhem.Api.Server`。
  3. `PolhemApiClient.CreateLocal` 透過 `AddPolhemFramework` 註冊的 `IInProcessTransportFactory` 呼叫同程序的
     dispatcher。不經它建立的 service provider，要自行把 `InProcessTransportFactory`（`Polhem.Api.Server.Dispatch`）
     註冊為 `IInProcessTransportFactory`。
  4. log 類別跟著命名空間改變：被遮蔽的失敗記錄在 `Polhem.Api.Server.Dispatch.PolhemExceptionMapper`，API 金鑰查詢的
     警告記錄在 `Polhem.Api.Server.Dispatch.PolhemObjectFactory`。以 `Polhem.Api.Core` 為鍵的 `Logging:LogLevel`
     篩選或 sink 路由要跟著改。
  5. `Polhem.Api.Client`（以及 `Polhem.UI.ApiBridge`）不再間接帶入 `Microsoft.Extensions.Logging.Abstractions`、
     `Polhem.JsonRpc.Server` 與 `Polhem.JsonRpc.Payload.Server`。經由它使用這些套件的應用程式要自行參考。
- **背景：** [ADR-055](../../../maintainers/adr/adr-055-api-core-split-from-server.md)

### 移除 `FileHashValidator`

- **影響對象：** 呼叫 `Polhem.Core.Security.FileHashValidator` 的程式碼。
- **原本：** `FileHashValidator` 以 SHA-256 雜湊驗證檔案。框架內沒有任何地方使用它。
- **現在：** 此型別已移除。
- **遷移：** 以 `SHA256.HashData(stream)` 計算雜湊，再以 `CryptographicOperations.FixedTimeEquals` 比對。

### 移除 `IDisplayName`

- **影響對象：** 實作 `Polhem.Core.IDisplayName` 的型別。
- **原本：** `TreeNodeAttribute.GetDisplayText` 在格式化結果為空時使用 `IDisplayName`。
- **現在：** `IDisplayName` 已移除，`TreeNodeAttribute.GetDisplayText` 改為退回 `ToString()`。
- **遷移：** 改為覆寫 `ToString()`，不再實作 `IDisplayName`。
