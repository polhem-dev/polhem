# Polhem 1.14.0 — 發佈說明

[English](../../en/changelogs/1.14.0.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.14.0]` 條目的詳細內容。

DefineEditor 現在能以和 Claude 的對話，從紙本文件草擬表單，背後是兩個新套件 `Polhem.Definition.Drafting` 與
`Polhem.AI.Claude`。型別與來源欄位不同的關聯欄位改為建置錯誤；沒有設定 `|DataDirectory|` 的 host，SQLite 檔改在定義資料夾旁。
wire 格式與 1.13.0 相同。

## 新功能與變更

### 在 DefineEditor 從文件草擬表單

**檔案 → 從文件匯入表單...** 先徵得同意，再把紙本表單（PDF、Word 文件或照片）送給 Claude，並開啟草擬視窗：左邊是對話；
右邊是匯入後會寫出的表單畫面、草擬的欄位（可直接編修）與待確認的問題。Claude 會讀出主表與明細表、英文與 zh-TW 標題、型別、長度、
下拉選項、計算欄位與清單欄位，並把挑選記錄的欄位（員工、部門、客戶）對到定義資料夾中既有的表單，沒把握時會詢問。
**產生定義** 執行的是與 Excel 活頁簿相同的匯入，檢查與確認步驟也相同。

對話以 DefineEditor 介面的語言開始，使用者改用別的語言時跟著換。DefineEditor 不保存任何憑證：它使用 Anthropic SDK 找到的憑證，
也就是 `ant auth login` 的設定檔或 `ANTHROPIC_API_KEY`，費用由該憑證所屬的 Claude Console 組織支付。使用指南見
[從文件草擬表單](../guides/document-form-drafting.md)。

- **背景：** [ADR-064](../../../maintainers/adr/adr-064-document-form-drafting.md)

### 新套件：`Polhem.Definition.Drafting`

草擬本身，供任何想提供這項功能的應用程式使用。`DocumentSource` 原樣讀取 PDF 與影像、把 Word 文件讀成 Markdown；
`FormDraftSession` 透過任何 `IChatClient`（`Microsoft.Extensions.AI.Abstractions`）進行對話，並執行模型用來修改草稿的工具；
`FormDraftConverter` 以固定規則把草稿轉成 `FormSchema`、zh-TW 文字與選單位置，模型從不直接撰寫定義。應用程式透過
`IFormDraftingHost` 提供既有表單與驗證。`FormDraftingOptions.ReplyCulture` 設定第一則回覆的語言。本套件不參考任何模型廠商的 SDK。
見其 [README](../../../src/Polhem.Definition.Drafting/README.zh-TW.md)。

### 新套件：`Polhem.AI.Claude`

草擬用的 Claude 提供者：`ClaudeChatClientFactory.Create` 傳回以官方 Anthropic SDK 實作的 `IChatClient`，具備串流、
明確設定 effort 的 adaptive thinking、prompt 快取、strict 工具與伺服器端的拒答備援。拒答、輸出到達上限而被截斷、憑證被拒時
丟出 `ClaudeChatException`。`ClaudeCredentials.Describe()` 回報 SDK 會用哪一個憑證，不讀取任何機密。見其
[README](../../../src/Polhem.AI.Claude/README.zh-TW.md)。

### Excel 匯入以記錄名稱列出關聯欄位

表單活頁簿在 **清單顯示欄位** 列出關聯欄位時，清單改列顯示關聯記錄名稱的欄位（`ref_<base>_name`），清單顯示名稱而非 row id。

### `DateOnly` 篩選值在 SQLite 與 Oracle 能比對日期

以 `DateOnly` 篩選日期欄位時，SQLite 的 **等於** 比對不到任何資料、**介於** 會漏掉最後一天，因為驅動程式把值綁成不含時間的文字，
而儲存的日期帶有時間；Oracle 則直接拒絕這個值。兩者現在都綁成當天午夜的日期。SQL Server、PostgreSQL 與 MySQL 不變。

### `polhem-db` 與 DefineEditor 的資料庫升級接受 `|DataDirectory|`

`polhem-db`（以及使用它的 DefineEditor **升級資料庫**）過去把 `|DataDirectory|` 下的 SQLite 路徑當成相對路徑而停止。
現在它與各 host 一樣，把這個前綴解析為存放定義資料夾的資料夾（見下方的破壞性變更）。見
[資料庫設定 §2.7](../database/database-settings-guide.md#27-sqlite-檔案路徑)。

### DefineEditor 拒絕 POLHEM2008 回報的關聯型別

關聯對話框過去會套用型別不同的對應，之後在使用端的建置被拒絕；也會標記規則其實接受的組合。它現在使用 analyzer 本身的規則：
型別不符在對話框中是錯誤，只供查詢的對應不檢查。

### wire fixtures 固定 Binary 欄位與唯讀欄位的樣本

`wire-fixtures/` 新增預設值為空位元組陣列的 Binary 欄位，以及異動資料列攜帶的唯讀欄位樣本。編碼不變；依 fixtures 撰寫的
用戶端現在能看到這兩種形狀。

## 破壞性變更

### 關聯欄位必須宣告與來源欄位相同的型別（POLHEM2008）

- **影響：** 定義中把關聯欄位對應到不同型別來源欄位的應用程式，例如把 `Guid` row id 複製到 `String` 欄位。
- **之前：** 這種對應會被接受，而篩選該欄位時依宣告的型別轉換值，結果比對不到或被拒絕。
- **現在：** analyzer 回報錯誤 **POLHEM2008**。`Integer` 與 `AutoIncrement`、`Decimal` 與 `Currency`、`String` 與 `Text`
  視為相同；較寬的整數可以接受；只供查詢的對應不檢查。
- **遷移：** 把關聯欄位的 `DbType` 改成來源欄位的型別，欄位型別有變時升級資料表。見 [Analyzer 規則](../reference/analyzer-rules.md)。

### 沒有設定 `|DataDirectory|` 的 host，SQLite 檔改在定義資料夾旁

- **影響：** 以 `AddPolhemBackend` 建立、`DatabaseSettings.xml` 使用 `|DataDirectory|` 卻沒有自行設定 `DataDirectory` 的 host。
- **之前：** Microsoft.Data.Sqlite 把這個前綴解析為應用程式的基底資料夾，通常是建置輸出資料夾，資料庫檔的位置取決於 host 的啟動方式。
- **現在：** `AddPolhemBackend` 與 `polhem-db` 呼叫 `DataDirectory.EnsureDefault`（`Polhem.Hosting.Database`），在 host 沒有設定時，
  把值設為存放定義資料夾的資料夾。已自行設定的 host 維持原值。
- **遷移：** 把既有的資料庫檔搬到定義資料夾旁，或在 `AddPolhemBackend` 之前設定 `DataDirectory` 以保留原位置。
