# Polhem 1.0.0 — 詳細發佈說明

[English](1.0.0.md) · [← CHANGELOG](../../CHANGELOG.zh-TW.md)

本檔是 [CHANGELOG.zh-TW.md](../../CHANGELOG.zh-TW.md) 中 `[1.0.0]` 一節的詳細說明。變更記錄每項變更只寫一行；本檔
保留理由與背景。1.0.0 發佈前，本檔為草稿。

> Polhem 以新名稱延續 [Bee.NET](https://github.com/jeff377/bee-library)。Polhem 1.0.0 是 Bee.NET 最後發佈的 4.33.0
> 改名之後，再加上下文所述、首發前審查帶來的變更。應用程式如何遷移，見
> [從 Bee.NET 遷移](../../README.zh-TW.md#從-beenet-遷移)。

## 為什麼換名稱、另開 repo

Polhem 就是原本以 Bee.NET 發佈的框架，移到 `polhem-dev` 組織，以便由多人共同維護。它從新的 repo
`polhem-dev/polhem` 開始，不帶 git 歷史；搬移之前的歷史留在已凍結的 `jeff377/bee-library`。`Bee.*` 套件不再開發。

新的套件 ID 從 1.0.0 開始自己的版號。

## 改名如何驗證

改名以機械方式進行，驗證方法是把所有名稱改回 `Bee`，再與起點的 Bee.NET 原始碼比對（`jeff377/bee-library` 的
commit `7d6cc9d9`，其 `src/` 與 `tools/Bee.Cli` 與 `v4.33.0` tag 完全相同）。比對後剩下的只有授權條款、套件中繼資料
與圖示。完整的測試（含資料庫測試）跑出的測試數與 Bee.NET 相同，且全數通過。

有幾類名稱是編譯器不會檢查的字串，例如定義檔中的型別名稱、analyzer 以 metadata name 查找的型別、trimming
descriptor 中的組件名稱。原本沒有測試的類別補上了測試，例如檢查定義檔型別名稱的
`DefinitionFileTypeReferenceGateTests`、檢查 trimming descriptor 的 `TrimmerDescriptorGateTests`。

這項驗證涵蓋的是改名這一步。之後的首發前審查修改了程式碼，那些變更寫在
[首發前審查帶來的變更](#首發前審查帶來的變更)。

## 由 Bee.NET 改名

### 套件 ID 與命名空間

每個 `Bee.<名稱>` 套件改為 `Polhem.<名稱>`，命名空間照同一規則。套件的切分不變，每個套件仍以 `net10.0` 為目標。

### 以 Bee 命名的型別與成員

型別或成員名稱中的 `Bee` 改為 `Polhem`：`AddPolhemFramework`、`UsePolhemFramework`、`AddPolhemBlazor`、
`PolhemBlazorOptions`、`PolhemBlazorProviderMode`、`PolhemApiConnectorFactory`、`PolhemAccessTokenProvider`、
`PolhemLoginPanel`，以及擴充方法類別 `PolhemFrameworkServiceCollectionExtensions`、
`PolhemFrameworkApplicationBuilderExtensions`、`PolhemBlazorServiceCollectionExtensions`。仍使用舊名稱的地方，
編譯器都會報出來。

有兩個名稱先照同一規則改名，之後又在審查中再改一次，因為框架名稱說明不了它們是什麼：`IBeeContext` / `BeeContext`
現在是 `IBusinessObjectContext` / `BusinessObjectContext`，`BeeStringLocalizer<T>` 現在是
`LanguageResourceStringLocalizer<T>`。

### 沒有相容層

所有帶 `Bee` 的名稱都已改名，包括編譯器不會檢查的那些，而且舊名稱不再被辨識。以 Bee.NET 建置的應用程式大多放在
開發者自己掌控的 repo 裡，一次性的搜尋取代就足夠。README 列出了這些名稱，並附上找出它們的指令。

- **型別名稱**：payload、預設設定，以及定義檔中 `BusinessObject` / `Repository` 的繫結，都使用 `Polhem.*` 型別名稱。
  伺服端只接受允許的命名空間中的 payload 型別，所以 Bee.NET 用戶端與 Polhem 伺服端無法互通；用戶端與伺服端要一起升級。
- **主金鑰**：預設的環境變數是 `POLHEM_MASTER_KEY`。在 `MasterKeySource` 寫明變數名稱的 `SystemSettings.xml`，
  照樣使用該名稱。
- **session 金鑰**：`DerivedApiEncryptionKeyProvider` 以 `polhem-api-session-key` 與 `polhem-api-encryption-root-key`
  這兩個標籤衍生各 session 的加密金鑰，原本是 `bee-api-*`。衍生出的金鑰從不儲存，所以沒有任何儲存的資料依賴這些
  標籤。無論如何，Bee.NET 建立的 session 都會結束，因為 session 表現在改用不同的鍵值（見下方〈安全性〉）。
- **建置整合**：analyzer 診斷代號為 `POLHEMnnnn`，數字不變（`POLHEM4001`–`POLHEM4004` 保留不用，因為 Bee.NET
  曾發佈後又停用 `BEE4001`–`BEE4004`，依數字對應過來的抑制設定不應讓未來的規則靜默）；定義檔檢查用的 MSBuild 屬性為
  `PolhemDefinitionFilesGlob`、`PolhemRequireDefinitionFiles`、`PolhemAnalyzeDefinitionFiles`。使用舊名稱的設定會被
  忽略，而且沒有警告。
- **命令列工具**為 `Polhem.Cli`，以 `dotnet polhem` 呼叫。
- **殘留名稱的提示**：無法解析且以 `Bee.` 開頭的型別或組件名稱，失敗訊息會指出改名這件事（`BeeNameHint`），定義檔、
  設定與 payload 皆然。找不到 `POLHEM_MASTER_KEY` 而 `BEE_MASTER_KEY` 有設定時，錯誤訊息會指出這一點。
- **Blazor 元件**使用 `polhem-` 開頭的 CSS class。
- **資料 key**：記錄欄位宣告型別的 `DataColumn` 擴充屬性為 `Polhem.FieldDbType`；`Exception.Data` 的 key
  `SerializationErrorData.FilePath` 為 `Polhem.FilePath`。Bee.NET 寫入的稽核紀錄，其儲存的 XML 中仍是
  `Bee.FieldDbType`；讀出的值不變，只是不再知道其欄位宣告的型別。

### 套件中繼資料

作者與著作權人為 Polhem contributors，專案與 repository 網址指向 `polhem-dev/polhem`，套件使用 Polhem 的圖示。
授權仍是 MIT。`Polhem.Cli` 共用相同的中繼資料，並隨附 README 與符號套件。([#3](https://github.com/polhem-dev/polhem/pull/3))

## 首發前審查帶來的變更

1.0.0 之前，框架做過一次全面審查：安全、wire 合約、並行、公開 API、測試、國際化、效能與修剪。修正都在首次發佈前
完成，所以修正公開 API 不必等到 2.0.0。以下各組說明理由，並連到做出該變更的 pull request；一行一項的清單在
[CHANGELOG](../../CHANGELOG.zh-TW.md)，升級時要做的事在 README。

### 安全性

- **不儲存存取權杖。** `st_session` 的 `access_token` 欄位存的是權杖經 `AccessTokenHasher.ComputeStorageKey` 算出的
  值，session 種子也不再包含權杖，因此能讀取該表也拿不到可用的 bearer 權杖。記錄表 `st_log_access`、
  `st_log_anomaly_api`、`st_log_change`、`st_log_login` 在 `token_fingerprint` 保存簡短的指紋，仍可串起同一個 session
  的記錄。切換前寫入的資料列對不上任何權杖，因此既有的 session 全部結束。
  ([#5](https://github.com/polhem-dev/polhem/pull/5))
- **密碼。** 新的雜湊使用 PBKDF2-SHA256、600,000 次迭代（當時的 OWASP 建議），格式本身記錄迭代次數；迭代次數較少的
  雜湊在下次登入成功時換新（`PasswordHasher.NeedsRehash`）。沿用自 Bee.NET、沒有前綴的 PBKDF2-SHA1 格式不再能通過
  驗證，仍是這種雜湊的帳號需要重設密碼。不存在的帳號也會執行一次誘餌雜湊，所以登入失敗花的時間不會透露帳號是否存在。
  ([#5](https://github.com/polhem-dev/polhem/pull/5))
- **寫入與讀取的記錄範圍。** 儲存時，主檔範圍以 UPDATE 或 DELETE 實際繫結的資料列檢查；拒絕變更自身 row id 的資料列；
  對照資料庫確認修改與刪除的明細列屬於同一個 payload 中、範圍內的主檔；新增或修改的主檔列儲存後留下的值，也要落在
  呼叫端的新增或修改範圍內。`GetList` 與 `GetCount` 只接受表單宣告過的過濾與排序欄位，且不接受受保護欄位；
  `GetLookup` 套用讀取範圍，除非業務物件把 `LookupAppliesRecordScope` 設為 `false`。規則說明見
  [權限與授權](../zh-TW/permission-authorization.md)。([#4](https://github.com/polhem-dev/polhem/pull/4))
- **經 API 取用定義。** 遠端 `GetDefine` 只提供明列的定義類型（用戶端呈現畫面所需的那些，列於
  `SystemBusinessObject.GetDefine`）；`SystemSettings`、`DatabaseSettings` 等部署設定只在行程內讀取。
  ([#4](https://github.com/polhem-dev/polhem/pull/4))
- **稽核規則**以 `ProgramSettings` 宣告的 ProgId 大小寫查找，與呼叫端使用的大小寫無關。
  ([#4](https://github.com/polhem-dev/polhem/pull/4))
- **傳輸。** Encoded 與 Encrypted 請求依請求解析出的 action 的參數型別解碼；用戶端宣告的型別名稱只用於一致性檢查。
  兩種 codec 解碼時套用同一個深度上限，巢狀的過濾條件也不例外。只有公開、非泛型、單一參數且不是屬性存取子的執行個體
  方法能被當成 action 呼叫，與 `POLHEM3001` 在建置時套用的規則相同。BCL 例外的訊息只留在伺服端的記錄
  （`JsonRpcExecutor.Logger`）；呼叫端得到每個錯誤碼固定的訊息，給使用者看的框架訊息以 `UserMessageException` 擲出。
  ([#6](https://github.com/polhem-dev/polhem/pull/6))
- **Plain 本文。** 過去 `Plain` 本文直接反序列化成業務物件方法的引數型別，呼叫端因此能設定該型別的任何公開成員，
  包括契約沒有宣告的成員。現在先讀成 action 的請求型別，再複製到引數，與 Encoded 路徑原本的做法相同；有一個閘門測試
  確保框架的引數型別沒有契約以外的成員。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **Session 與金鑰。** `CreateSession` 只接受本機呼叫。API 金鑰的 `CreateApiKey`、`SetApiKeyEnabled`、
  `SetApiKeyExpiry` 與其他會改變狀態的系統方法一樣受重放防護。資料庫異常記錄只有部署管理員能讀取。主金鑰檔與用戶端
  的 `apikey.txt` 以僅擁有者可存取的權限建立；`DatabaseSettings` 含密碼卻沒有 `ConfigEncryptionKey` 保護時會記錄警告。
  ([#5](https://github.com/polhem-dev/polhem/pull/5))
- **用戶端。** 用戶端拒絕伺服端宣告的 "none" 加密器，除非用戶端自己處於除錯模式；也不再沿用伺服端的除錯旗標與允許的
  型別命名空間。([#6](https://github.com/polhem-dev/polhem/pull/6))
- **DDL 與連線字串。** SQL Server 的字串預設值會被跳脫，其他預設值必須是該欄位型別的字面值；連線字串的佔位字透過
  `DbConnectionStringBuilder` 填入（`ConnectionStringTemplate`）。([#4](https://github.com/polhem-dev/polhem/pull/4))

### 行為變更

- **匿名呼叫。** 伺服端原本手動維護一份可以不帶 Bearer 標頭呼叫的方法清單，其他沒帶標頭的請求一律回 HTTP 401。現在
  沒帶標頭的請求就是匿名呼叫，只由 `[ApiAccessControl]` 決定；需要 session 的方法回應 JSON-RPC `-32001`
  （`AuthenticationRequiredException`），.NET 用戶端把它轉成 `UnauthorizedAccessException`。`RemoteApiProvider` 取得存取權杖後才送出
  該標頭，因此覆寫 `IsAuthorizationRequired` 以拒絕匿名請求的部署，不會被空的佔位權杖繞過。
  ([#6](https://github.com/polhem-dev/polhem/pull/6), [#18](https://github.com/polhem-dev/polhem/pull/18))
- **分頁。** 沒有分頁選項的 `GetList` 回傳第一頁，上限為 `PagingOptions.MaxPageSize`，不再回傳全部資料列。
  ([#4](https://github.com/polhem-dev/polhem/pull/4))
- **英文基底語言。** 內建定義檔、Avalonia 與 Blazor 的 UI 文字、框架訊息都以英文為基底文字，中文移到隨附的 `zh-TW`
  資源。標題、列舉、選單、規則訊息與框架文字共用同一條回退鏈（`LanguageFallback`）：要求的文化、其上層文化、部署預設，
  最後是基底文字。部署預設是 `CommonConfiguration.DefaultLanguage`，取代 `CommonConfiguration.DefaultLang` 與
  `BackendConfiguration.DefaultLanguage`，預設值仍是 `zh-TW`。登入回應帶有使用者的文化（`st_user.culture` 或部署
  預設），用戶端會採用，因此 `UserInfo.Culture` 在登入前是空字串，不再是 `zh-TW`。
  ([#15](https://github.com/polhem-dev/polhem/pull/15))
- **給使用者的訊息**帶有鍵值與參數，依 session 的文化解析；表單規則訊息解析 `{ProgId}.Rule.{RuleId}.Message`。數字與
  日期依使用者的文化顯示與剖析，wire 則維持與文化無關。([#15](https://github.com/polhem-dev/polhem/pull/15))
- **`CBool`** 只接受與語言無關的代碼（`1`、`T`、`TRUE`、`Y`、`YES`，不分大小寫）。中文的「是」「真」讓一種語言在
  與文化無關的轉換裡享有特例；使用者以自己語言輸入的值，應由 UI 轉換。
  ([#15](https://github.com/polhem-dev/polhem/pull/15))
- **設定。** `BackendComponents` 各項預設為空白，空白代表框架預設，因此設定檔不必寫出框架內部型別的名稱。
  `CacheProvider` 或元件型別名稱寫錯時，會在啟動時失敗並指出設定名稱，而不是之後才出現 null 參考。
  ([#8](https://github.com/polhem-dev/polhem/pull/8), [#11](https://github.com/polhem-dev/polhem/pull/11))
- **用戶端儲存。** 端點與 API 金鑰存成每位使用者本機應用程式資料資料夾下的 `endpoint.txt` 與 `apikey.txt`
  （`FileEndpointStorage`，現在位於 `Polhem.UI.Core` 並作為預設），因為組件旁的資料夾在 iOS 上唯讀、在 WebAssembly
  上會遺失。原本的 `{ExeName}.Settings.xml` 不再讀取。([#12](https://github.com/polhem-dev/polhem/pull/12))
- **Wire。** 經 MessagePack 傳輸的 `DataTable` 改寫成一份欄位表加上依位置排列的資料列，不再每列一份名稱／值對照。
  初始值不是 CLR 預設值的成員一律寫出，因此不論哪種 codec，缺少的成員都代表 CLR 預設值；Plain 請求依 JSON 種類繫結
  `object` 型別的過濾與參數值，所以 Plain、JSON 與 MessagePack 傳遞相同的值。TypeScript 用戶端
  `polhem-connector-js` 跟著合約變更更新（`userId`、移除的 `oneTime`、`culture`、`AuditLog…` 回應型別名稱）。
  ([#9](https://github.com/polhem-dev/polhem/pull/9), [#12](https://github.com/polhem-dev/polhem/pull/12))
- **快取中的定義**不再因為被序列化而改變。每個物件的序列化狀態已移除；空集合改由唯讀的 `XSpecified` 屬性省略，
  iOS 上僅用反射的 `XmlSerializer` 接受這種寫法。內建定義檔重新序列化後逐位元組相同。
  ([#8](https://github.com/polhem-dev/polhem/pull/8))
- **預設值運算式。** 建立新列時（伺服端的 `GetNewData` 或 UI 用戶端），欄位的 `DefaultValueExpression` 現在優先於
  字面值 `DefaultValue` 與依型別的初值（0、空字串、今天、`Guid.Empty`）。過去初值讓大多數欄位不是空的，所以日期欄位
  上的 `Today()` 之類的運算式從來不會執行。存檔時運算式仍只填空的欄位，使用者輸入的值會保留。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **定義載入器。** `ClientInfo.UseDefinitionLoader` 預設開啟，Avalonia 畫面不需任何設定，就會顯示使用者語言的
  標題、租戶客製的版面與公司的數值格式；設為 `false` 則照原樣呈現定義，省下載入器額外的往返。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **啟動檢查。** 以 `AddPolhemFramework` 建立的 host 會在其他 hosted service 啟動前呼叫
  `IDatabaseSettingsProvider.ValidateRequired`，因此缺少 `common` 資料庫項目的部署會在啟動時失敗，而不是等到第一個
  碰到框架資料表的請求。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **協定錯誤。** 解析不到任何方法的 action 名稱回應 JSON-RPC `-32601`（`MethodNotFound`），無法讀成方法型別的
  `Plain` 本文回應 `-32602`（`InvalidParams`），各有固定訊息。過去兩者都以其他錯誤碼出現，這兩個錯誤碼沒有產生者。
  ([#22](https://github.com/polhem-dev/polhem/pull/22))

### 破壞性 API 變更

公開 API 在任何版本以 Polhem 名義出貨之前一次定案。它現在遵循的規則記錄在
[ADR-046](../adr/adr-046-api-evolution-policies-for-1-0.zh-TW.md)。

- **Sealed。** 不是為繼承而設計的類別改為 sealed，日後的版本才能調整其內部，而不會弄壞沒人預期的子類別。擴充透過介面與
  文件記載的基底類別，這些仍可繼承：業務物件、repository 與集合的基底類別、`TextEdit`、`DateEdit`、`ListView`、
  `FormView`、各 connector 與 `AuditRuleBusinessObject`。`KeyCollectionBase<T>` 改為 abstract。
  ([#13](https://github.com/polhem-dev/polhem/pull/13))
- **名稱。** 型別依其本身命名，而不是依框架名稱或縮寫：`IBusinessObjectContext`、`LanguageResourceStringLocalizer<T>`、
  `AuditLog…` 系列、`PermissionActions`（flags 列舉）、`NullLogWriter`、`UserId`。沒有零值的列舉加上 `None = 0`。
  ([#10](https://github.com/polhem-dev/polhem/pull/10), [#11](https://github.com/polhem-dev/polhem/pull/11))
- **歸屬。** 型別搬到負責該職責的組件：`DeploymentAuthorizationService` 與 `EmployeeContextResolver` 移到
  `Polhem.Business`，權限能力解析器移到 `Polhem.Api.Client` 讓兩種 UI head 都能使用，`FileEndpointStorage` 移到
  `Polhem.UI.Core`。`Polhem.ObjectCaching` 不再參考 `Polhem.Repository.Abstractions`。
  ([#11](https://github.com/polhem-dev/polhem/pull/11), [#12](https://github.com/polhem-dev/polhem/pull/12))
- **用戶端介面。** 本機 provider 與 connector 接收 `IServiceProvider`，不再從靜態屬性讀取；每個 session 的狀態放在
  `ApiSessionContext`。所有公開的非同步成員都多一個結尾的 `CancellationToken`，一路傳到 `HttpClient`；請求被取消時
  伺服端回應 499。
  ([#10](https://github.com/polhem-dev/polhem/pull/10), [#11](https://github.com/polhem-dev/polhem/pull/11),
  [#12](https://github.com/polhem-dev/polhem/pull/12))
- **重放儲存。** `IReplayWindowStore` 改為單一原子操作 `TryAcceptAsync`，多個伺服端節點共用的儲存才能正確實作。
  ([#12](https://github.com/polhem-dev/polhem/pull/12))
- **Codec。** 自訂 codec 以 `ApiServiceOptions.RegisterPayloadCodec` 加入；請求未宣告 codec 時使用的仍是 MessagePack，
  因為所有既有用戶端都依賴它。([#10](https://github.com/polhem-dev/polhem/pull/10))
- **快取型別**中來自資料庫的改為 init-only 屬性；session 的公司範圍改為單一不可變的 `SessionCompanyScope`，一次寫入
  整個替換，讀取端不會看到只改了一半的狀態。
  ([#8](https://github.com/polhem-dev/polhem/pull/8), [#10](https://github.com/polhem-dev/polhem/pull/10))
- **規則處理器。** `IFormRuleProcessor` 新增上述預設值變更所需的 `ApplyNewRowDefaults`。ADR-046 允許可由主機
  替換的介面增加成員；其他實作必須補上。([#22](https://github.com/polhem-dev/polhem/pull/22))

### 移除

1.0 不需要的相容性殘留、死碼與沒有呼叫端的公開型別已移除，實作型別改為 internal，讓 1.0 不必為它們承諾。較大的幾塊是
自行實作的追蹤子系統、序列化狀態介面、連同 `DbUpgradeAction` 的舊結構比對路徑、一次性 session 旗標，以及同步的
`JsonRpcExecutor.Execute`。框架 repository 的實作改為 internal；主機程式使用 `I*Repository` 介面。未使用的設定型別
`ClientSettings`、`EndpointItem`、`EndpointItemCollection` 最後移除，因為它們描述的設定檔已由 `FileEndpointStorage` 取代。
([#8](https://github.com/polhem-dev/polhem/pull/8), [#10](https://github.com/polhem-dev/polhem/pull/10),
[#11](https://github.com/polhem-dev/polhem/pull/11), [#12](https://github.com/polhem-dev/polhem/pull/12),
[#22](https://github.com/polhem-dev/polhem/pull/22))

### 效能

變更當時的量測：

- 帶檔案 token 的定義快取命中，由 1,216 ns 降到 62 ns，因為每個項目每秒最多檢查一次來源檔。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- Gzip 改用最快等級，壓縮 570 KB 的 payload 由 1.67 ms 降到 0.48 ms，輸出由 80 KB 變成 110 KB。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- `AesCbcHmacCryptor` 加密 173 KB 的 payload，配置由 694 KB 降到 174 KB，輸出格式不變。
  ([#14](https://github.com/polhem-dev/polhem/pull/14))
- 快取每個請求的反射結果後，存取控制查找由 506 ns 降到 20 ns。([#14](https://github.com/polhem-dev/polhem/pull/14))
- 20 欄、10,000 列的 `DataTable` 經 MessagePack：原始位元組少 57%、壓縮後少 10%、序列化時間少 86%、配置少 83%。
  ([#12](https://github.com/polhem-dev/polhem/pull/12))
- 稽核批次寫入器以單一交易寫入一批。([#14](https://github.com/polhem-dev/polhem/pull/14))

### 平台支援

- **修剪。** Polhem 支援不修剪與部分修剪的建置。使用端專案以 NativeAOT 發佈、以 `TrimMode=full` 修剪，或停用
  System.Text.Json 反射時，`POLHEM9004` 會發出警告；把 `PolhemSuppressTrimSupportWarning` 設為 `true` 可關閉。
  `Polhem.Expressions` 隨附 ILLink descriptor，行動端預設的修剪會保留運算式以反射取用的成員。
  ([#7](https://github.com/polhem-dev/polhem/pull/7), [#17](https://github.com/polhem-dev/polhem/pull/17))
- **行動端與瀏覽器。** `LookupDialog` 與 `RowEditDialog` 只在桌面開原生視窗，其他平台一律使用覆蓋層（overlay host），
  因此 lookup 在 iOS、Android 與瀏覽器都能使用。MessagePack 值格式器不需動態程式碼即可處理 Polhem 列舉與巢狀的
  `ParameterCollection`；HTTP 用戶端在瀏覽器、Android 與 Apple 行動端 head 使用平台預設的處理器。
  ([#7](https://github.com/polhem-dev/polhem/pull/7), [#17](https://github.com/polhem-dev/polhem/pull/17))

### 修正

- **重建時縮小欄位。** `UpgradeOptions.AllowColumnNarrowing` 過去只在 `ALTER` 路徑檢查，因此重建資料表（SQLite 上的
  任何欄位變更）可能在未開啟選項時縮小欄位並截斷資料。重建路徑現在套用同樣的檢查。([#22](https://github.com/polhem-dev/polhem/pull/22))
- **關聯 JOIN。** 表單資料表沒有 `DbTableName` 時，產生的 JOIN 使用空白的資料表名稱；現在與 SQL 建構器其他部分一樣
  改用 `TableName`。([#22](https://github.com/polhem-dev/polhem/pull/22))

## 不變的部分

- 套件的切分與目標框架 `net10.0`。
- 框架資料表的名稱，維持 `st_` 開頭。唯一的欄位變更是〈安全性〉提到的四個 `st_log_*` 表中，`access_token` 改為
  `token_fingerprint`；舊欄位該怎麼處理，見 README。
