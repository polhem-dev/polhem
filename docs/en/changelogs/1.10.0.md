# Polhem 1.10.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.10.0.md)

This file holds the details behind the `[Unreleased]` entry in [CHANGELOG.md](../../../CHANGELOG.md), which becomes
`[1.10.0]` when it is released.

This version gives the Blazor Server head the field editors the Avalonia head has, with the same names, the same
contract and the same behavior, so a form is built and extended the same way in both. The rules the two heads share
move into `Polhem.UI.Core`. The wire format is the one of 1.9.0, so a 1.9.0 client and a 1.10.0 server, or the other
way round, talk to each other.

## New features and changes

### Field editors for Blazor Server

`Polhem.Web.Blazor.Server.Controls.Editors` holds one component per `ControlType`: `TextEdit`, `MemoEdit`,
`NumericEdit`, `TimeEdit`, `DateTimeEdit`, `DateEdit`, `YearMonthEdit`, `CheckEdit`, `DropDownEdit` and `ButtonEdit`.
They carry the
names of the Avalonia field editors and implement the same `IFieldEditor` contract (`Bind`, `Unbind`,
`SetControlState`, `FieldName`, `FieldValue`), and they behave the same way:

- The value is committed when the user leaves the input or presses Enter, not per keystroke.
- The editor applies the schema field's metadata itself: `MaxLength`, `ListItems`, the number format.
- Whether it accepts input follows the form mode, the layout field's `ReadOnly` and its `AllowEditModes`.
- A value written by code, or a reload of the data object, refreshes the editor.
- `NumericEdit` shows the formatted value at rest and the full-precision value while focused, and keeps the last valid
  value when the input does not parse; `TimeEdit` stores `HH:mm`.

An editor binds through an explicit `Bind`, else its `DataObject` parameter, else an enclosing `FormScope`:

```razor
<FormScope DataObject="dataObject" FormMode="SingleFormMode.Edit">
    <TextEdit FieldName="emp_name" />
    <NumericEdit LayoutField="amountField" />
</FormScope>
```

A custom editor derives from `FieldEditorBase` and overrides `RefreshFromSource` and, when it needs schema metadata,
`ApplyMetadata`. `FieldEditorFactory.GetEditorType` maps a `ControlType` to its editor type.

The editors render the class `polhem-field-editor`, a modifier per editor (such as `polhem-field-editor--numeric`) and
`polhem-field-editor--readonly` when they do not accept input; the package ships no CSS. The read-only state of the
date, date-time and drop-down editors shows the value as text in the user's culture, as the Avalonia editors do.

`FormDataObject` gains what the editors need: `GetField` and `SetField` for a given row, `GetFormField` for a table
and field, and the events `FieldValueChanged`, `IsDirtyChanged` and `DataSetReplaced`. Writing the value a field
already holds no longer marks the object dirty.

### Lookup in Blazor Server

A `ButtonEdit` bound to a field with a `RelationProgId` runs the lookup flow of the Avalonia `ButtonEdit`: the input
shows the field's display fields (for example `D01 - Engineering`) and is read-only, the button opens `LookupDialog`,
the chosen row's `sys_rowid` and mapped fields are written through `FormDataObject.ApplyLookupSelection`, and Delete or
Backspace clears them through `ClearLookupSelection`. Without a `RelationProgId` the button raises `ButtonClick`.
`LookupFailed` reports a lookup that cannot load or a selection that cannot be written; without a handler the message
is shown as the input's tooltip.

`LookupDialog` is a modal overlay over `LookupPanel`, which has a search box, a list over the target form's lookup
layout and OK / Cancel; a double-click commits a row. The dialog takes the target schema and connector from its
`Schema` and `Connector` parameters, else from an `IFormDefinitionSource` and an `IFormApiConnectorFactory` registered
in the container, else from the circuit's `PolhemApiClient`, loading the schema the way `FormPage` loads its own. An
application with a Polhem backend registers nothing; one without registers its own source, scoped:

```csharp
builder.Services.AddScoped<IFormDefinitionSource, MyDefinitionSource>();
builder.Services.AddScoped<IFormApiConnectorFactory, MyConnectorFactory>();
```

`DynamicGrid` gains `OnRowActivated` (a double-click) and `SelectedRowId` (the row to highlight), which the panel uses.

### Live computation in Blazor Server

`FormPage` recomputes computed fields (`ValueExpression`) as the user edits and evaluates default-value expressions
for a new record, the way the Avalonia `FormView` does. The rules are the new `FormLiveComputationEngine` in
`Polhem.UI.Core`, which both heads now drive, so a value previewed in either head matches what the server writes on
save. It takes the expression evaluator and the user's time zone from its caller; the Avalonia `FormLiveComputation`
keeps its public shape over it.

The new `Polhem.Web.Blazor.Server.DataObjects.FormLiveComputation` brings that engine to a page of its own, with
the shared DynamicExpresso evaluator by default. Pass the circuit's time zone:

```csharp
var live = new FormLiveComputation(schema, timeZoneProvider: () => client.Session.Credentials.UserTimeZoneId);
dataObject.FieldValueChanged += (_, e) =>
{
    if (!live.IsRecomputing) live.Recompute(e.TableName, e.FieldName, e.Row);
};
```

`FormPage` rounds the preview with framework-default decimal places; the server rounds authoritatively on save.
`Polhem.Web.Blazor.Server` now references `Polhem.Expressions` for the default evaluator.

The Blazor `FormDataObject` gains the row lifecycle of the Avalonia one: a new row is seeded with the schema's
defaults (a fresh `sys_rowid`, the link to the master, non-null values by type), `RowAdded` and `RowDeleted` report
row changes, and `BeginRowEdit` / `CommitRowEdit` / `CancelRowEdit` buffer one row's edits, which raise
`RowEditFieldChanged` until the commit publishes them through `FieldValueChanged`.

### FormPage follows the form mode

`FormPage` edits a record in Add mode after **New**, in Edit mode after a row is loaded or saved, and shows View mode
while there is no record, so a field limited to Add (a key, for example) is read-only once the record is saved.

### Field rules shared by both heads

`Polhem.UI.Core.Fields` holds the rules the field editors of both heads use, so they cannot drift apart:

- `FieldEditRules.AllowsEdit`: the form mode, the layout read-only flag and `AllowEditModes`.
- `FieldValueFormatter.Format`: the display of a value in the user's culture.
- `NumericFieldFormat`: number format resolution, including currency and unit decimals, display, input parsing and
  the value written back.
- `DateTimeFieldFormat`: the display, input and binding-string rules of a date-and-time field.
- `FormLiveComputationEngine`: the live recomputation of computed fields and new-row defaults.
- `LookupFieldRules` and `LookupDisplay`: whether a field looks up, which program it opens, which fields it shows and
  how they are joined, and how a selection is written back or cleared.

## Breaking changes

### `DynamicForm` is replaced by `FormLayoutPresenter`

- **Affects:** Blazor Server applications that render `DynamicForm` themselves. Applications that use `FormPage` only
  need nothing.
- **Before:** `Polhem.Web.Blazor.Server.Components.DynamicForm` rendered the master sections with plain inputs and the
  CSS classes `polhem-dynamic-form`, `polhem-dynamic-form__*` and `polhem-dynamic-form__input--*`. It followed only
  each field's `ReadOnly`.
- **Now:** `Polhem.Web.Blazor.Server.Controls.FormLayoutPresenter` renders the same sections through the field
  editors. It takes the same `Layout`, `DataObject` and `IdPrefix` parameters, plus `FormMode` and `RoundingContext`.
- **Migrate:**
  1. Replace `<DynamicForm ...>` with `<FormLayoutPresenter ...>` and add `@using Polhem.Web.Blazor.Server.Controls`.
  2. Pass `FormMode` when the page has a view or add state; it defaults to Edit, which matches the old behavior for
     fields that are not read-only.
  3. Rename the CSS selectors: `polhem-dynamic-form` → `polhem-form-layout` (and its `__section`,
     `__section-caption`, `__grid`, `__field` and `__label` parts); `polhem-dynamic-form__input` →
     `polhem-field-editor`; `polhem-dynamic-form__input--<kind>` → `polhem-field-editor--<kind>`.
