# Polhem 1.12.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.12.1.md)

This file holds the details behind the `[1.12.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version fixes what building and recording with the 1.12.0 Blazor packages turned up: relation chains three
relations deep, list and layout details of relation fields, how unformatted numbers and editable dates show, and the
grid and editor behavior of the MudBlazor and Fluent UI packages. DefineEditor gains the web preview inside the editor.
It has no breaking change, and its wire format is the one of 1.12.0.

## New features and changes

### DefineEditor: the web preview inside the editor

The FormLayout editor's preview has a **Web** option. It shows the same Blazor page as **Open in browser**, drawn by
the MudBlazor components, inside the preview instead of in a browser window, and follows unsaved edits and the View
mode, Phone width and Field names options. Each open layout keeps its own choice; a new one starts with the Avalonia
preview.

The **Focus on the web preview** button beside the layout buttons arranges the window for that work in one step: the
tree beside the web preview only, with the side bar hidden and the property grid in the **Properties…** dialog.
Pressing it again puts back the layout, the preview and the side bar as they were.

The page is drawn by the operating system's web engine: WebView2 on Windows, WKWebView on macOS, and WPE WebKit or
WebKitGTK on Linux. Its date and time inputs look the way that engine draws them, so the final check of how a browser
shows a form is still **Open in browser**, which is unchanged.

The engine has to be installed: the WebView2 Runtime on Windows (part of Windows 11, a separate install on some
Windows 10 machines) and WebKitGTK 4.1 on Linux (`libwebkit2gtk-4.1-0` on Debian and Ubuntu). When it is missing, the
preview says why and offers the browser instead; the rest of the editor is unaffected. The web view keeps no data in
the user's profile.

### DefineEditor: icon toggles for the layout and preview options

The FormLayout editor's buttons that choose what the right-hand side shows, and the preview's View mode, Phone width
and Field names options, are icon toggles in the style of VS Code, with their names in tooltips.

### Blazor packages: grid editing

- **Enter commits a cell.** Enter in an in-cell editor did nothing in the MudBlazor and Fluent UI grids, while the
  Avalonia grid commits on it. It now leaves the input, which writes the value, closes the editor and rests the focus
  on the cell, as Escape does without writing. A multi-line input keeps Enter for a new line, and a drop-down for its
  list.
- **A click made while a cell opens is kept.** When a cell opened, the focus fell back to the page until the script
  that focuses the editor arrived, and a click elsewhere in that moment was swallowed: the editor kept the typed text
  and the value was never written. The click now waits for the editor and is then replayed.

### Blazor packages: how fields look

- **Editable dates follow the user's culture.** A date showed as `yyyy-MM-dd` while it could be edited and in the
  user's culture once read-only. The date and year-month pickers, and the date part of the date-time editor, now show
  the culture's pattern too; the value is still written back in the invariant form.
- **A read-only editor keeps only its underline**, as in the Avalonia controls, so a record viewed read-only no longer
  looks editable. In MudBlazor the underline lines up with the bottom edge of an editable editor beside it.
- **MudBlazor pages scroll in a host that also references Fluent UI.** Fluent UI's default stylesheet hides the body's
  overflow in every Blazor app of such a host; the rule that lets the shell's page scroll now lives in the shared
  stylesheet both UI packages import.
- **Fluent UI:** the lookup and the grid commands are drawn as icon buttons, as in the MudBlazor package; the numeric
  editor is right-aligned; a grid no longer shows a vertical scrollbar over rows that fit; and a column the layout
  gives no width shares the grid's spare width instead of keeping 120px.

### Avalonia

- Grid text cells are centered vertically, like the drop-down, date and check box cells beside them, and a numeric
  column's text and in-cell editor are right-aligned, as in the Blazor grids.
- The lookup button of `ButtonEdit` is named with the Search text, and `DateEdit` (and `YearMonthEdit`) take the bound
  field's caption as their accessible name unless the application set one, so assistive technology no longer reads a
  type name.

### Templates: input methods in the Avalonia browser head

The browser head of the `polhem-avalonia` template accepts input methods such as Boshiamy. Avalonia.Browser inserted
each key of a composition as text and ignored the chosen character; `wwwroot/ime-input-bridge.js`, loaded by
`main.js`, stops those keys and forwards the character. An existing project copies both from a newly generated one.

### Relation chains three relations deep

A relation field may come from a related form's own relation field, which may come from another one in turn. A
chain three relations deep, such as an order's employee, that employee's department and its manager, failed when the
query read it: saving the record succeeded, but reading it back or listing the form stopped with
"Field mapping for '…' is null." Such fields are now read under the outer form's field name at any depth, as
[FormSchema-driven data access](../definitions/formschema-data-access.md) describes.

### Syncing a form lists a foreign key by its name

When **Sync TableSchema and FormLayout** adds a new field to the form's `ListFields`, a foreign key is now listed by
the last of its display fields, its related name when it maps `sys_name`, because a list cannot show the row id the
key holds. A foreign key without display fields is not listed. Other fields are listed as before.

### Relation fields are read-only in a generated layout

`FormLayoutGenerator` marks every relation field (`Type="RelationField"`) read-only, in the master section and in
detail grids. Its value is filled by a lookup or by the query join, and no table stores it, so an edit was lost on the
next read. Layouts generated before keep what they say; set `ReadOnly` on such a field by hand, or regenerate.

### Unformatted numbers drop the trailing zeros of their scale

A database returns a decimal with its column's scale, so a field without a number format showed `0.0000` for a value
read back and `0` for the same value typed or defaulted, in the edit screen and in grids. Such a value now shows the
smallest exact form in the user's culture (`0`, `18.5`). A field with a number format, a number kind or a display
format is unchanged.

### Lookup-only rows keep a relation field when the source is one

When a row of DefineEditor's relation dialog is switched to **Lookup only**, the new destination field used to become
a stored field whatever the source was. It now follows the source: a column of the related form is copied into a
stored field, as before, and a relation field of the related form stays a relation field, which the form fills
through its own relation (the employee and department example in
[FormSchema-driven data access](../definitions/formschema-data-access.md) §3.4).

## Breaking changes

None.
