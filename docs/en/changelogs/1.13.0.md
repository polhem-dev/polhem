# Polhem 1.13.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.13.0.md)

This file holds the details behind the `[Unreleased]` entry in [CHANGELOG.md](../../../CHANGELOG.md), which becomes
1.13.0 when it is released. Its wire format is the one of 1.12.0.

## New features and changes

### DefineEditor: the web preview inside the editor

The FormLayout editor's preview has a **Web** option. It shows the same Blazor page as **Open in browser**, drawn by
the MudBlazor components, inside the preview instead of in a browser window, and follows unsaved edits and the View
mode, Phone width and Field names options. Each open layout keeps its own choice; a new one starts with the Avalonia
preview.

The **Focus on the web preview** button beside the layout buttons arranges the window for that work in one step: the
tree beside the web preview only, with the side bar hidden and the property grid in the **Properties…** dialog.
Pressing it again puts back the layout, the preview and the side bar as they were.

The page is drawn by the operating system's web engine: WebView2 on Windows, WKWebView on macOS, and WPE WebKit or
WebKitGTK on Linux. Its date and time inputs look the way that engine draws them, so the final check of how a browser
shows a form is still **Open in browser**, which is unchanged.

The engine has to be installed: the WebView2 Runtime on Windows (part of Windows 11, a separate install on some
Windows 10 machines) and WebKitGTK 4.1 on Linux (`libwebkit2gtk-4.1-0` on Debian and Ubuntu). When it is missing, the
preview says why and offers the browser instead; the rest of the editor is unaffected. The web view keeps no data in
the user's profile.

### Relation chains three relations deep

A relation field may come from a related form's own relation field, which may come from another one in turn. A
chain three relations deep, such as an order's employee, that employee's department and its manager, failed when the
query read it: saving the record succeeded, but reading it back or listing the form stopped with
"Field mapping for '…' is null." Such fields are now read under the outer form's field name at any depth, as
[FormSchema-driven data access](../definitions/formschema-data-access.md) describes.

### Syncing a form lists a foreign key by its name

When **Sync TableSchema and FormLayout** adds a new field to the form's `ListFields`, a foreign key is now listed by
the last of its display fields, its related name when it maps `sys_name`, because a list cannot show the row id the
key holds. A foreign key without display fields is not listed. Other fields are listed as before.

### Relation fields are read-only in a generated layout

`FormLayoutGenerator` marks every relation field (`Type="RelationField"`) read-only, in the master section and in
detail grids. Its value is filled by a lookup or by the query join, and no table stores it, so an edit was lost on the
next read. Layouts generated before keep what they say; set `ReadOnly` on such a field by hand, or regenerate.

## Breaking changes

None.
