# Polhem 1.4.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.4.0.md)

This file holds the details behind the `[1.4.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version adds object trees and a property grid, the building blocks DefineEditor now uses for its document trees
and property panels, and removes three public types that the move to Polhem.JsonRpc in 1.2.0 had left without a job.
Building against it needs the .NET SDK 10.0.400 or later. The wire is unchanged: a 1.4.0 client and a 1.3.x server,
or the other way round, talk to each other, so servers and clients do not have to upgrade together.

## New features and changes

### Object trees

`ObjectTreeBuilder` (`Polhem.Definition.ObjectTree`) builds a UI-independent tree of `ObjectTreeNode` from an object
graph, driven by `[TreeNode]` and `[TreeNodeIgnore]`. It is meant for desktop tools.

- The builder follows the properties whose values carry `[TreeNode]`. It skips the properties that the collection base
  types declare, so the back references of collection items do not become nodes. `[Browsable(false)]` plays no part,
  because the definition types put it on their collection properties to keep them out of property grids.
- Each object becomes one node, which together with `ObjectTreeOptions.MaxDepth` stops cycles.
  `ObjectTreeOptions.ExpandDepth` sets how many levels of a built tree start expanded.
- Nodes raise change notifications, so a UI head can bind them. `ObjectTreeNode.IsExpanded` holds the expanded state.
- `PropertyFilter`, `NodeBuilt` and `LabelTranslator` let the consumer narrow, extend and translate the tree.
- `ObjectTreeNode(object, Func<object, string>, bool)` creates a node whose label is computed from its value and
  recomputed on `Refresh`, for nodes a consumer adds that must follow a change of display language.
- `TreeNodeAttribute.GetDisplayText(object, Func<string, string>?)` translates the display format before the property
  values are put into it.
- `ITreeNodeCommandProvider` and `TreeNodeCommand` describe UI-independent commands for a tree node.
- `ITreeNodeDragDropHandler` and `TreeNodeDropPosition` describe which tree nodes can be dragged and where they may
  land.

`ObjectTreeView` (`Polhem.UI.Avalonia`) is a `TreeView` that shows an `ObjectTreeNode` tree. Set `RootNode`, and
optionally `IconSelector` for an icon before each label; each item's `IsExpanded` binds both ways to the node.
`ObjectTreeView.CommandProvider` fills the tree's context menu with the selected node's commands each time it opens.
`ObjectTreeView.DragDropHandler` lets the user drop a node before or after another, shows where it will land, and moves
the node in the tree after the handler has moved the objects.

### The `[TreeNode]` annotations of the definition types

The definition types follow one rule for folders: a collection is shown as a folder when its owner has more than one
annotated collection, and directly under the owner otherwise. The Sections and Details of `FormLayout` and the Tables
and Rules of `FormSchema` become folders; the Fields of `FormTable` and the Entries of `LanguageEnum` no longer are.
Every annotated object type now names the properties its label is formatted from, matching its `ToString()`, and
`IndexField` with its collection gains an annotation so an index lists its fields.

### The property grid

`PropertyGridControl` (`Polhem.UI.Avalonia`) shows the properties of `SelectedObject` as labels and editors driven by
the ComponentModel annotations its properties carry: `[Category]`, `[Description]`, `[DisplayName]`, `[Browsable]`,
`[DefaultValue]`, `[TypeConverter]` and `[PasswordPropertyText]`.

- A value that differs from its default is shown in bold, and the label's context menu resets it.
  `PropertyValueChanged` reports each write.
- `LabelTranslator` translates the labels. It receives each text as a `PropertyGridText` with its
  `PropertyGridTextKind` (category, display name, description, item label), the type it belongs to and the property
  name, so a description can be looked up by the property. `Refresh` reads the object and translates again.
- A property marked `[PasswordPropertyText(true)]` is masked.
- `ValueSuggestionProvider` turns a string property into a drop-down of suggested values that still takes typed text.
- `PropertyFilter` narrows the rows, for example to one category.
- A collection property opens in `CollectionEditDialog`, or in whatever `CollectionEditorProvider` supplies. Nested
  objects are shown read-only.
- The control reads types through `TypeDescriptor`, which trimming does not preserve, so it is meant for desktop tools,
  not trimmed mobile heads.

`CollectionEditDialog` and `CollectionEditContext` (`Polhem.UI.Avalonia`) form a modal dialog that edits a collection
property, with the items in a list (add, delete, move up and down) and a `PropertyGridControl` for the selected one.
It edits copies of the items and OK replaces the collection's items with them, so references to the old items must be
read again; Cancel leaves the collection untouched. In a keyed collection a new item gets a free key, and OK refuses a
key used twice.

`PolhemUIText` gains `ResetValue`, `CollectionSummary`, `MoveUp`, `MoveDown`, `CollectionKeyMissing`,
`CollectionKeyDuplicate` and `CollectionKeyTaken`, the text keys the property grid and the collection dialog use. When
the grid writes a key that another item of the collection already has, it shows `CollectionKeyTaken` in the UI
language instead of the collection's English exception message.

### Definition types annotated for property grids

- Every property a property grid shows on a definition type now declares `[Category]` and `[Description]`, so it
  groups and describes itself instead of falling into `Misc`.
- The collections an editor shows as tree nodes (the tables and rules of a form schema, the items of the settings
  files, a language resource's items and enums) and `SessionUser.AccessToken` are marked `[Browsable(false)]`.
- The encryption keys of `SecurityKeySettings` are marked `[PasswordPropertyText(true)]`, so a property grid masks
  them.
- `LanguageItem.Key` is marked browsable again: the override inherited `[Browsable(false)]` from the base key.
- `PermissionRule.Action` declares a type converter whose exclusive standard values are the single actions, so a
  property grid offers a drop-down of one action rather than a text box for combined flags.

None of these attributes changes the XML or the wire form.

### Dependencies

The package dependencies move to MessagePack 3.1.11, DynamicExpresso.Core 2.19.6 and the 10.0.12 releases of the
`Microsoft.Extensions` packages the framework references. These are the lowest versions NuGet resolves for an
application. The analyzers move to Microsoft.CodeAnalysis 5.9; see
[The .NET SDK 10.0.400 or later is required](#the-net-sdk-100400-or-later-is-required).

### Fixes

- **The signed-in user's culture applies again under Avalonia 12.1.** Avalonia 12.1
  ([AvaloniaUI/Avalonia#21627](https://github.com/AvaloniaUI/Avalonia/pull/21627)) writes the UI thread's live culture
  back after every dispatcher operation. `ClientInfo` sets the user's culture inside the async sign-in handler, and the
  runtime reverted that change at the next `await`, so an en-US account on a Chinese operating system saw the
  operating system's language in captions and date formats. `ClientInfo` now also posts the culture to the caller's
  synchronization context, where a plain callback sets it. `Polhem.UI.Avalonia` accepts Avalonia 12.0.0 and later, so
  an application that moved to 12.1 on its own was affected with 1.3.x as well.
  ([#95](https://github.com/polhem-dev/polhem/pull/95))

### Samples and tools

- DefineEditor builds every document tree with `ObjectTreeBuilder`, shows it in `ObjectTreeView` and takes its context
  menus from an `ITreeNodeCommandProvider` per document type, in place of its hand-written tree nodes. Labels follow
  the `[TreeNode]` annotations, and folders no longer show a count. In every editor a node can be dragged before or
  after a sibling to reorder the collection that holds it. Folder, root and group labels follow the editor's language
  and switch with it.
- DefineEditor shows the selected object in a `PropertyGridControl` instead of hand-written property panels, so every
  browsable property is editable, grouped by `[Category]` and described by `[Description]`. Categories and
  descriptions are translated into Traditional Chinese and follow the editor's language; property names stay as
  written. A field's ListItems are edited in the grid's collection dialog rather than as tree nodes; selecting a
  field's Relation or Lookup group shows its Relation properties, and form ids, mapping fields and the language enums
  of the solution are offered as suggestions. Pasting a connection string moves to a dialog on a database server's or
  item's context menu, and its preview no longer shows the password. Renaming an object relabels its tree node at once.
- Avalonia.DemoCenter adds a Property Grid case: `PropertyGridControl` over a `FormField`, a `DbField`, a
  `DatabaseServer`, a `PermissionRule`, `BackendConfiguration` and a demo object of groups with entries, with its
  display options, suggested form ids and a log of `PropertyValueChanged`. The FormField's `ListItems` open in
  `CollectionEditDialog`, and a group's entries open a second dialog from inside the first.
- The Avalonia heads (DefineEditor, Avalonia.DemoCenter, the Northwind heads) run Avalonia 12.1 with Semi.Avalonia
  12.1; `Polhem.UI.Avalonia` keeps Avalonia 12.0.0 as its lowest version. The Northwind iOS head requires iOS 15.0,
  the lowest that the iOS workload of the .NET SDK 10.0.400 accepts. Xamarin.AndroidX.Core.SplashScreen stays at
  1.0.1.15 in the Northwind Android head: 1.2.0.3 brings AndroidX Lifecycle 2.11, outside the range Avalonia.Android
  depends on, and the Android build fails. ([#95](https://github.com/polhem-dev/polhem/pull/95),
  [#96](https://github.com/polhem-dev/polhem/pull/96))

## Breaking changes

### The .NET SDK 10.0.400 or later is required

- **Affects:** every project that references the `Polhem.Definition` package, directly or through another Polhem
  package.
- **Before:** an older .NET 10 SDK built projects that reference the Polhem packages.
- **Now:** the Roslyn analyzers shipped in the `Polhem.Definition` package are built against Microsoft.CodeAnalysis
  5.9. The version an analyzer is built against is the lowest compiler that can load it, so an older compiler reports
  `CS9057` instead of running the analyzers, which fails the build under `TreatWarningsAsErrors`.
- **Migrate:**
  1. Build with the .NET SDK 10.0.400 or later; check with `dotnet --version`.
  2. Move a `global.json` that pins an older SDK band as well. In CI, `actions/setup-dotnet` with
     `dotnet-version: 10.0.x` already resolves to a 10.0.4xx SDK.
- **Background:** [#96](https://github.com/polhem-dev/polhem/pull/96)

### Leftovers of the move to Polhem.JsonRpc are removed

- **Affects:** code that names `Polhem.Api.Core.Messages.PayloadFormat` (for example in a connector's `ExecuteAsync`
  call or an `ApiCallContext`), calls `Polhem.Core.Serialization.Gzip`, or throws or catches
  `Polhem.Api.Core.JsonRpc.JsonRpcException`; and assemblies built against an earlier 1.x that use these types.
- **Before:** the three types were public, although the move to Polhem.JsonRpc in 1.2.0 had left them without a job:
  `Polhem.JsonRpc.Payload` has a format enum with the same members and values, `Gzip` was a thin wrapper of
  `GZipStream` that nothing in the framework called since 1.2.0, and the framework has not thrown `JsonRpcException`
  since 1.2.0.
- **Now:** the three types are removed. The connectors' `ExecuteAsync` and `ApiCallContext` take
  `Polhem.JsonRpc.Payload.PayloadFormat`, which has the same members and values. The wire is unchanged.
- **Migrate:**

  | Removed | Replacement |
  |---------|-------------|
  | `Polhem.Api.Core.Messages.PayloadFormat` | `Polhem.JsonRpc.Payload.PayloadFormat`: replace `using Polhem.Api.Core.Messages;` with `using Polhem.JsonRpc.Payload;` where `PayloadFormat` is named |
  | `Polhem.Core.Serialization.Gzip` | `System.IO.Compression.GZipStream`, used directly |
  | `Polhem.Api.Core.JsonRpc.JsonRpcException` | `UserMessageException`, for a business object that threw it to show a message; it travels under the same code (`-32099`), so clients see no difference |

  Then recompile everything that references the Polhem packages: assemblies built against an earlier 1.x that use the
  removed types fail at run time.
- **Background:** the removal of `PayloadFormat` and `Gzip` breaks source and binary compatibility. It is the fourth
  exception to semantic versioning within 1.x, after 1.1.0, 1.2.0 and 1.3.0, and like those it has its own ADR,
  [ADR-051](../../../maintainers/adr/adr-051-remove-jsonrpc-leftovers-in-1-x.md). Neither type carries behavior an
  application would lose. `JsonRpcException` is removed under a rule added in this release: decision 4 of
  [ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md) lets the framework's exception types
  change in a minor version, provided the release notes list the change. The JSON-RPC error codes, and the code each
  failure travels as, stay under semantic versioning, because clients compare against the numbers.

### `[TreeNode]` and `[TreeNodeIgnore]` move to Polhem.Definition

- **Affects:** types of your own that apply `[TreeNode]` or `[TreeNodeIgnore]`.
- **Before:** `TreeNodeAttribute` and `TreeNodeIgnoreAttribute` were in `Polhem.Core.Attributes` (`Polhem.Core`).
  Nothing in the framework read them, so applying them had no effect.
- **Now:** they are in `Polhem.Definition.Attributes` (`Polhem.Definition`), next to the definition types they
  annotate, and `ObjectTreeBuilder` reads them.
- **Migrate:** replace `using Polhem.Core.Attributes;` with `using Polhem.Definition.Attributes;` in those types.

### `DatabaseItem` is labelled by its `Id`

- **Affects:** code that shows or compares the result of `DatabaseItem.ToString()`.
- **Before:** `DatabaseItem.ToString()` and its `[TreeNode]` label used `DbName`, so an item that names no database,
  such as a SQLite one, showed an empty name.
- **Now:** both use `Id`.
- **Migrate:** read `DbName` explicitly where the database name is wanted.
