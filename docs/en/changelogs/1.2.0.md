# Polhem 1.2.0 — Detailed Release Notes

[繁體中文](../../zh-TW/changelogs/1.2.0.md)

This file is the detailed companion to the `[1.2.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md). The changelog lists
each change in one line; this file keeps the reasons and the background.

> JSON-RPC now runs on the [`Polhem.JsonRpc`](https://github.com/polhem-dev/polhem-jsonrpc) packages, and the payload
> envelope on their optional payload packages. The decisions, the alternatives and the full migration steps are
> recorded in [ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md).

## Why the protocol moved out

Up to 1.1.0, Polhem carried its own JSON-RPC 2.0 implementation: the executor and its message types in
`Polhem.Api.Core`, a controller in `Polhem.Api.AspNetCore`, and two client providers in `Polhem.Api.Client`. None of
that was specific to Polhem. What is specific sits on top of it: API key and access token checks, method-level access
control, the error contract, the anomaly records, and the session key and wire types behind the payload envelope.

The protocol half is now maintained as its own packages, which know nothing about Polhem and can be used without it.
Polhem attaches its own behaviour through their extension points, in `Polhem.Api.Core.Dispatch`. The payload
envelope, its encryption and its replay frame followed for the same reason: they are a protocol of their own, which
[polhem-connector-js](https://github.com/polhem-dev/polhem-connector-js) also speaks, so they now live in
`Polhem.JsonRpc.Payload` and `Polhem.JsonRpc.Payload.Server`.

## Why a breaking change in a minor version

Moving the protocol left `ApiServiceController` with nothing to do but call the endpoint, and left `ApiServiceOptions`
as a second configuration surface that would have had to mirror the payload package's options. Keeping either would
mean two ways to host the API and two ways to configure the payload, and every later change would have to keep them
in step. Both are removed in this release, which breaks hosts.

[ADR-048](../../../maintainers/adr/adr-048-rename-base-to-core-in-1-1.md) said the rename in 1.1.0 was the only
exception to semantic versioning in 1.x. ADR-049 is a second one, and it says further breaking changes within 1.x need
an ADR of their own. The same ADR also names the **framework pipeline types**: public types that exist only for
`Polhem.*` packages to cooperate, such as everything in `Polhem.Api.Core.Dispatch`. Changes to them are not counted as
breaking, so an application should not build on them.

## Breaking API changes

- The `Polhem.Api.AspNetCore` package is removed, with `ApiServiceController` and `UsePolhemFramework()`. A host serves
  the API with `Polhem.JsonRpc.AspNetCore`: `AddJsonRpcServer()` and `MapJsonRpc("/api")`. A check that overrode a
  controller member becomes a filter. The startup check `UsePolhemFramework()` ran moves to
  `AddPolhemApiKeyGateCheck()`, which is opt-in because an in-process host has no HTTP endpoint for an API key to
  guard. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- `IJsonRpcProvider`, `JsonRpcExecutor` and the message types of `Polhem.Api.Core.JsonRpc` are removed. The providers
  implement the package's `IJsonRpcTransport`. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- `ApiServiceOptions` is removed, with the payload transformer, its serializer, compressor and encryptor types, the
  envelope types and the replay types. A server registers the payload options with `AddPolhemPayload()`, and a .NET
  client holds them in `ApiClientInfo.PayloadOptions`; `PolhemPayload` builds them the framework's way. Codecs,
  the replay store and the frame settings move to the package's `PayloadOptions`, and `IApiAuthorizationValidator` is
  resolved from the service collection. ([#47](https://github.com/polhem-dev/polhem/pull/47))

The upgrade of a host is shown in the changelog. Every step, including the ones most hosts do not need (custom codecs,
a shared replay store, a host that also calls the API in-process), is in decisions 3 and 5 of
[ADR-049](../../../maintainers/adr/adr-049-jsonrpc-packages-in-1-2.md).

## Changed behaviour

- **The wire.** The parameters and the result envelope are the same bytes as in 1.1.0; the wire fixtures did not
  change. Two things that were Polhem's own are aligned with JSON-RPC 2.0: an internal error is answered with -32603,
  the code the specification defines for it, instead of -32000, and a response no longer echoes the method name in a
  `method` member. A client that compares against -32000 or reads `method` moves with the server; for
  polhem-connector-js that is the release that targets 1.2.0. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **Rejected credentials.** A rejected API key or `Authorization` header is answered with HTTP 200 and a JSON-RPC
  error instead of 401. The check now runs before the business object is created, inside the JSON-RPC pipeline, so
  its failure is reported like every other failure, and the .NET client throws the error contract's exception
  instead of `HttpRequestException`. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **Method names.** A malformed method name is answered with `MethodNotFound`, as the specification asks, instead of a
  user message. An action that does not exist is answered by the dispatcher itself with a fixed message, also in debug
  mode, and leaves no anomaly record. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **In-process calls** serialize their parameters like remote calls, so the server never holds the caller's objects.
  A filter value in a `Plain` body arrives as text, as it always did over HTTP. ([#46](https://github.com/polhem-dev/polhem/pull/46))
- **Payload format.** An envelope whose `format` is not 0, 1 or 2 is refused as invalid parameters instead of being
  accepted and failing further on. ([#47](https://github.com/polhem-dev/polhem/pull/47))
- **Log categories** follow the types that write them: `Polhem.Api.Core.Dispatch.PolhemExceptionMapper` for masked
  failures, `Polhem.Hosting.ApiKeys.ApiKeyGateWarningService` for the API key startup check. A log filter on the old
  categories needs the new names. ([#46](https://github.com/polhem-dev/polhem/pull/46))

## Samples and tools

- `QuickStart.Server`, the Northwind server and the load test host serve the API with `MapJsonRpc("/api")`, and
  register the payload options with `AddPolhemPayload()`. They show the upgrade above on a working host.
  ([#46](https://github.com/polhem-dev/polhem/pull/46), [#47](https://github.com/polhem-dev/polhem/pull/47))
