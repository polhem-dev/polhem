# Polhem 1.3.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.3.1.md)

This file holds the details behind the `[1.3.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version changes how the client seals its calls internally and raises the lowest Polhem.JsonRpc version it accepts
to 1.2.0. Nothing in the `PublicAPI.Shipped.txt` baselines is added, removed or changed, and the wire format is the one
of 1.3.0, so a 1.3.1 client and a 1.3.0 server, or the other way round, talk to each other: servers and clients do not
have to upgrade together.

## New features and changes

### The client seals its calls through `PayloadConnector`

`ApiConnector` used to wrap the parameters with `PayloadProcessor.WrapRequest`, read back the format it had sent, call
the JSON-RPC connector and open the result itself.
[Polhem.JsonRpc 1.2.0](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/CHANGELOG.md) adds a package that does
this, `Polhem.JsonRpc.Payload.Client`, and `ApiConnector` now calls its `PayloadConnector`. The wire format, and the
formats, keys and sequence numbers a call uses, are unchanged: the key still comes from the session, the sequence
numbers from the session's counter, and the codec from `PayloadCodec`. Polhem's own rules stay where they were: a local
provider outside debug mode sends Plain, an Encrypted call without a session key is sent Encoded, and the time-zone
conversion and its guards run around the call.

`Polhem.Api.Client` references `Polhem.JsonRpc.Payload.Client` instead of `Polhem.JsonRpc.Client`, which it still gets
through it. This requires Polhem.JsonRpc 1.2.0 or later: NuGet brings it along when the Polhem packages are updated to
1.3.1, and an application that pins Polhem.JsonRpc itself raises the pin to 1.2.0 or later.
([#63](https://github.com/polhem-dev/polhem/pull/63))

### Documentation

- The development constraints and the documentation of `StaticApiEncryptionKeyProvider` say what a shared API key
  leaves open. With one key for every client, sequence numbers are still counted per session, so a call captured in
  one session is accepted in any other session in which its sequence number is still new, while its timestamp is
  within the tolerance, by whoever can present that session, without holding the key. The default
  `DerivedApiEncryptionKeyProvider` gives each session its own key. ([#62](https://github.com/polhem-dev/polhem/pull/62))

## Breaking changes

### A response without a result fails with `InvalidPayloadException`

- **Affects:** .NET clients that call a server that is not Polhem and may answer a call with no `result` at all, and
  code that catches the `InvalidOperationException` this used to throw. A Polhem server always answers with a payload
  envelope, so a client of a Polhem server does not see the change.
- **Before:** `ApiConnector` threw `InvalidOperationException` ("The API answered without a result.").
- **Now:** an Encoded or Encrypted call fails with `InvalidPayloadException` from Polhem.JsonRpc, because the missing
  result is not in the format of the call, and a Plain call reads it as a null value.
- **Migrate:** catch `InvalidPayloadException` for an Encoded or Encrypted call, and handle a null value for a Plain
  call, where `InvalidOperationException` was caught.
  ([#63](https://github.com/polhem-dev/polhem/pull/63))
