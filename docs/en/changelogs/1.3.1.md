# Polhem 1.3.1 — Detailed Release Notes

[繁體中文](../../zh-TW/changelogs/1.3.1.md)

This file is the detailed companion to the `[1.3.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md). The changelog lists
each change in one line; this file keeps the reasons and the background.

## Why a patch version

Nothing in the `PublicAPI.Shipped.txt` baselines is added, removed or changed, and the wire format is the one of 1.3.0,
so a 1.3.1 client and a 1.3.0 server, or the other way round, talk to each other. The release changes how the client
seals its calls internally and raises the lowest Polhem.JsonRpc version it accepts.

## How to upgrade

Update the Polhem packages to 1.3.1. NuGet brings Polhem.JsonRpc 1.2.0 along; an application that pins Polhem.JsonRpc
itself raises the pin to 1.2.0 or later. Servers and clients do not have to upgrade together.

## Changed behaviour

- **The client seals its calls through `PayloadConnector`.** `ApiConnector` used to wrap the parameters with
  `PayloadProcessor.WrapRequest`, read back the format it had sent, call the JSON-RPC connector and open the result
  itself. [Polhem.JsonRpc 1.2.0](https://github.com/polhem-dev/polhem-jsonrpc/blob/main/CHANGELOG.md) adds a package
  that does this, `Polhem.JsonRpc.Payload.Client`, and `ApiConnector` now calls its `PayloadConnector`. The key still
  comes from the session, the sequence numbers from the session's counter, and the codec from `PayloadCodec`. Polhem's
  own rules stay where they were: a local provider outside debug mode sends Plain, an Encrypted call without a session
  key is sent Encoded, and the time-zone conversion and its guards run around the call.
  `Polhem.Api.Client` references `Polhem.JsonRpc.Payload.Client` instead of `Polhem.JsonRpc.Client`, which it still
  gets through it. ([#63](https://github.com/polhem-dev/polhem/pull/63))
- **A response without a result fails differently.** A server that answers a call with no `result` at all used to make
  `ApiConnector` throw `InvalidOperationException` ("The API answered without a result."). An Encoded or Encrypted call
  now fails with `InvalidPayloadException` from Polhem.JsonRpc, because the missing result is not in the format of the
  call, and a Plain call reads it as a null value. A Polhem server always answers with a payload envelope, so this is
  seen only with a server that is not Polhem. ([#63](https://github.com/polhem-dev/polhem/pull/63))

## Documentation

- The development constraints and the documentation of `StaticApiEncryptionKeyProvider` say what a shared key leaves
  open. With one key for every client, sequence numbers are still counted per session, so a call captured in one
  session is accepted in any other session in which its sequence number is still new, while its timestamp is within the
  tolerance, by whoever can present that session, without holding the key. The default
  `DerivedApiEncryptionKeyProvider` gives each session its own key. ([#62](https://github.com/polhem-dev/polhem/pull/62))
