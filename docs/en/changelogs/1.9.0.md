# Polhem 1.9.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.9.0.md)

This file holds the details behind the `[1.9.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version follows a definition change through DefineEditor without going back to Excel, fits the ready-made front
end to phones, and lets an application choose its starting theme. It also fixes what UI automation and VoiceOver could
not do in the shell and in DefineEditor's trees. The wire format is the one of 1.8.0, so a 1.8.0 client and a 1.9.0
server, or the other way round, talk to each other.

## New features and changes

### Sync a FormSchema to its TableSchemas and FormLayout in DefineEditor

After a field is added to a FormSchema, **Sync TableSchema and FormLayout** on the schema node, or in the **File** menu
while the FormSchema is the active tab, brings the form's other definition files up to date. It plans an import of the
saved form in merge mode, so it only adds: a new field goes into the TableSchema and the FormLayout next to its
neighbour on the form, a new detail table is registered, and a removed field or a changed column type is reported as a
warning rather than applied. A new visible master field is also appended to the form's `ListFields`; an empty
`ListFields`, which lists every field, stays empty.

**Upgrade This Form's Tables** next to it upgrades only the tables of that form, with a preview of the statements
first.

The layout half is available to code as `FormLayoutGenerator.Merge(layout, schema)` (`Polhem.Definition.Layouts`): it
adds the fields and detail grids the schema has and the layout lacks, changes and removes nothing, and returns the
names it added. The form workbook import can merge into an existing layout the same way, so a re-imported workbook no
longer has to choose between keeping a hand-arranged layout and regenerating it.

### Choose what the FormLayout editor shows on its right

Buttons above the FormLayout editor show the property grid and the preview (the default), only the preview, or only
the property grid. Without the grid, **Properties…** on the toolbar or in a node's context menu edits the selected
node in a dialog with the same grid; edits there mark the document changed and update the tree, and ⌘S saves.

### Toggle DefineEditor's sidebar

**View › Toggle Side Bar** (⌘B; Ctrl+B off macOS) collapses the sidebar so the editors, such as the FormLayout preview,
take the whole window, as in VS Code.

### One form at a time on phones

On the iOS and Android heads, `Polhem.UI.Avalonia.Shell` now shows one form that fills the screen instead of document
tabs: picking another menu entry replaces it, and the menu slides over the form, starts closed and closes once an entry
is picked. The back button returns an open record to its list and then leaves the app. Desktop and browser heads keep
the tabs.

### Choose the shell's starting theme

`ShellOptions.DefaultThemeVariant` sets the theme the shell starts with. It is light unless an application sets
otherwise, and the light/dark switch on the forms screen starts from the theme in effect:

```csharp
protected override ShellOptions CreateOptions() => new()
{
    AppTitle = "MyApp",
    DefaultThemeVariant = ThemeVariant.Dark,
};
```

Projects created from the `polhem-avalonia` template from this version on start dark, and so does the Northwind
sample; remove the line from the generated `App.cs` to start light. Projects created earlier do not change.

### Fixes

- **The shell's menu and tab close buttons on the browser head.** They showed the characters U+2630 and U+2715, which
  the embedded Inter font has no glyph for. Desktop heads borrowed a system font; the browser head has none and drew a
  placeholder. Both buttons now draw a vector icon.
- **Selections made through accessibility.** Selecting a menu entry of the shell through the macOS accessibility
  interface, as VoiceOver and UI automation do, highlighted it without opening the form; it now opens. Selecting a row of
  a single-selection tree the same way left the previous row as the selected item, so an editor bound to the selection
  did not follow. The new `TreeViewExtensions.KeepSelectionSingle` (`Polhem.UI.Avalonia.Controls`) makes the added row
  the selected one; `ObjectTreeView` and DefineEditor's sidebar trees apply it. Rows and cells of a `DataGrid` still
  cannot be selected this way, because the grid's automation peers do not support it
  ([#149](https://github.com/polhem-dev/polhem/issues/149)).

## Breaking changes

None.
