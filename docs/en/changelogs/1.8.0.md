# Polhem 1.8.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.8.0.md)

This file holds the details behind the `[Unreleased]` entry in [CHANGELOG.md](../../../CHANGELOG.md), which becomes
`[1.8.0]` when it is released.

This version is not released yet. The wire format is the one of 1.7.0.

## New features and changes

### Render a form layout without data

`FormLayoutPresenter` (`Polhem.UI.Avalonia.Controls`) renders the body of a form from a `FormLayout` alone: the master
sections with one field editor per `LayoutField`, laid out by `ColumnCount` and the spans, followed by the detail
grids. It needs no data, schema or backend, so a design tool can show a layout while it is being edited:

```csharp
var preview = new FormLayoutPresenter { Layout = layout };
FormScope.SetFormMode(preview, SingleFormMode.Edit);
```

Without data, the editors follow the layout's `ReadOnly` and `AllowEditModes` under the form mode, and each detail
grid shows the toolbar its `AllowActions` allow, with the buttons disabled. Drop-down items, field values, lookup text
and computed fields come from the schema or the data and are not shown. Changing a property renders again; after
changing the layout in place, call `Refresh()`. `IsCompact` renders the phone-sized form.

`FormView` now renders its record through this control, so the two draw a layout the same way. What `FormView` shows
does not change.

### Live FormLayout preview in DefineEditor

The FormLayout editor shows a preview under the property grid, drawn by `FormLayoutPresenter`. It redraws shortly after
each edit: a property written in the grid, a section, field, grid or column added, deleted or reordered. It can show
View mode or the phone-sized form, and puts each field's name into empty fields. Unchecking **Show** collapses it to
its header.

### DefineEditor colours

DefineEditor takes its colours from VS Code's **Dark (Visual Studio)** and **Light (Visual Studio)** themes: the
backgrounds, input fields, accent, selection and focus colours, and faint dividers. Every pane splitter turns the focus
colour while the pointer is on it or it is being dragged, as VS Code's sashes do.

### DefineEditor sidebar views

A VS Code style activity bar on the left switches the sidebar between three views of the same definition files:

- **Explorer**: the files of the DefinePath folder, as before.
- **Programs**: each ProgId registered in `ProgramSettings.xml`, with its FormSchema, FormLayout, the TableSchema of
  each of its tables and its Language files.
- **Databases**: each category in `DbCategorySettings.xml` with its tables; a table opens its TableSchema.

Clicking the icon of the view already shown collapses the sidebar, and the view is remembered between sessions.

### CREATE TABLE in the DefineEditor TableSchema editor

A **CREATE TABLE** panel under the property grid of the TableSchema editor shows the statement for the table being
edited. Pick SQL Server, PostgreSQL, MySQL, Oracle or SQLite in its header; the statement updates as you edit and
**Copy** puts it on the clipboard. It comes from the same dialect builders in `Polhem.Db` that create the tables at
run time, so it includes the indexes and the description statements each database uses. Unticking **Show** collapses
the panel to its header.

### Describe forms in Excel workbooks

A form can be described in an Excel workbook and imported as definition files, so the people who know a form can model
it before a developer touches the XML. One workbook describes one form: its tables, fields, validation rules and menu
placement, with drop-downs for the columns that take fixed values and a zh-TW column next to each display text. The
headers and instructions come in English or Traditional Chinese (`--lang zh-TW`; DefineEditor follows its interface
language), and the import reads either.

```bash
dotnet polhem forms template --out Quote.xlsx
dotnet polhem forms import Quote.xlsx --define ./Define --dry-run
dotnet polhem forms export Quote --define ./Define --out Quote.xlsx
```

The import fills in what the framework's conventions decide (system fields, the `ref_*` fields of a relation, `ft_`
table names, the `company` category), validates the form, and writes the FormSchema, a TableSchema per table, the
FormLayout when there is none, the registrations in `DbCategorySettings.xml`, `ProgramSettings.xml` and
`MenuSettings.xml`, and the zh-TW language files. Nothing is written when there is an error. An existing TableSchema
is merged by default (the columns and indexes the form brings are added, nothing is removed); `--tables keep` or
`--tables overwrite` choose otherwise. A framework table such as `st_employee` starts from the framework's own
TableSchema, so the columns the framework reads but no form shows are kept. DefineEditor offers the
same import from **File** and an export on a FormSchema node. See
[Modeling Forms in Excel](../guides/excel-form-modeling.md).

A String field that becomes a table column needs a max length: no database builds a text column without one, so the
import stops at that row. The export writes the lengths a form keeps only in its TableSchema, and a merge gives an
existing column without a length the workbook's length.

### DefineEditor as a dotnet tool, and database work without a project

DefineEditor is published as the dotnet tool `Polhem.DefineEditor`. A project pins it in its tool manifest and opens
its definitions with `dotnet polhem-define Define`; the folder on the command line opens at startup.

The new dotnet tool `Polhem.DbManager` (`polhem-db`) runs the `db` commands of `Polhem.Hosting` against a definition
folder, with the drivers of SQL Server, PostgreSQL, MySQL, Oracle and SQLite, so no application project is needed:
`polhem-db upgrade --define ./Define`. See [its README](../../../tools/DbManager/README.md).

DefineEditor carries no database driver and uses it for its database work, through `dotnet tool exec` at exactly its own
version: **Test Connections** in the DatabaseSettings editor, **Upgrade Database** and **Preview Database Upgrade** in
the **File** menu, and the dialog that ends an import, which upgrades only the imported form's tables. The first run
asks before the tool is downloaded. A window shows the output as it arrives and reads the exit code; password values
are masked. See [its README](../../../tools/DefineEditor/README.md#database-work).

`db check` opens a connection to each database item (`IDatabaseInitializer.CheckConnections`). `db upgrade` takes
`--table <name>`, which can be repeated, to build or upgrade only the named tables (`IDatabaseInitializer.UpgradeTables`
gains the matching `tableNames` parameter), since a database can hold thousands of tables. See
[Initializing a New Deployment](../database/database-settings-guide.md#7-initializing-a-new-deployment).

### Project template

The new package `Polhem.Templates` installs the `dotnet new` template `polhem-avalonia` (**Polhem App (Avalonia)** in VS Code's
New .NET Project). It creates a server that references the Polhem packages of the same version and the driver of the
database chosen with `--database`, a definition folder with the three databases, a tool manifest with DefineEditor and
DbManager, and VS Code tasks that initialize the database and open DefineEditor. See
[its README](../../../tools/Polhem.Templates/README.md).

### Fixes

- **A generated detail TableSchema indexes its master column.** `TableSchemaGenerator` (and `FormTable.GenerateDbTable`,
  which the Excel import uses to write the TableSchema files) now adds a non-unique index named `fk_{0}_master` on
  `sys_master_rowid` to every table that has that column. Loading or deleting the details of one record filters on it,
  and without the index each such read scans the whole detail table. The hand-written detail TableSchemas in the
  samples and the Northwind app already declared this index under the same name.

  Effect on existing databases: a TableSchema file already on disk does not change. If you regenerate or re-import the
  TableSchema of a detail table, the next schema upgrade creates `fk_{0}_master` on that table. Building an index on a
  large table takes time and, depending on the database, may block writes to it, so plan that upgrade as you would any
  other index addition. A TableSchema that already declares `fk_{0}_master` gets no second index.
