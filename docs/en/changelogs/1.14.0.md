# Polhem 1.14.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.14.0.md)

This file holds the details behind the `[1.14.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

DefineEditor can now draft a form from a paper document in a conversation with Claude, through two new packages,
`Polhem.Definition.Drafting` and `Polhem.AI.Claude`. A relation field whose type differs from its source field is now a
build error, and a host that leaves `|DataDirectory|` unset finds its SQLite files next to its definition folder. The wire
format is the one of 1.13.0.

## New features and changes

### Draft a form from documents in DefineEditor

**File → Import Form from Documents...** sends a paper form (a PDF, a Word document or photos) to Claude after asking
for consent, and opens a drafting window: the conversation on the left; on the right the form as the import will write
it, the drafted fields (editable in place) and the open questions. Claude reads the master table and any detail tables,
captions in English and zh-TW, types, lengths, drop-down choices, computed fields and the fields of the list, and
matches the fields that pick a record (an employee, a department, a customer) to the forms the definition folder
already has, asking when it is not sure. **Create Definitions** runs the same import as an Excel workbook, with the same
checks and confirmation.

The conversation starts in the language of DefineEditor's interface and follows the user when they write in another
one. DefineEditor keeps no credential: it uses the one the Anthropic SDK finds, the profile of `ant auth login` or
`ANTHROPIC_API_KEY`, and the requests are charged to that credential's Claude Console organization. The guide is
[Drafting Forms from Documents](../guides/document-form-drafting.md).

- **Background:** [ADR-064](../../../maintainers/adr/adr-064-document-form-drafting.md)

### New package: `Polhem.Definition.Drafting`

The drafting itself, for any application that wants to offer it. `DocumentSource` reads PDFs and images as they are and a
Word document as Markdown; `FormDraftSession` runs the conversation over any `IChatClient` (from
`Microsoft.Extensions.AI.Abstractions`) with the tools the model edits the draft with; `FormDraftConverter` turns the
draft into a `FormSchema`, its zh-TW texts and its menu placement by fixed rules, so the model never writes the
definition. The application supplies its existing forms and its validation through `IFormDraftingHost`.
`FormDraftingOptions.ReplyCulture` sets the language of the first reply. The package references no model vendor's SDK.
See its [README](../../../src/Polhem.Definition.Drafting/README.md).

### New package: `Polhem.AI.Claude`

The Claude provider for drafting: `ClaudeChatClientFactory.Create` returns an `IChatClient` over the official Anthropic
SDK, with streaming, adaptive thinking at an explicit effort, prompt caching, strict tools and server-side refusal
fallbacks. A refusal, an answer cut off at the output limit and a rejected credential throw `ClaudeChatException`.
`ClaudeCredentials.Describe()` reports which credential the SDK will use without reading any secret. See its
[README](../../../src/Polhem.AI.Claude/README.md).

### The Excel import lists a relation field by its record's name

A form workbook that names a relation field in **List fields** now lists the field that shows the related record's
name (`ref_<base>_name`) in its place, so the list shows a name and not a row id.

### A `DateOnly` filter value matches dates on SQLite and Oracle

A list filtered on a date column with a `DateOnly` value matched nothing on SQLite for **Equal** and left out the last
day for **Between**, because the driver bound the value as text without a time while saved dates carry one; Oracle
refused the value. Both now bind it as the date at midnight. SQL Server, PostgreSQL and MySQL are unchanged.

### `polhem-db` and DefineEditor's database upgrade accept `|DataDirectory|`

`polhem-db`, and with it DefineEditor's **Upgrade Database**, used to stop on a SQLite path under `|DataDirectory|` as
relative. It now resolves the prefix to the folder that holds the definition folder, as the hosts do (see the breaking
change below). See [Database Settings §2.7](../database/database-settings-guide.md#27-sqlite-file-paths).

### DefineEditor refuses the relation types POLHEM2008 reports

The relation dialog applied a mapping whose types differ, which the consumer's build then refused, and flagged pairs the
rule accepts. It now uses the analyzer's own rule: a mismatch is an error in the dialog, and a lookup-only mapping is not
checked.

### The wire fixtures pin a Binary column and a read-only column

`wire-fixtures/` gains samples of a Binary column whose default is an empty byte array and of a read-only column a
modified row carries. The encoding does not change; a client written against the fixtures now sees both shapes.

## Breaking changes

### A relation field must declare the type of its source field (POLHEM2008)

- **Affects:** applications whose definitions map a relation field to a source field of another type, such as a `Guid`
  row id copied into a `String` field.
- **Before:** the mapping was accepted, and a filter on the field converted its value by the declared type, so it matched
  nothing or was refused.
- **Now:** the analyzer reports **POLHEM2008** as an error. `Integer` and `AutoIncrement`, `Decimal` and `Currency`, and
  `String` and `Text` count as the same; a wider integer is accepted; lookup-only mappings are not checked.
- **Migrate:** change the relation field's `DbType` to the source field's, and upgrade the table if its column changes.
  See [Analyzer Rules](../reference/analyzer-rules.md).

### A host that leaves `|DataDirectory|` unset opens SQLite files next to its definition folder

- **Affects:** hosts built with `AddPolhemBackend` whose `DatabaseSettings.xml` uses `|DataDirectory|` without the host
  setting the `DataDirectory` value itself.
- **Before:** Microsoft.Data.Sqlite resolved the prefix to the application's base folder, usually the build output, so
  the database file depended on how the host was started.
- **Now:** `AddPolhemBackend` and `polhem-db` call `DataDirectory.EnsureDefault` (`Polhem.Hosting.Database`), which sets
  the value to the folder that holds the definition folder unless the host has set it. A host that sets it keeps its value.
- **Migrate:** move an existing database file next to the definition folder, or set `DataDirectory` before
  `AddPolhemBackend` to keep the old location.
