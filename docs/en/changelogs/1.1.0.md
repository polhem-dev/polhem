# Polhem 1.1.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.1.0.md)

This file holds the details behind the `[1.1.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md). This version renames
`Polhem.Base` to `Polhem.Core`, a break that semantic versioning would hold back until 2.0.0; it ships in 1.1.0 as a
one-time exception (see the first breaking change). The wire fixtures are unchanged by the rename, so the bytes a 1.0.0
client and a 1.1.0 server exchange are the same; the one difference is that a type name under `Polhem.Base` is no
longer on the built-in type namespace allowlist.

## New features and changes

### The user documents are grouped by topic

The documents are split by reader. The user documents stay under `docs/<lang>/`, grouped into topic folders
(`getting-started/`, `architecture/`, `guides/`, `reference/` and others), and the detailed changelogs move into
`docs/<lang>/changelogs/`. The maintainer documents and the ADRs move to `maintainers/` and are written in English
only. A link to a document under its old path no longer resolves.
([#38](https://github.com/polhem-dev/polhem/pull/38), [#39](https://github.com/polhem-dev/polhem/pull/39),
[#40](https://github.com/polhem-dev/polhem/pull/40))

### The `Web.Js.Demo` sample is removed

The `Web.Js.Demo` sample, a vanilla JavaScript client, is removed. JavaScript clients standardise on
[polhem-connector-js](https://github.com/polhem-dev/polhem-connector-js), and the
[frontend integration guide](../api/jsonrpc-frontend-integration.md) and the READMEs point there. `QuickStart.Server`
keeps its CORS policy for browser clients. ([#41](https://github.com/polhem-dev/polhem/pull/41))

## Breaking changes

### `Polhem.Base` is renamed to `Polhem.Core`

- **Affects:** every application on 1.0.0: code that names a `Polhem.Base` namespace, and projects that reference the
  `Polhem.Base` package directly.
- **Before:** the lowest assembly of the framework was the `Polhem.Base` package, with namespaces such as
  `Polhem.Base.Serialization` and `Polhem.Base.Collections`.
- **Now:** the package ID, the assembly and every namespace are `Polhem.Core` (`Polhem.Base.Serialization` →
  `Polhem.Core.Serialization`, `Polhem.Base.Collections` → `Polhem.Core.Collections`, and so on). The type names do
  not change. There is no compatibility shim: `TypeForwardedTo` forwards a type to another assembly but cannot change
  its namespace. ([#42](https://github.com/polhem-dev/polhem/pull/42))
- **Migrate:**
  1. If a project references `Polhem.Base` directly, replace it with `Polhem.Core`. Most applications do not: every
     other Polhem package brings it in.
  2. Replace `Polhem.Base` with `Polhem.Core` in `using` directives and in fully qualified type names.
  3. Build. The compiler reports each place that is left.
  4. Check the `AllowedTypeNamespaces` setting, if you set it (see the next item).

  ```diff
  - <PackageReference Include="Polhem.Base" Version="1.0.0" />
  + <PackageReference Include="Polhem.Core" Version="1.1.0" />
  - using Polhem.Base.Serialization;
  + using Polhem.Core.Serialization;
  ```

- **Background:** The lowest assembly of the framework was always meant to be called `Polhem.Core`. Polhem 1.0.0
  shipped on 2026-09-28 with the name it inherited from Bee.NET, and the cost of a rename only grows with the number
  of applications that use the old name. Two days after 1.0.0 that number was, as far as anyone knew, zero. A major
  version two days after 1.0.0, for a rename nobody had adopted yet, would signal an upheaval that did not happen. So
  the rename ships in 1.1.0, and every `Polhem.*` 1.0.0 package is unlisted: an application that pinned 1.0.0 still
  restores, but no new application starts on the old name. A minor version rather than a patch, because automated
  dependency updates apply patch versions most readily, and a break hidden in a patch is the one most likely to go
  unnoticed. This is the only such exception: from 1.1.0 on, 1.x follows semantic versioning as
  [ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md) describes. The decision and the
  alternatives are recorded in [ADR-048](../../../maintainers/adr/adr-048-rename-base-to-core-in-1-1.md).

### The type namespace allowlist names `Polhem.Core`

- **Affects:** servers whose JSON-RPC calls carry type names under `Polhem.Base`, and settings with a custom
  `AllowedTypeNamespaces` entry that lists `Polhem.Base`.
- **Before:** the built-in JSON-RPC type namespace allowlist named `Polhem.Base`.
- **Now:** it names `Polhem.Core`, so a type name under `Polhem.Base` is rejected like any other unknown namespace. A
  custom `AllowedTypeNamespaces` entry that lists `Polhem.Base` no longer matches anything.
  ([#42](https://github.com/polhem-dev/polhem/pull/42))
- **Migrate:** remove `Polhem.Base` from `AllowedTypeNamespaces`; the built-in namespaces never need to be listed.
- **Background:** [ADR-048](../../../maintainers/adr/adr-048-rename-base-to-core-in-1-1.md)
