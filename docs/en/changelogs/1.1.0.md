# Polhem 1.1.0 — Detailed Release Notes

[繁體中文](../../zh-TW/changelogs/1.1.0.md)

This file is the detailed companion to the `[1.1.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md). The changelog lists
each change in one line; this file keeps the reasons and the background.

> `Polhem.Base` is renamed to `Polhem.Core`. Semantic versioning would hold that back until 2.0.0; it ships in 1.1.0 as
> a one-time exception. The decision and the alternatives are recorded in
> [ADR-048](../../../maintainers/adr/adr-048-rename-base-to-core-in-1-1.md).

## Why a breaking change in a minor version

The lowest assembly of the framework was always meant to be called `Polhem.Core`. Polhem 1.0.0 shipped on 2026-09-28
with the name it inherited from Bee.NET, and the cost of a rename only grows with the number of applications that
use the old name. Two days after 1.0.0 that number was, as far as anyone knew, zero.

A major version two days after 1.0.0, for a rename nobody had adopted yet, would signal an upheaval that did not
happen. So the rename ships in 1.1.0, and every `Polhem.*` 1.0.0 package is unlisted: an application that pinned 1.0.0
still restores, but no new application starts on the old name. A minor version rather than a patch, because automated
dependency updates apply patch versions most readily, and a break hidden in a patch is the one most likely to go
unnoticed.

This is the only such exception. From 1.1.0 on, 1.x follows semantic versioning as
[ADR-046](../../../maintainers/adr/adr-046-api-evolution-policies-for-1-0.md) describes.

## Breaking API changes

- `Polhem.Base` is renamed to `Polhem.Core`: the package ID, the assembly and every namespace
  (`Polhem.Base.Serialization` → `Polhem.Core.Serialization`, `Polhem.Base.Collections` → `Polhem.Core.Collections`,
  and so on). The type names do not change. There is no compatibility shim: `TypeForwardedTo` forwards a type to
  another assembly but cannot change its namespace. ([#42](https://github.com/polhem-dev/polhem/pull/42))

To upgrade from 1.0.0:

1. If a project references `Polhem.Base` directly, replace it with `Polhem.Core`. Most applications do not: every
   other Polhem package brings it in.
2. Replace `Polhem.Base` with `Polhem.Core` in `using` directives and in fully qualified type names.
3. Build. The compiler reports each place that is left.
4. Check the `AllowedTypeNamespaces` setting, if you set it (see the next section).

```diff
- <PackageReference Include="Polhem.Base" Version="1.0.0" />
+ <PackageReference Include="Polhem.Core" Version="1.1.0" />
- using Polhem.Base.Serialization;
+ using Polhem.Core.Serialization;
```

## Changed behaviour

- The built-in JSON-RPC type namespace allowlist names `Polhem.Core` instead of `Polhem.Base`, so a type name under
  `Polhem.Base` is rejected like any other unknown namespace. The built-in list used to be written twice in `SysInfo`
  and is now written once. A custom `AllowedTypeNamespaces` entry that lists `Polhem.Base` no longer matches anything
  and can be removed; the built-in namespaces never need to be listed. The wire fixtures are unchanged by the rename.
  ([#42](https://github.com/polhem-dev/polhem/pull/42))

## Samples and tools

- The `Web.Js.Demo` sample, a vanilla JavaScript client, is removed. JavaScript clients standardise on
  [polhem-connector-js](https://github.com/polhem-dev/polhem-connector-js), and the [frontend integration guide](../api/jsonrpc-frontend-integration.md)
  and the READMEs point there. `QuickStart.Server` keeps its CORS policy for browser clients.
  ([#41](https://github.com/polhem-dev/polhem/pull/41))

## Documentation

- The documents are split by reader. The user documents stay under `docs/<lang>/`, grouped into topic folders
  (`getting-started/`, `architecture/`, `guides/`, `reference/` and others), and the detailed changelogs move into
  `docs/<lang>/changelogs/`. The maintainer documents and the ADRs move to `maintainers/` and are written in English
  only. A link to a document under its old path no longer resolves.
  ([#38](https://github.com/polhem-dev/polhem/pull/38), [#39](https://github.com/polhem-dev/polhem/pull/39),
  [#40](https://github.com/polhem-dev/polhem/pull/40))
