# Polhem 1.11.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/1.11.0.md)

This file holds the details behind the `[1.11.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version is in progress. Its wire format is the one of 1.10.0.

## New features and changes

### The `polhem-blazor-server` template

`Polhem.Templates` gains a second template, listed as **Polhem App (Blazor Server)** in the C# Dev Kit:

```bash
dotnet new polhem-blazor-server -n Acme.Erp --database SqlServer
```

It creates one ASP.NET Core site, `src/<Name>.Web`, that runs the backend in its own process with `AddPolhemBackend`
and serves the Blazor Server shell: sign-in, the server's menu and one page that shows every form. It shares the
definition folder, the workbook folder, the tools and the database tasks with `polhem-avalonia`, and takes the same
`--database`, `--company`, `--db-password` and `--default-language` options. The pages' calls to the backend are
trusted local calls; the generated `Program.cs` and `README.md` say what a page of your own must not pass into them.

### `AddPolhemBackend`: the backend in one call

`Polhem.Hosting` gains `AddPolhemBackend`, an extension of `IHostApplicationBuilder` (a web application, a Worker
Service, a generic host). It makes the calls every backend host made before `AddPolhemFramework`, in order: it finds the
`Define` folder above the build output, adds the framework's default definitions the folder does not have yet, reads
`SystemSettings.xml`, initializes `SysInfo`, and calls `AddPolhemPayload` and `AddPolhemFramework`. It returns the
`PathOptions` it registered.

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddPolhemBackend(options => options.AutoCreateMasterKey = true);
builder.Services.AddJsonRpcServer();
```

`PolhemBackendOptions` names a definition folder (`DefinePath`) and a customization root (`CustomizePath`), turns
adding the defaults off or filters them (`MaterializeDefaults`, `MaterializeOptions`), and lets a development host
create its master key (`AutoCreateMasterKey`). Register the database providers yourself, as before. Existing hosts that
make these calls themselves keep working; the `polhem-avalonia` template's server now uses `AddPolhemBackend`.

### Template strings in Traditional Chinese

The names, descriptions and options of the templates are translated into Traditional Chinese
(`zh-Hant`). `dotnet new` shows them when its language is Traditional Chinese (`DOTNET_CLI_UI_LANGUAGE=zh-TW` or
`zh-Hant`), and the New Project list of the C# Dev Kit in VS Code shows them when the operating system's language is
Traditional Chinese; zh-TW and zh-HK fall back to zh-Hant. Every other language shows the English. Reload the VS Code
window after installing or updating the template package.

### A ready-made shell for Blazor Server

`Polhem.Web.Blazor.Server` gains `Polhem.Web.Blazor.Server.Shell`, the front end of a site in a few lines, as
`Polhem.UI.Avalonia.Shell` is for the Avalonia heads. `PolhemShellLayout`, the router's default layout, shows a sign-in
screen (company, user, password) until the circuit's user has entered a company, then a top bar with the title, the
user and company and Sign out, the server's menu, and the routed page. On a screen narrower than 600 CSS pixels the menu
slides over the page. The sign-in screen switches between English and Traditional Chinese through a new `GET /culture`
endpoint, which redirects only to a path on the site.

A site registers it with `AddPolhemShell` (title, sign-in hint, default company, user and password, the offered
languages and the default culture, the form route), adds `UsePolhemShellLocalization` and `MapPolhemShellCulture` to its
pipeline, sets `PolhemShellLayout` as the default layout, and keeps a root page with `PolhemShellHome` and a form page
with `FormPage`. The package README shows the whole setup. The Northwind Blazor head now runs on it.

`PolhemShellHome` opens the menu's first form. Until the menu holds a form, as in a new application before its first
form is added, the root page and the menu both say that the menu has no forms yet; when the menu cannot be loaded, the
menu shows the error and the root page stays empty.

`PolhemLoginPanel` gains `InitialUserId` and `InitialPassword`, which fill its inputs once.

### A default stylesheet for the Blazor components

The package ships `_content/Polhem.Web.Blazor.Server/polhem.css`, the default look of the components and the shell.
It is optional: until now every site styled the `polhem-*` classes itself, and a site that keeps doing so is
unaffected. Its colours are custom properties (`--polhem-accent`, `--polhem-surface` and others), so a site's own sheet,
linked after it, restyles it by redefining them.

### The default Department and Employee forms show their lists

The framework's default `Department` and `Employee` form schemas, which `Defaults.MaterializeTo` and `AddPolhemBackend`
write into a new application's `Define` folder, had an empty `ListFields`, so their lists showed no columns: a saved
row could be opened through View or Edit but not seen. They now list `sys_id`, `sys_name` and the related name
(`ref_manager_name` for Department, `ref_dept_name` for Employee).

`Department` also declares `LookupFields="sys_id,sys_name,ref_manager_id,ref_manager_name"`. Employee's department
lookup copies the department's manager into the supervisor fields, and without the declaration the lookup returned
only `sys_id` and `sys_name`, so picking a department failed with "Lookup source field 'ref_manager_id' is not in the
lookup result". `Employee` declares `LookupFields="sys_id,sys_name"`, the set it already fell back to.

Adding the defaults skips a file that already exists, so an application whose `Define` folder was created by an
earlier version keeps the old schemas. Set the two attributes in its `FormSchema/Department.FormSchema.xml` and
`FormSchema/Employee.FormSchema.xml` by hand, or delete those two files and start the host again to have them written
afresh (only if you have not changed them).
