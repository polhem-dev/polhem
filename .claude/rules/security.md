# Security rules

## Encryption implementation

### AES-CBC-HMAC (standard encryption)
- AES key length: **256-bit**
- HMAC: **SHA-256**, with a separate 256-bit key
- Use a **random IV** for every encryption; never reuse one
- Verify the HMAC with `CompareBytes` (constant-time comparison) to prevent timing attacks

```csharp
// Correct: constant-time comparison
private static bool CompareBytes(byte[] a, byte[] b) { ... }

// Forbidden: direct comparison can leak timing information
if (hmac == expected) { ... }
```

### RSA
- Use the `RsaCryptor` class; do not operate the underlying API directly
- Keys are generated by `AesCbcHmacKeyGenerator`; do not construct them by hand

## Security type layering (primitives vs policy)

Security-related types live in two layers according to "cryptographic primitive vs security policy". When looking for
a type, first decide which kind it is:

| Layer | Location | Contents | Examples |
|----|------|------|------|
| **Primitives** | `Polhem.Base/Security/` | Stateless cryptographic operations | `AesCbcHmacCryptor`, `RsaCryptor`, `PasswordHasher`, `FileHashValidator`, `AesCbcHmacKeyGenerator` |
| **Policy / key protocol** | `Polhem.Definition/Security/` | Key sources, access policy, verification protocols | `MasterKeyProvider`, `EncryptionKeyProtector`, `IAccessTokenValidator`, `ILoginAttemptTracker` |

Dividing principle: pure computation (given input, compute output, no business meaning) goes in `Polhem.Base`;
policy involving "where the key comes from, who may access it, how it is verified" goes in `Polhem.Definition`.

## API access control

Declare it with `[ApiAccessControl]`. **Prefer declaring it on the class so methods inherit it**; mark a method only
when it needs to override.

```csharp
[ApiAccessControl(ApiProtectionLevel.Encrypted, ApiAccessRequirement.Authenticated)]
public class OrderBO : FormBusinessObject { }
```

**For the full values and meaning of the two enums, see their XML docs** (`src/Polhem.Definition/Security/ApiProtectionLevel.cs`,
`ApiAccessRequirement.cs`). This file does not copy the enum members; that would drift.

## Session management

- The AccessToken is a **GUID**; never use a predictable value
- Tokens have an **expiry time**; after expiry, re-authentication is required
- One-time tokens are supported
- Session data is stored in the database (`st_session`, `st_user`), not on the client

## Payload security pipeline

This processing order must be preserved:
```
Serialize → Compress → Encrypt
Decrypt → Decompress → Deserialize
```
No step may be skipped or reordered.

## Prohibited

- Never write **plaintext keys, tokens or passwords** to logs or exception messages
- Never use `MD5` or `SHA1` for security hashing (SHA-256 or stronger only)
- Never hardcode any key or credential in source code
- Never use `NoEncryptionEncryptor` outside tests
- Never compare HMAC / hash results directly with `==`

## File integrity

Use `FileHashValidator` to verify file integrity; do not implement your own hash comparison logic.
